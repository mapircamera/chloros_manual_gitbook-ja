# Chloros の「DAQ」タブ

「DAQ」タブ（Chlorosのサイドバーでは**「光センサー」**と表示されています）は、[DAQ-U、DAQ-M、およびDAQ-E光センサー](README.md)のライブ制御画面です。 任意のトランスポート経由でセンサーを接続し、校正済みスペクトルをリアルタイムで監視し、センサーペアからリアルタイムの反射率を算出し、`.daq`ファイルをプロジェクトに直接記録できます。

このタブは、Chlorosバックエンドの起動が完了すると利用可能になります。 このタブのグラフは、ChlorosのDAQサービスによってリアルタイム接続を介してデータが供給されます。接続が中断された場合は自動的に再接続されます（2～10秒のバックオフ）。サービスに接続できない間、センサーの「ステータス」行には**「No Server」**と表示されます。

レイアウトは、**センサーサイドバー**（接続されたセンサーごとに1行）と**チャート領域**（センサーまたはグループごとに1つのチャートタイル）で構成されています。

## センサーの接続

サイドバー上部の ****センサーを接続****をクリックします。接続ダイアログがメインエリアに表示されます（別のセンサーを追加する場合はオーバーレイとして表示され、その場合は****キャンセル**** ボタンが表示されます）。

| コントロール | 動作 |
| --- | --- |
| **デバイスタイプ** | `DAQ-U (USB)`（デフォルト）、`DAQ-M (Bluetooth)`、または `DAQ-E (Ethernet)`。切り替えを行うと、新しく選択されたトランスポートに対するスキャンが再開始されます。 |
| **ポート / BLE デバイス / ホスト名 / IP** | 検出されたデバイスを `device - description` の形式で一覧表示します。センサーとして認識された最初のエントリが自動的に選択されます。 スキャン中は、`Scanning...`（USB）、8秒のカウントダウン付きで `Scanning (N)...`（BLE）、または5秒のカウントダウン付きで `Discovering ethernet sensors (N)...` （イーサネット）が表示されます。結果がない場合は、`No ports` / `No BLE devices` / `No ethernet sensors found`と表示されます。 |
| **↻ 更新** | 選択したトランスポートを直ちに再スキャンします（BLE／イーサネットのスキャン中は無効）。 |
| **接続** | デバイスが選択されると有効になります。接続中はラベルが `Connecting...` に変更されます。 |

ディスカバリーは**接続ダイアログが画面に表示されている間**のみ実行され、選択されたトランスポートに対してのみ15秒ごとに繰り返されます。タブを開いただけではスキャンは行われません。失敗した場合、ダイアログには次のように表示されます：*「接続に失敗しました。センサーのプラグを一度抜き、再度差し込んでから、もう一度『接続』をクリックしてください。』*

最初のセンサーが接続されると、サイドバーが自動的に開きます。

{% hint style="info" %}
**DAQ-Eが表示されない場合** DAQ-EにはステータスLEDがありません。接続されているスイッチまたはインジェクタのポートにあるPoE/リンクインジケータを確認し、電源投入後、起動が完了するまで数秒間お待ちください。 Chloros マシンは同じブロードキャストドメイン内にある必要があります（mDNS はルーターを通過しません）。 Windows では、Chloros がマルチキャストソケット（mDNS UDP 5353、DAQ-E データ UDP 5002、 PTP UDP 319/320）をバインドする際、Defender ファイアウォールのプロンプトに同意してください。1 つの LAN 上の 2 台の DAQ-E ユニットは、それぞれ独自の `daq-e-<id>.local` ホスト名で個別に検出されます。
{% endhint %}

## センサーサイドバー

接続された各センサーには1行が割り当てられます（さらに、Ambient+Objectグループごとに1行が追加されます）。行はドラッグして並べ替えることができ、その順序によってチャートタイルの順序も変更されます。行をクリックすると、そのセンサー／グループがリストビューのアクティブなチャートになります。

| 要素 | 意味 |
| --- | --- |
| 左側の色付き枠 | センサーのグラフの色。 |
| 通信バッジ | `DAQ-U` / `DAQ-M` / `DAQ-E`、または Ambient+Object 反射率グループの場合は緑色の `REF` バッジ。 |
| デバイス名 | デフォルトはセンサーのシリアル番号（校正、`.daq` ファイル名、およびインポート時の照合のための安定した識別子）です。プロジェクトごとにカスタム名を設定できます。 |
| **校正済み** ピル（緑） | センサーの工場出荷時校正バンドルが読み込まれている場合（つまり、スペクトルが真の W/m²/nm である場合）に表示されます。 |
| **更新可能** ピル（琥珀色、DAQ-Eのみ） | 実行中のファームウェアが、この Chloros ビルドに同梱されているイメージよりも古い場合。更新中は進行状況がリアルタイムで表示されます（`Flashing… N%`、 `Restarting sensor…`、次に `Updated X → Y` または `Failed`）が表示されます。 |
| 目 | チャート上でのこのセンサーの表示/非表示を切り替えます。 |
| 歯車 | センサーごとの設定モーダル（下部）を開きます。 |
| ✕（赤） | センサーの接続を解除するか、Ambient+Objectグループを削除します。 |

各行の上部には2つのボタンがあります：

* **センサーを接続** — 接続ダイアログを開きます （処理中は「`Connecting...`」にラベルが変更されます）。
* **すべて記録 / すべて停止**—**すべての**接続済みセンサーで `.daq` の記録を開始または停止します。 少なくとも1つのセンサー**および開いているプロジェクト** が必要です（ツールチップ：「記録するにはプロジェクトを開いてください」）。記録が実行されている間は赤色になります。

空の状態では「接続されたセンサーはありません」と表示されます。

## センサーごとの設定（歯車アイコンのモーダル）

センサー行の歯車アイコンをクリックして開きます。表示内容は以下の順です：

* **情報行** — デバイスタイプ（DAQ-U/M/E）、接続（`Serial (USB)` / `Bluetooth` / `Ethernet`）、ポート（COMポート、BLEアドレス、またはホスト）、およびシリアル番号。
* **校正レポート：ダウンロード** — このユニットのNISTトレーサブルな校正証明書 （PDF）を取得し、PDFビューアで開きます。シリアル番号が判明次第利用可能になります。証明書は初回接続時にキャッシュされます。
* **デバイス名** — 鉛筆アイコンをクリックして名前を変更できます。プロジェクトごとに保持されます。
* **グラフの線色** — カラーパレット。プロジェクトごとに保持されます。
* **積分時間 (ms)**— スライダー＋数値、**1～500 ms**、デフォルト**32 ms**。AEがONのときは無効。
* **フレーム平均**— スライダー＋数値、**1～50 フレーム**、デフォルト**20**。
* **AE: ON/OFF**— 自動露出の切り替え；接続時は**デフォルトでON**。露光時間を手動で設定するにはOFFにします。
* **ストリーミング停止 / ストリーミング開始** — ライブストリームを一時停止または再開します。
* **録画 / 録画停止** — センサーごとの `.daq` 録画（プロジェクトを開いている必要があります）。
* **Cap** — キャップ補正プロファイル（次のセクション）。
* **ライブ情報行** — 積算時間 (ms)、FPS、サンプル数、録画中 (赤色の `REC` または `Off`)、およびステータス (`Streaming` / `Paused` / `SATURATED` / `No Server`）。

### DAQ-Eのみ：ネットワーク、ファームウェア、およびPTP行

* **ホスト名 / IP** — ユニットの現在のアドレス。
* **ファームウェア** — 現在のファームウェアバージョンに加え、アクションセルが表示されます。<version\>

この Chloros ビルドに新しい DAQ-E ファームウェアイメージが含まれている場合、</version\>

**「\」に更新<version\>** ボタンが表示されます。 更新はネットワーク経由で約30秒で完了します。センサーは自動的に再起動して再接続され、転送が中断された場合でも現在のファームウェアは保持されます。 進行状況はリアルタイムで表示され（`Flashing… N%` → `Restarting sensor…` → `Updated X → Y`）、最新の状態ではセルに `Up to date` と表示されます。
* **PTP同期** — リアルタイムのPTP状態（`unknown`にフォールバック）。DAQ-Eファームウェアv1.2.0以上は、IEEE 1588 PTPv2にスレーブ専用クロックとして参加します。 ChlorosホストのバックエンドがPTPグランドマスターであり、LAN上のすべてのDAQ-EおよびLATTICEカメラはドメイン0でこれにスレーブとして同期し、タイムスタンプの誤差を約1 ms以内に抑えています。

Ambient+Object グループの場合、ギアのモーダルには、そのグループのソースセンサー、デバイス名、およびグラフの線色のみが表示されます。

### キャップの選択

**Cap** ドロップダウンは、センサーのディフューザーにどの物理的なキャップが装着されているかを Chloros に指定し、そのキャップの工場出荷時に測定された補正プロファイルをすべてのスペクトルに適用します。選択肢はモデルによって異なります：

| モデル | キャップの選択肢 |
| --- | --- |
| DAQ-U | なし（センサー本体のみ）、FOV 15°、FOV 30°、FOV 45°、FOV 60°、FOV 90°、Sunshine（コサイン補正器） |
| DAQ-M | なし（センサー素体）、Sunshine（コサイン補正器） |
| DAQ-E | なし（センサー素体）、FOV 15°、FOV 45°、FOV 90°、Sunshine（コサイン補正器） |

**すべてのモデルのデフォルト設定は「Sunshine（コサイン補正）」です** — MAPIRは、すべてのDAQに「Sunshine」キャップを装着した状態で出荷しており、これが標準的な屋外用構成となります： 180°の半球視野を持ち、60°まではコサイン誤差が±4 %以下、70°までは±4.5 %以下（太陽高度角が約15°未満での使用は推奨されません）で、設計上、約12倍の減衰があります。選択内容はプロジェクトに保存されます。

{% hint style="warning" %}
**キャップの選択は、実際に装着されているキャップと一致している必要があります。**センサーもソフトウェアも、どのキャップが装着されているかを検知することはできません。 この選択は、リアルタイム補正と、すべての `.daq` ファイルに書き込まれるスタンプの両方に影響します。Sunshine キャップの約 12 倍の減衰を考慮すると、キャップの変更が申告されない場合、スペクトルはおよそその倍率だけ誤って補正されます。 （同じキャップを取り外して再装着しても、誤差は約1.5％程度に収まります。）**「なし（センサー裸）」** を選択するのは、キャップが物理的に取り外されている場合のみです。DAQ-E では、「なし」を選択しても、その凹型ガラスディフューザーに対して工場出荷時の幾何学的プロファイルが適用されます（何もしないわけではありません）。また、キャップなしの DAQ-E はベンチ構成であり、サポート対象の現場構成ではありません。
{% endhint %}

{% hint style="info" %}
以前のマニュアルからの更新点：バージョン1.1.0にあったブラウザ側の「Sunshine Diffuser Installed」トグルは廃止されました。キャップの処理は、サーバー側で適用されるセンサーごとのキャッププロファイルによって行われるようになりました。
{% endhint %}

## チャート領域

固定された上部バーには、**リスト表示とグリッド表示の切り替え**と、**チャートズーム**スライダー（タイルサイズ 200～2000 ピクセル）があります。 チャートグループが複数存在する場合は表示が自動的にグリッド表示に切り替わり、1つ以下の場合はリスト表示に戻ります。表示モードとチャートサイズはプロジェクトごとに保持されます。

各センサーの**スペクトルチャート**には以下が表示されます：

* **X軸** — 波長（nm）。センサーのグリッドは340～1010 nm（5 nm間隔、135点）ですが、表示時には1 nm間隔に補間されます。
* **Y軸** — パワー（W/m²）。ピーク値に基づいて、SI接頭辞（m/µ/n）が自動的に選択されます。3つのトランスポートすべてにおいて、スペクトルは放射測定学的に校正されたスペクトル放射照度（W/m²/nm）で表示されます。
* 単一のトレースの下には虹色のスペクトル塗りつぶしが表示されます。1つのチャート上に複数のセンサーがある場合は、色付きの線で重ね合わせられ、塗りつぶしは薄くなります。
* **カーソルを合わせると**— 波長とセンサーごとの値が表示された垂直カーソルが表示されます。**ドラッグ**してズームします（ズーム中はズームアウトボタンが表示されます）。
* **+** ボタン（グリッド表示のみ）で、このチャートにセンサーを追加したり、グループを作成したりできます（後述）。
* デバイス名は上部中央に表示され、最初のフレームが到着するまではスピナーが表示されます。

**飽和**はチャート上には表示されません。飽和したセンサーは、ライブデータテーブルに赤い「`SATURATED`」というステータステキストと、赤い「`Saturated: Yes`」という行として表示されます。 これを解消するには、積分時間を短縮するか、AEを再度有効にしてください。

## ライブデータテーブル（リストビュー）

リストビューのグラフの下部に表示され、500 msごとに更新されます：

* **全モデル**： 光の色見本（CIE XYZ からの sRGB）、飽和（はい/いいえ）、CIE 1931 X/Y/Z、色度 x/y、CIE u′/v′、CCT (K)、CRI (Ra)、主波長 (nm)、 ピーク波長（nm）、励起純度、Duv、CIE L\*/a\*/b\*、およびマンセル H/V/C。
* **校正済みセンサーのみ**（DAQ-U / DAQ-M / DAQ-Eのいずれかで、工場出荷時の校正バンドルが読み込まれているもの — センサー行に表示される緑色の**Calibrated**バッジが目安となります）： 総光束（W/m²）、明所視ルクス（lx）、暗所視ルクス（lx）、 S/P比、PPFDおよびPPFD Red/Green/Blue（µmol/m²/s）、 および各オピック放射照度 — S錐体、メラノピック、ロドピック、M錐体、L錐体（すべて W/m²）。

## 反射率グループ（周囲光 + 対象物）

接続された2つのセンサーを組み合わせることで、カメラを使用せずにリアルタイムの反射率表示を行うことができます：

1. グリッドビューで、チャートタイルの **+**をクリックし、**「周囲光 + 対象物」を結合** を選択します。
2. **「周囲光源」**センサーと**「対象物スキャナー」**センサー（2つの異なるセンサー）を選択し、**「作成」** をクリックします。

Chlorosは、2つのリアルタイムストリームから波長ごとにR(λ) = 対象物(λ) / 周囲光(λ)を算出します（周囲光が0以下の場合は0）。グループのラベルは、センサーのキャリブレーションクラスに基づきます：

* 両方のセンサーがキャリブレーション済み（バンドルが読み込まれている） → **「見かけの反射率」**。
* いずれかのセンサーがキャリブレーションされていない → **「相対反射率」**。

このグループは、サイドバーに緑色の `REF` 行として表示され、専用のチャート（虹色の塗りつぶし、マウスオーバーで小数点以下4桁の値が表示、ドラッグによるズーム）も表示されます。

**+**メニューには**新しいセンサーの追加** もあり、3つの配置オプションが用意されています：*新しいセンサーを結合*（このグラフに追加）、*既存のセンサーをここに移動*、または *新しいセンサーを表示*（専用のグラフ）。

### 植生指数テーブル

リスト表示では、反射率グループのチャートの下に植生指数テーブルが表示されます。これは、**青 450 / 緑 550 / 赤 670 / NIR 800 nm** のバンド中心におけるリアルタイムの反射率から算出されます （値は小数点以下4桁、計算不能な場合は`---`と表示されます。インデックス名にカーソルを合わせると、その正式名称が表示されます）：

* **常に表示**（スケール不変、どのセンサーの組み合わせでも）：NDVI、GNDVI、 ENDVI、WDRVI、GRVI、CVI、GCI、MSR。
* **両方のセンサーがパワーキャリブレーション済みである場合のみ**（両方のバンドルが読み込まれている場合）：EVI、SAVI、 OSAVI、GSAVI、GOSAVI、MSAVI2、RDVI、TDVI、LAI、NLI、MNLI、FCI、GEMI。

## `.daq` ファイルの記録

* 記録を行うには **プロジェクトを開いている** 必要があります。そうでない場合、「すべて記録」（サイドバー）および各センサーの「記録」ボタンは使用できません。
* ファイルは **`<project folder>/light_sensor/`** に書き込まれます。ファイル名にはセンサーIDとタイムスタンプが含まれ、デバイス名は記録データと共に保存されます。
* 記録が停止した場合（「停止」、「すべて停止」、または記録中の接続切断）、完了した `.daq` ファイルは **開いているプロジェクトに自動的に追加** されます — 手動で追加することなくプロジェクトのファイル一覧に表示され、[反射率処理](README.md) の下向き放射データとしてすぐに利用可能です。
* 記録中は、設定モーダルのライブ行に赤い `REC` インジケーターが表示されます。

定量的な放射照度の数値については、少なくとも 15 秒分のデータを平均化してください。これは機器の特性であり、不具合ではありません。

## マルチセンサーのレイアウトとプロジェクトの永続性

* 複数のセンサーを1つのチャートに統合（軸の共有）、別々のチャートを維持（自動グリッドレイアウト）、チャート間のセンサー移動、行やタイルのドラッグによる並べ替え、および「目」アイコンの切り替えによる個々のセンサーの非表示が可能です。
* プロジェクトごとに、Chlorosでは以下の設定が保持されます：デバイス名、グラフの色、チャートサイズ、表示モード、および各センサーの設定（積分時間、フレーム平均化、AE状態、キャップの選択）。
* **プロジェクトを再開すると、** アドレス（DAQ-Uの場合はCOMポート、DAQ-Mの場合はBLEデバイス、 DAQ-Eの場合はmDNSホスト名（デバイスのIPが変更されても解決されます）— に基づき、各センサーの保存されたキャッププロファイル、フレーム平均化、AE状態、および手動積分時間が再適用されます。***

## カメラのペアリング（DLS）

ペアリングを行う必要はありません。 ドローンのDLSワークフローのように、事前に光センサーをカメラに紐付けるのとは異なり、ChlorosはDAQデータを後工程の画像と照合します。つまり、インポート／処理時に、`.daq`の測定値が各キャプチャの露出タイムスタンプに合わせて補間されます。 接続された任意のセンサーで記録を行ってください（`.daq`は自動的にプロジェクトに追加されます）。反射率処理により、時間に応じて適切な測定値が特定されます。下向きデータの使用方法については、[DAQ光センサー](README.md)を参照してください。</version\>
