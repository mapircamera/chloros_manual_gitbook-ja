# Chloros の「DAQ」タブ

「DAQ」タブ（Chlorosのサイドバーでは**Light Sensors**と表示されています）は、[DAQ-U、DAQ-M、およびDAQ-E 光センサー](README.md)用のライブ制御画面です。 任意のトランスポート経由でセンサーを接続し、校正済みスペクトルをリアルタイムで監視し、センサーペアからリアルタイムの反射率を算出し、`.daq`ファイルをプロジェクトに直接記録できます。

このタブは、Chlorosのバックエンドの起動が完了すると利用可能になります。タブ内のチャートは、ChlorosのDAQサービスからライブ接続を介してデータが供給されます。接続が中断された場合は自動的に再接続されます（2～10秒のバックオフ）。サービスに接続できない間、センサーの「ステータス」行には**No Server**と表示されます。

レイアウトは、**センサーサイドバー**（接続されたセンサーごとに1行）と**チャート領域**（センサーまたはグループごとに1つのチャートタイル）で構成されています。

## センサーの接続

サイドバー上部の ****センサーを接続****をクリックします。接続ダイアログがメインエリアに表示されます（別のセンサーを追加する場合はオーバーレイとして表示され、その場合は****キャンセル**** ボタンが表示されます）。

| コントロール | 動作 |
| --- | --- |
| **デバイスタイプ** | `DAQ-U (USB)`（デフォルト）、`DAQ-M (Bluetooth)`、または`DAQ-E (Ethernet)`。切り替えると、新しく選択されたトランスポートに対するスキャンが再開されます。 |
| **ポート / BLE デバイス / ホスト名 / IP** | 検出されたデバイスを `device - description` の形式で一覧表示します。センサーとして認識された最初のエントリが自動的に選択されます。 スキャン中は、`Scanning...`（USB）、8秒のカウントダウン付きで`Scanning (N)...`（BLE）、または5秒のカウントダウン付きで`Discovering ethernet sensors (N)...` （イーサネット）が表示されます。結果がない場合は、`No ports` / `No BLE devices` / `No ethernet sensors found`と表示されます。 |
| **↻ 更新** | 選択したトランスポートを直ちに再スキャンします（BLE/イーサネットのスキャン中は無効）。 |
| **センサーに接続** | デバイスが選択されると有効になります。接続中はラベルが `Connecting...` に変更されます。 |

ディスカバリーは**接続ダイアログが画面に表示されている間**のみ実行され、選択されたトランスポートに対してのみ15秒ごとに繰り返されます。タブを開いただけではスキャンは行われません。失敗した場合、ダイアログに次のように表示されます：*「接続に失敗しました。センサーのプラグを一度抜き、再度差し込んでから、もう一度『接続』をクリックしてください。』*

最初のセンサーが接続されると、サイドバーが自動的に表示されます。

{% hint style="info" %}
**DAQ-Eが表示されない？**DAQ-EにはステータスLEDがありません。接続されているスイッチまたはインジェクタのポートにあるPoE/リンクインジケータを確認し、電源投入後、起動するまで数秒待ってください。Chlorosマシンは同じブロードキャストドメイン内にある必要があります（mDNSはルーターを通過しません）。 インストーラの**Chlorosバックエンド（UDP-In）**ファイアウォールルールでは、mDNS（UDP 5353）、DAQ-Eデータ（UDP 5002）、PTP（UDP 319/320）が許可されています。 サードパーティ製のファイアウォールでも、同じポートを通す必要があります。1つのLAN上の2台のDAQ-Eユニットは個別に検出され、それぞれ独自の`daq-e-<id>.local`というホスト名で認識されます。
{% endhint %}

## センサーサイドバー

接続された各センサーには1行が割り当てられます（さらに、Ambient+Objectグループごとに1行が追加されます）。行はドラッグして並べ替えることができ、その順序によってチャートタイルの順序も変更されます。行をクリックすると、そのセンサー/グループがリストビューのアクティブなチャートになります。

| 要素 | 意味 |
| --- | --- |
| 左側の色付き枠 | センサーのグラフの色。 |
| 転送バッジ | `DAQ-U` / `DAQ-M` / `DAQ-E`、または Ambient+Object 反射率グループの場合は緑色の `REF` バッジ。 |
| デバイス名 | デフォルトはセンサーのシリアル番号（校正、`.daq` ファイル名、およびインポート時の照合のための安定した識別子）。カスタム名はプロジェクトごとに保持されます。 |
| **校正済み** ピル（緑） | センサーの工場出荷時校正バンドルが読み込まれている場合に表示されます。つまり、スペクトルが真の W/m²/nm であることを示します。 |
| **更新可能** ピル（琥珀色、DAQ-Eのみ） | 実行中のファームウェアが、このChloros

ビルドに同梱されているイメージよりも古い場合。更新中は進行状況がリアルタイムで表示されます（`Flashing… N%`、 `Restarting sensor…`、続いて `Updated X → Y` または `Failed`）が表示されます。 |
| 目 | チャート上のこのセンサーの表示/非表示を切り替えます。 |
| 歯車 | センサーごとの設定モーダル（下部）を開きます。 |
| ✕（赤） | センサーの接続を解除するか、Ambient+Objectグループを削除します。 |

各行の上部には2つのボタンがあります：

* **センサーを接続** — 接続ダイアログを開きます （処理中は「`Connecting...`」と表示されます）。
* **すべて記録 / すべて停止**— 接続されている**すべての**センサーで `.daq` の記録を開始または停止します。 少なくとも1つのセンサー**および開いているプロジェクト** が必要です（ツールチップ：「記録するにはプロジェクトを開いてください」）。記録が実行されている間は赤色に変わります。

空の状態では「接続されたセンサーはありません」と表示されます。

## センサーごとの設定（歯車アイコンのモーダル）

センサー行の歯車アイコンをクリックして開きます。表示内容は順に以下の通りです：

* **情報行** — デバイスタイプ（DAQ-U/M/E）、接続（`Serial (USB)` / `Bluetooth` / `Ethernet`）、ポート（COMポート、BLEアドレス、またはホスト）、およびシリアル。
* **校正レポート：ダウンロード** — このユニットのNISTトレーサブルな校正証明書（PDF）を取得し、PDFビューアで開きます。 シリアル番号が判明次第利用可能。証明書は初回接続時にキャッシュされます。
* **デバイス名** — 鉛筆アイコンをクリックして名前を変更できます。プロジェクトごとに保持されます。
* **グラフの線色** — カラーパレット。プロジェクトごとに保持されます。
* **積分時間 (ms)**— スライダー＋数値、**1～500 ms**、デフォルト**32 ms**。AEがONのときは無効になります。
* **フレーム平均**— スライダー＋数値、**1～50フレーム**、デフォルト**20**。
* **AE: ON/OFF**— 自動露出の切り替え；接続時は**デフォルトでON**。露光時間を手動で設定するにはOFFにしてください。
* **ストリーミング停止 / ストリーミング開始** — ライブストリームを一時停止または再開します。
* **録画 / 録画停止** — センサーごとの `.daq` 録画（開いているプロジェクトが必要です）。
* **Cap** — キャップ補正プロファイル（次のセクション）。
* **ライブ情報行** — 積算時間 (ms)、FPS、サンプル数、録画中 (赤色の `REC` または `Off`)、およびステータス (`Streaming` / `Paused` / `SATURATED` / `No Server`）。

### DAQ-E のみ：ネットワーク、ファームウェア、および PTP 行

* **ホスト名 / IP** — ユニットの現在のアドレス。
* **ファームウェア** — 現在のファームウェアバージョン。さらに、アクションセルが表示されます。<version\>

このChloros

ビルドに新しいDAQ-Eファームウェアイメージが含まれている場合、</version\>

**「\」に更新**<version\>

ボタンが表示されます。更新はネットワーク経由で約30秒で完了します。センサーは自動的に再起動して再接続され、転送が中断された場合でも現在のファームウェアはそのまま維持されます。 進行状況はリアルタイムでストリーミングされ（`Flashing… N%` → `Restarting sensor…` → `Updated X → Y`）、最新の状態ではセルに `Up to date` と表示されます。
* **PTP 同期** — リアルタイムの PTP 状態（`unknown` にフォールバックします）。DAQ-E ファームウェア v1.2.0 以降では、IEEE 1588 PTPv2 にスレーブ専用クロックとして参加します。 Chloros

ホストのバックエンドがPTPグランドマスターとなり、LAN上のすべてのDAQ-EおよびLATTICEカメラはドメイン0でこれにスレーブとして同期し、タイムスタンプの誤差を約1 ms以内に保ちます。
* **ネットワーク**— ユニットが動作するアドレスとその取得方法（DHCP、リンクローカル、または静的）、および再起動後に適用される保存済み設定。**変更…**を選択するとフォームが開きます：**自動（DHCP）**または**静的IP**（IPアドレス、サブネットマスク、およびオプションのゲートウェイを入力）。**適用して再起動** を選択すると、設定が保存され、センサーが再起動して再接続されます。 このコンピュータのネットワーク外にある静的アドレスは拒否されます。これは、再起動後にChloros

がセンサーに到達できなくなるためです。ただし、そのネットワークに再アドレス指定またはルーティングされるコンピュータの場合は、それでも許可するチェックボックスが表示されます。**電源投入時のストリーミング**は、ソフトウェアが接続する前に、センサーが電源投入直後にストリーミングを開始するかどうかを設定します。****センサーの再起動**** を選択すると、センサーが再起動され、現在の設定で再接続されます。センサーが記録中の場合は再起動は拒否されます。バージョン 1.3.0 の新機能です。

Ambient+Object グループの場合、歯車アイコンのモーダルには、そのグループのソースセンサー、デバイス名、およびグラフの線色のみが表示されます。

### キャップの選択

**キャップ**ドロップダウンでは、センサーのディフューザーにどの物理的なキャップが装着されているかをChloros

に指定し、そのキャップの工場出荷時に測定された補正プロファイルをすべてのスペクトルに適用します。選択肢はモデルによって異なります：

| モデル | キャップの選択肢 |
| --- | --- |
| DAQ-U | なし（センサー本体のみ）、FOV 15°、FOV 30°、FOV 45°、FOV 60°、FOV 90°、Sunshine（コサイン補正器） |
| DAQ-M | なし（センサー裸）、Sunshine（コサイン補正器） |
| DAQ-E | なし（センサー裸）、FOV 15°、FOV 45°、FOV 90°、Sunshine（コサイン補正器） |

**すべてのモデルのデフォルト設定は「サンシャイン（コサイン補正）」です** — MAPIR

はすべてのDAQにサンシャインキャップを装着して出荷しており、これが標準的な屋外構成となります： 180°の半球視野で、60°までコサイン誤差が±4 %以下、70°まで±4.5 %以下（太陽高度約15°未満での使用は推奨されません）、設計上減衰（約12倍）します。選択内容はプロジェクトに保持されます。

{% hint style="warning" %}
**キャップの選択は、実際に装着されているキャップと一致している必要があります。**センサーもソフトウェアも、どのキャップが装着されているかを検出することはできません。この選択は、リアルタイム補正と、すべての `.daq` ファイルに書き込まれるスタンプの両方に影響を与えます。サンシャインキャップの約12倍の減衰率を考慮すると、 キャップの変更が申告されていない場合、スペクトルはおよそその倍率分だけ誤補正されます。（同じキャップを取り外して再装着すると、誤差は約1.5％に収まります。）**「なし（センサーのみ）」**を選択するのは、キャップが物理的に取り外されている場合に限ってください。 DAQ-E では、「None」を選択しても、凹型のガラスディフューザーに対する工場出荷時の幾何学的プロファイルが適用されます（何もしないわけではありません）。また、キャップなしの DAQ-E はベンチ構成であり、サポート対象のフィールド構成ではありません。
{% endhint %}

{% hint style="info" %}
以前のマニュアルからの更新点：バージョン 1.1.0 にあったブラウザ側の「Sunshine Diffuser Installed」トグルは廃止されました。キャップの扱いは、サーバー側で適用されるセンサーごとのキャッププロファイルに変更されました。
{% endhint %}

## チャート領域

固定された上部バーには、**リスト表示 ⇄ グリッド表示の切り替え**と**グラフズーム** スライダー（タイルサイズ 200～2000 px）があります。複数のチャートグループが存在する場合は自動的にグリッド表示に切り替わり、1つ以下の場合はリスト表示に戻ります。 表示モードとチャートサイズはプロジェクトごとに保持されます。

各センサーの**スペクトルチャート**には以下が表示されます：

* **X軸** — 波長（nm）。 センサーのグリッドは 340～1010 nm（5 nm 間隔、135 ポイント）で、表示時には 1 nm 間隔に補間されます。
* **Y 軸**— 校正済みのセンサー（緑色の**Calibrated**ピル）の場合、**パワー（W/m²/nm）**— 3つの伝達関数すべてにおける放射測定的に校正されたスペクトル放射照度 — ピーク値から自動的に選択されたSI接頭辞（m/µ/n）が付きます。校正データセットが読み込まれていないセンサーは、スケーリングされていない生の測定値を**強度（カウント）**としてプロットします。 両方の種類が1つのグラフに重ねて表示される場合、左軸にはパワー、右軸にはカウントが表示されます。
* 単一のトレースの下には虹色のスペクトル塗りつぶしが表示されます。1つのグラフに複数のセンサーが重ねて表示される場合は、色付きの線として表示され、塗りつぶしは薄くなります。
* **ホバー**— 波長とセンサーごとの値（校正済みのセンサーの場合は W/m²/nm、それ以外は総カウント数）が表示される垂直カーソル。**ドラッグ**でズーム（ズーム中はズームアウトボタンが表示されます）。
* **+** ボタン（グリッド表示のみ）：このグラフにセンサーを追加するか、グループを作成します（後述）。
* デバイス名が上部に中央揃えで表示され、最初のフレームが到着するまではスピナーが表示されます。

**飽和**はチャート上には表示されません。センサーが飽和状態になると、ライブデータテーブルに赤い「`SATURATED`」というステータステキストと、赤い「`Saturated: Yes`」の行が表示されます。積分時間を短縮するか、AEを再度有効にすることで解消できます。

## 反射率グループ （周囲光 + 対象物）

接続された2つのセンサーを組み合わせることで、カメラを使用せずにリアルタイムの反射率表示を作成できます：

1. グリッドビューで、チャートタイルの**+**をクリックし、**「周囲光 + 対象物を組み合わせる」**を選択します。
2. **周囲光源**センサーと**対象物スキャナー**センサー（2つの異なるセンサー）を選択し、**作成**をクリックします。

Chloros

は、2つのライブストリームから波長ごとに R(λ) = 対象物(λ) / 周囲(λ) を算出します（周囲が 0 以下の場合は 0 となります）。 グループのラベルは、センサーのキャリブレーションクラスに基づきます：

* 両方のセンサーがキャリブレーション済み（バンドルが読み込まれている） → **「見かけの反射率」**。
* いずれかのセンサーが未校正 → **「相対反射率」**。

このグループは、サイドバーに緑色の `REF` 行として表示され、専用のチャート（虹色の塗りつぶし、ホバー時に小数点以下4桁の値が表示、ドラッグによるズーム）が表示されます。

**+**メニューには**新しいセンサーの追加** もあり、3つの配置オプションが用意されています：*新しいセンサーを結合*（このグラフに追加）、*既存のセンサーをここに移動*、または *新しいセンサーを表示*（専用のグラフ）。

## `.daq` ファイルの記録

* 記録には**開いているプロジェクト**が必要です。プロジェクトが開いていない場合、「すべて記録」（サイドバー）および各センサーの「記録」ボタンは使用できません。
* ファイルは **`<project folder>/light_sensor/`** に書き込まれます。ファイル名にはセンサー ID とタイムスタンプが含まれ、デバイス名は記録データと共に保存されます。
* 記録が停止した場合（「停止」、「すべて停止」、または記録中の接続切断）、完了した `.daq` ファイルは **開いているプロジェクトに自動的に追加** されます — 手動で追加することなくプロジェクトのファイル一覧に表示され、[反射率処理](README.md)用の下向き放射データとしてすぐに利用可能です。
* 記録中は、設定モーダルのライブ行に赤い `REC` インジケーターが表示されます。

定量的な放射照度の数値については、少なくとも 15 秒分のデータを平均化してください。これは機器の特性であり、不具合ではありません。

## マルチセンサーのレイアウトとプロジェクトの永続性

* 1つのチャートに複数のセンサーを統合（軸の共有）、個別のチャートを維持（自動グリッドレイアウト）、チャート間のセンサー移動、行やタイルのドラッグによる並べ替え、および「目」アイコンの切り替えによる個々のセンサーの非表示が可能です。
* Chloros

は、プロジェクトごとに以下の設定を保持します：デバイス名、グラフの色、チャートサイズ、表示モード、および各センサーの設定（積分時間、フレーム平均化、AE状態、キャップの選択）。
* **プロジェクトを再開すると、** アドレス（DAQ-Uの場合はCOMポート、DAQ-Mの場合はBLEデバイス、 DAQ-Eの場合はmDNSホスト名（デバイスのIPアドレスが変更されても解決されます）— に基づき、各センサーの保存されたCAPプロファイル、フレーム平均化、AE状態、および手動積分時間を再適用します。***

## カメラのペアリング（DLS）
