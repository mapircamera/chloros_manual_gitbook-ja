# 記録と.daq形式

`.daq`ファイルは、Chlorosの光センサー用記録形式であり、1つのDAQセンサーから得られた、較正済みのスペクトルフレームを格納した**SQLiteデータベース**です。 キャプチャセッション中にこれを1つ記録しておけば、後で反射率処理パイプラインが、各画像をその瞬間に測定された下向き放射照度で除算することができます。

## .daqファイルの内容

| プロパティ | 値 |
| --- | --- |
| コンテナ | SQLite データベース。記録ごとにセンサーごとに 1 ファイル |
| ファイル名 | **センサー ID**と**タイムスタンプ** を含む。例：`daq_data_daq-e-def330_2026_04_13_18h30m00.daq` |
| フレームごとのスペクトル | 135 ポイント、340～1010 nm（5 nm 間隔）、および CIE XYZ 三刺激値 |
| 単位 | 校正済み分光放射照度、**W/m²/nm**（工場出荷時の校正バンドル＋キャッププロファイルが適用済み） |
| 記録されたメタデータ | センサーID（そのユニットの工場校正データを取得するためのキー）および適用中のキャッププロファイル — [キャッププロファイルと校正範囲](caps-and-range.md) を参照 |

このフォーマットはDAQ-U、DAQ-M、DAQ-E、DAQ-E-Sで共通であるため、後処理においてどのトランスポートで記録されたかは問題になりません。DAQ-E-Sの記録では、各スペクトルの横にユニットのチルト、ロール、ピッチも保存されます。

**記録データは停電後も保持されます（1.3.0）。**ライブ記録は、コミットごとにジャーナルとディスク全体の同期が行われながら書き込まれるため、停電やプロセスの強制終了が発生しても、失われるのは直近約3秒分のデータのみで、ファイル自体は失われません。 書き込み途中で停止した記録では、`.daq`ファイルの横に`<name>.daq-journal`ファイルが残る場合があります：**この2つのファイルを一緒に保持し、コピーしてください。** Chlorosは、ファイルを初めて読み込む際にジャーナルをロールバックします。 ディスクがビジー状態の場合、ファイルの書き込みが遅延することはありますが、センサーの測定値の記録が遅れることはありません。

**データ送信を停止したDAQ-Eは再接続されます（1.3.0）。** DAQ-Eのストリームが途絶えた場合（スイッチの電源再投入、リンク切断など）、バックエンドは以前の設定で再接続を行い、そのDAQ-Eでの記録は、ファイル内に欠落部分がマークされた状態で、同じ`.daq`ファイル内で継続されます。

校正済みの記録には、センサーの工場出荷時校正バンドルが必要です。DAQ-UおよびDAQ-Mの場合、バックエンドはセンサーIDに基づいてMAPIRのクラウドからバンドルを取得します（取得できない場合は記録が拒否されます）。DAQ-Eユニットは、デバイス内に校正データを保持しているため、この対象外となります。

## GUIからの記録

GUIでの記録には**プロジェクトを開いている**必要があります（そうでない場合、「記録」ボタンは無効になります）：

* **すべて記録 / すべて停止** — 「光センサー」サイドバーの上部；接続されているすべてのセンサーでの`.daq`記録を一度に開始または停止します。
* **記録 / 記録停止** — センサーごとに、歯車アイコンの設定モーダルから操作します。記録中は、センサーのライブ情報行に赤い「REC」インジケーターが表示されます。

ファイルは `<project>/light_sensor/` に書き込まれ、記録が停止すると（「停止」、「すべて停止」による場合、または記録中のセンサーが切断された場合を問わず）、完成した `.daq` は **開いているプロジェクトに自動的に追加** されます。 手動での追加手順は不要で、プロジェクトのファイルリストに表示され、すぐに反射率処理に使用できます。

## CLI

からの記録

CLIは、バックエンドのセンサープールを通じて記録を行います（バックエンドは実行中である必要があります。これらのコマンドは簡易な HTTPクライアントです）：

```bash
# Connect the sensor into the backend pool
chloros-cli daq pool-connect --eth-host daq-e-def330.local

# Record for 150 seconds, with a human-friendly device label
chloros-cli daq pool-record --sensor-id daq-e-def330 --duration 150 \
    -o ./out --device-name "rooftop-A"

# Or run open-ended and stop explicitly
chloros-cli daq pool-record --sensor-id daq-e-def330            # --duration defaults to 0 = run until --stop
chloros-cli daq pool-record --sensor-id daq-e-def330 --stop
```

`chloros-cli daq pool-list`から`--sensor-id`の値を取得します。知っておくべき2つのデフォルト設定：

| オプション | デフォルト |
| --- | --- |
| `--duration` | `0` — `pool-record --stop` まで記録 |
| `--output` / `-o` | `~/Documents/DAQ Live View/`（CLIではなく、**バックエンド**のファイルシステム上） |

CLIが別のマシン上のバックエンドを指定する場合、出力ディレクトリの区別が重要になります。ファイルはバックエンドが実行されている場所に保存されます。 バックエンドが同じコンピュータ上にある場合、相対パス指定の `-o`（上記の `./out` など）は、コマンドを実行したフォルダを基準に解決されます。

## Python

からの記録`DAQSensorSession`（`chloros_sdk.connect_daq_sensor()`によって返される）は、同じプールされた記録を公開します： `record_start(output_dir=None, device_name=None)`はファイルパスを返し、`record_stop()`は`{path, rows}`を返します。 セッション APIの詳細については、[SDKリファレンス](../reference/sdk-reference.md) を参照してください。 SDKのダイレクトハードウェアクラス（デスクトップ版のみ）は、デフォルトで記録データを`~/Documents/DAQ/`に書き込みます。リリース版ビルドでは、上記のプールされたパスがサポートされる経路となります。

## 処理時の .daq ファイルの使用

画像から反射率を算出するために、Chlorosには各露出に一致する下向放射照度が必要です：

* **`.daq` を画像と一緒に保管してください。** 処理時、パイプラインは、記録された `.daq`（任意の DAQ モデル）— または画像と一緒に保存されている DAQ-M ネイティブの `.csv` — から自動的に解決します。GUI 記録は、停止した瞬間にプロジェクトに追加されるため、この条件を自動的に満たします。
* **キャリブレーションデータはオンデマンドで取得されます。** カメラごとまたはDAQごとの工場出荷時キャリブレーションバンドルがローカルにキャッシュされていない場合、Chlorosは初回使用時にMAPIRのクラウドから自動的に取得します（初回のみインターネット接続が必要；`~/.chloros/`としてキャッシュされます）。
* **ライブキャプチャは独自のサイドカーファイルを書き込みます。** ライブでキャプチャされた反射率フレームについては、実際に使用されたDAQの測定値が、キャプチャの `daq/` フォルダ内に `.daq` ファイルとして保存されるため、元の記録データがなくても後でキャプチャを再処理することができます。
* **`chloros_scripts`レコーダーからの記録（1.3.0）。**一般向けの [`chloros_scripts`](https://github.com/mapircamera/chloros_scripts) レコーダーによって作成された `.daq` は、それを作成した DAQ モデルとして一覧表示され、その上限値は他の記録と同様に**プロジェクト設定 → DAQ 光センサー**で、他の記録と同様に上限値を設定できます。これらのレコーダーは生のセンサーカウントを書き込みます。Chlorosはシリアル通信を介してセンサーの工場出荷時のキャリブレーションデータを取得し、それを適用します。
* **どの測定値か (1.3.0)。**各キャプチャ「`.daq`」の横には、「`.daq.cameras.json`」という名前で、その測定値が表すフレームのカメラ名が示されており、処理は**そのカメラからの画像のみ**を対象に行われます。 したがって、独自の光センサーを持たないスタンドアロンカメラは、もはや他のカメラの測定値を借用することはありません。センサーをそのカメラにバインドするか、センサーの測定値を記録してください。 DAQ本体で作成された記録（GUIの「記録」、`daq pool-record`）および、そのファイルを持たないすべての`.daq`（古いキャプチャを含む）は、引き続きすべてのカメラに対応します。

## 放射照度の再取得

プロジェクトを処理すると、そのプロジェクトに含まれるすべての光センサーの記録が、画像データと同じフォルダ内の
`Light Sensor/`フォルダにエクスポートされます。これには画像データは**必要ありません**。
光センサーの記録データのみでも完全なキャプチャとなり、`.daq`
ファイルのみを含むフォルダも有効な入力となります。 光センサーの記録データのみを含むプロジェクトは、それらを一覧表示し、
アプリおよびCLIのいずれからも処理が可能であり、実行後も一覧に残ります。実行時には、
書き出された光センサー製品の数が報告されます。

| 製品 | 内容 |
| --- | --- |
| `<name>_calibrated.daq` | ライブ記録と同じスキーマを持つ再処理可能なアーカイブ。生成に使用されたキャリブレーションバンドルが宣言されています。これを再インポートしても、**再度**キャリブレーションされることはありません。 |
| `<name>_calibrated.csv` | センサー独自の波長グリッドにおける分光放射照度（W/m²/nm）。1行につき1つの測定値に加え、測光値の列（総電力、明所視および暗所視のルクス、青/緑/赤に分割されたPPFD、およびピーク波長）が含まれます。 |

キャリブレーション・バンドルを取得できない DAQ-U または DAQ-M（オフラインであるか、
そのセンサーのキャリブレーションデータがファイルに存在しない場合）は、**理由を明記してスキップ**され、
生カウントを含む「キャリブレーション済み」ファイルとして書き出されることはありません。インターネットに接続して再実行してください。 DAQ-E
は独自のキャリブレーション情報を保持しているため、ユニットが接続されておらず、
ローカルに何もキャッシュされていない場合にのみ、これが必要となります。

### DAQ-A：生カウント、そしてそれが正しい答えである理由

**DAQ-A**は、シリアルごとのキャリブレーション・バンドル・システムが導入される以前に開発されたものであり、取得すべきバンドルを
持ちません。 これは見落としではありません。DAQ-Aは現場で
反射率ターゲットを用いてキャリブレーションされ、ターゲットベースのキャリブレーションに必要なのはセンサーの*相対的な*
応答特性のみであり、それはまさに生カウントそのものです。Chloros社は現在もこれを使用してキャリブレーションを行っています。

したがって、DAQ-Aの記録データはエクスポートされますが、異なる名前で保存されます：

```
<project>/
└── Light Sensor/
    ├── <name>_raw.daq
    └── <name>_raw.csv
```

`_raw` となり、`_calibrated` とはなりません。これはファイル内のフラグではなく、ファイル名そのものが異なる形式になっているのは、
ファイルが単なるファイル名としてメールで転送される際にも、その情報が保持されなければならないためです。 `.csv`
というヘッダーには「`raw spectral sensor counts (NOT irradiance)`」と記載されており、値は
ファイル**内**でのみ比較可能であり、センサー間で比較できないことが警告されています。 実際の放射照度に関してのみ
意味を持つ列（総電力、ルクス、PPFD）は、
カウント値から計算されるのではなく、空欄のままにされています。

古いDAQ-A-SDの記録（スキーマv1.01／v1.02）では、ファイルの書き込み時刻のみが記録され、
読み取りごとのタイムスタンプは記録されません。 Chlorosは、これらのデータと画像を照合しません — フレームを
書き込み時刻と紐付けることは、一見問題ないように見えても誤りとなるためです — しかし、エクスポートでは正常に読み込まれ、
CSVファイルにはどのクロックが使用されているかが明記されています。

反射率測定の全容（カメラを用いたシングルセンサー方式、および環境光／被写体用のデュアルセンサー方式）については、[反射率ワークフロー](reflectance.md)を参照してください。
