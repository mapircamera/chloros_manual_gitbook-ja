# 記録と.daq形式

`.daq`ファイルは、Chlorosの光センサー記録形式であり、1つのDAQセンサーから得られた、較正済みのスペクトルフレームを格納した**SQLiteデータベース**です。 キャプチャセッション中にこれを1つ記録しておけば、後で反射率処理パイプラインが、その瞬間に測定された下向きの放射照度で各画像を割算できるようになります。

## .daqファイルの内容

| プロパティ | 値 |
| --- | --- |
| コンテナ | SQLite データベース。記録ごとにセンサーごとに 1 ファイル |
| ファイル名 | **センサー ID**および**タイムスタンプ** を含む。例：`daq_data_daq-e-def330_2026_04_13_18h30m00.daq` |
| フレームごとのスペクトル | 135点、340～1010 nm（5 nm刻み）、およびCIE XYZ三刺激値 |
| 単位 | 校正済み分光放射照度、**W/m²/nm**（工場出荷時の校正バンドル＋キャッププロファイルが適用済み） |
| 記録されたメタデータ | センサーID（そのユニットの工場出荷時キャリブレーションを取得するためのキー）および適用中のキャッププロファイル — [キャッププロファイルとキャリブレーション範囲](caps-and-range.md) を参照 |

このフォーマットは DAQ-U、DAQ-M、DAQ-E を通じて同一であるため、下流の処理ではどのトランスポートによって記録されたかに関係なく処理できます。

校正済み記録には、センサーの工場出荷時キャリブレーションバンドルが必要です。 DAQ-UおよびDAQ-Mの場合、バックエンドはセンサーIDに基づいてMAPIRのクラウドからバンドルを取得します（取得できない場合は記録を拒否します）。DAQ-Eユニットは、デバイス内にキャリブレーションデータを保持しているため、この対象外となります。

## GUIからの記録

GUI での記録には、**プロジェクトを開いている**必要があります（そうでない場合、「記録」ボタンは無効になります）：

* **すべて記録 / すべて停止** — 「光センサー」サイドバーの上部。接続されているすべてのセンサーで `.daq` による記録を一度に開始または停止します。
* **記録 / 記録停止** — センサーごとに、歯車アイコンの設定モーダル内で行います。記録中は、センサーのリアルタイム情報行に赤い「REC」インジケーターが表示されます。

ファイルは `<project>/light_sensor/` に書き込まれ、録画が停止すると（「停止」、「すべて停止」による場合、または録画中のセンサーが切断された場合を問わず）、完成した `.daq` が **開いているプロジェクトに自動的に追加** されます。 手動での追加手順は不要で、プロジェクトのファイルリストに表示され、すでに反射率処理の準備が整っています。

## CLIからの記録

CLIは、バックエンドのセンサープールを通じて記録を行います（バックエンドは実行中でなければなりません。これらのコマンドは、軽量なHTTPクライアントです）：

```bash
# Connect the sensor into the backend pool
chloros-cli daq pool-connect --eth-host daq-e-def330.local

# Record for 150 seconds, with a human-friendly device label
chloros-cli daq pool-record --sensor-id daq-e-def330 --duration 150 \
    -o ./out --device-name "rooftop-A"

# Or run open-ended and stop explicitly
chloros-cli daq pool-record --sensor-id daq-e-def330            # --duration defaults to 0 = run until --stop
chloros-cli daq pool-record --sensor-id daq-e-def330 --stop
```

`--sensor-id`の値を`chloros-cli daq pool-list`から取得します。知っておくべき2つのデフォルト設定：

| オプション | デフォルト |
| --- | --- |
| `--duration` | `0` — `pool-record --stop`まで記録 |
| `--output` / `-o` | `~/Documents/DAQ Live View/` **バックエンド**のファイルシステム上に記録（CLIのファイルシステム上ではない） |

CLIが別のマシン上のバックエンドをターゲットにしている場合、出力ディレクトリの違いが重要になります。ファイルはバックエンドが実行されている場所に保存されます。

## Pythonからの記録

`DAQSensorSession`（`chloros_sdk.connect_daq_sensor()`によって返される）は、同じプール化された記録を公開します： `record_start(output_dir=None, device_name=None)`はファイルパスを返し、`record_stop()`は`{path, rows}`を返します。 完全なセッション API については、[SDK リファレンス](../reference/sdk-reference.md)を参照してください。 SDKのダイレクトハードウェアクラス（デスクトップインストールのみ）は、デフォルトで記録データを`~/Documents/DAQ/`に書き込みます。リリース版ビルドでは、上記のプールされたパスがサポートされる経路となります。

## 処理時に .daq ファイルを使用する場合

画像から反射率を算出するには、Chloros に対して、各露出に一致する下向きの放射照度が必要です：

* **`.daq` を画像と一緒に保管してください。** 処理時、パイプラインは、記録された `.daq`（DAQ モデルは問わない）— または画像と一緒に保存されている DAQ-M ネイティブの `.csv` ）から自動的に解決します。GUIの記録データは、停止した瞬間にプロジェクトに追加されるため、この条件を自動的に満たします。
* **キャリブレーションはオンデマンドで取得されます。** カメラごとまたはDAQごとの工場出荷時キャリブレーションバンドルがローカルにキャッシュされていない場合、Chlorosは初回使用時にMAPIRのクラウドから自動的に取得します （初回のみインターネット接続が必要；`~/.chloros/`の下にキャッシュされます）。
* **ライブキャプチャは独自のサイドカーファイルを書き込みます。** ライブでキャプチャされた反射率フレームについては、実際に使用されたDAQの測定値が画像の隣に `.daq` サイドカーファイルとして保存されるため、元の記録データがなくても後でキャプチャを再処理できます。

## 放射照度の抽出

プロジェクトを処理すると、そのプロジェクトに含まれるすべての光センサーの記録が、
画像プロダクトの隣にある「`Light Sensor/`」フォルダにエクスポートされます。 これには画像は**必要ありません**。
単独で飛行した光センサーの記録は完全なキャプチャであり、`.daq`
ファイルのみを含むフォルダも有効な入力となります。実行レポートには、書き出された光センサー製品の数が記載されます。

| 製品 | 内容 |
| --- | --- |
| `<name>_calibrated.daq` | ライブ記録と同じスキーマを持つ再処理可能なアーカイブ。生成に使用されたキャリブレーションバンドルが宣言されています。これを再インポートしても、**再度**キャリブレーションされることはありません。 |
| `<name>_calibrated.csv` | センサー独自の波長グリッドに基づくスペクトル放射照度（W/m²/nm）。1行につき1つの測定値に加え、測光関連の列（総出力、明所視および暗所視のルクス、青・緑・赤に分割されたPPFD、およびピーク波長）が含まれます。 |

キャリブレーション・バンドルを取得できない DAQ-U または DAQ-M（オフラインであるか、
そのセンサーのキャリブレーションデータがファイルに存在しない場合）は、**理由を付記してスキップ**され、生カウントを含む
「キャリブレーション済み」ファイルとして書き出されることはありません。インターネットに接続して再実行してください。 DAQ-E
は独自の校正情報を保持しているため、ユニットが接続されておらず、
ローカルに何もキャッシュされていない場合にのみこれが必要です。

### DAQ-A：生カウント、そしてそれが正しい答えである理由

**DAQ-A**は、シリアルごとのキャリブレーションバンドルシステムが導入される以前に開発されたものであり、取得すべきバンドルが
存在しません。 これは見落としではありません。DAQ-Aは現場で
反射率ターゲットを用いてキャリブレーションされ、ターゲットベースのキャリブレーションに必要なのはセンサーの*相対*
応答のみであり、それはまさに生カウントそのものです。Chlorosは現在、これらを用いてキャリブレーションを行っています。

したがって、DAQ-Aの記録データはエクスポートされますが、異なる名前で保存されます：

```
<project>/
└── Light Sensor/
    ├── <name>_raw.daq
    └── <name>_raw.csv
```

`_raw`、つまり `_calibrated` ではありません。これはファイル内のフラグではなく、ファイル名そのものが異なるのです。
なぜなら、ファイルが単なるファイル名としてメールで転送されても、その情報が保持されなければならないからです。 `.csv`
というヘッダーには「`raw spectral sensor counts (NOT irradiance)`」と記載されており、値は
ファイル**内**でのみ比較可能であり、センサー間で比較できないことが警告されています。 実際の放射照度に対してのみ
意味を持つ列（総電力、ルクス、PPFD）は、
カウント値から計算されるのではなく、空欄のままにされています。

古い DAQ-A-SD 記録（スキーマ v1.01 / v1.02）では、ファイルの書き込み時刻のみが記録され、
読み取りごとのタイムスタンプは記録されません。 Chlorosは、これらのデータと画像を照合することはできません――フレームを
書き込み時刻と結びつけることは、一見して間違いには見えなくても実際には誤りとなります――が、エクスポートでは正しく読み込まれ、
CSVにはどのクロックが使用されているかが明記されています。

反射率測定の全容（カメラを備えたシングルセンサー、および環境光／被写体用のデュアルセンサー）については、[反射率ワークフロー](reflectance.md)を参照してください。
