# 反射率のワークフロー

DAQ光センサーは、放射測定画像を反射率に変換します。主に2つのワークフローがあります：

1. **シングルセンサー** — 1つのDAQが下向きの放射照度を測定し、カメラが画像を撮影します。Chloros
は、カメラが捉えた放射輝度をその基準値で割って計算します。
2. **デュアルセンサー** — 2つのDAQセンサー（1つは空を、もう1つは対象物を観測）が、カメラを使用せずにリアルタイムの分光反射率曲線を生成します。

## シングルセンサー + カメラ（下向き基準）

DAQは下向き光センサー（DLS）として機能します： カメラが上向きの放射度 **L**(W/m²/sr/nm) を測定し、DAQが下向きの放射照度**E** (W/m²/nm) を測定すると、Chloros
は各バンドごとの反射率を次のように計算します：

> ρ = π · L / E

DAQの測定値は常に**露光時間とタイムスタンプが一致**しています。これが、DAQとカメラがPTP制御のクロックを共有している理由です（[DAQ-E ネットワークと時刻同期](ethernet-ptp.md)を参照）。 屋外作業ではSunshineコサインキャップを適合させ、正しく宣言してください。キャップの宣言はEを直接スケーリングします（[キャッププロファイルと校正範囲](caps-and-range.md)を参照）。 定量的な作業を行う場合は、計測器の特性を覚えておいてください。定量的な放射照度は、少なくとも 15 秒間の測定値の平均から算出されます。

### ライブキャプチャ

[Cameras]タブでDAQをカメラに紐付けます。各カメラの設定パネルには、[Light Sensors]タブから接続されたすべてのDAQ（DAQ-U/M/E）を一覧表示する**Light Sensor**ドロップダウンがあります。同期化されたアレイの場合、アレイ全体に対するLight Sensorの選択はすべての構成要素に反映されます （個々のカメラでは上書き設定が可能です）。紐付けが完了すると、センサーのスペクトルデータがカメラのDLSスロットに供給され、反射率のエクスポート値は対応する測定値で除算されます。 アレイ内では、独自のセンサーを持つ構成要素は、ライブ合成画像内のそのバンド、エクスポートデータ、および自動露出設定において独自の測定値を使用し、他の構成要素はアレイ全体の測定値を使用します。

知っておくべき2つの動作：

* **DAQがバインドされていない場合 → 反射率は拒否され、偽の値は生成されません。**Chloros
は、反射率の算出結果を拒否し、スキップ理由を記録します。単に精度の低い結果を黙って返すことはありません。
* **使用された測定値は保持されます。** 各反射率フレームについて、実際に適用されたDAQ測定値は、キャプチャの「`daq/`」フォルダ内に「`.daq`」ファイルとして書き込まれるため、後でそのキャプチャを再処理することができます（[記録と.daq形式](recording.md))。その隣にある `.daq.cameras.json` ファイルには、そのデータが記述するカメラ名が記載されており、再処理時にはそのカメラの画像のみが対象となります。

### 記録された画像の処理

飛行後の処理のために、セッション中に `.daq` を記録し、画像と一緒に保管してください。パイプラインは、タイムスタンプが一致するダウンウェル画像を自動的に特定し、初回使用時に MAPIR
のクラウドから不足している工場出荷時のキャリブレーションデータを取得します。GUI 記録は、停止すると自動的に開いているプロジェクトに追加されます。

反射率基準は処理時に選択可能です。`--reflectance-source` 上の `chloros-cli process`、または GUI の「プロジェクト設定」にある「反射率ソース」設定から選択できます：

| 値 | 動作 |
| --- | --- |
| `auto`（デフォルト） | QAに合格したフレーム内キャリブレーションターゲットが絶対基準となり、DAQダウンウェリング（ρ = π·L/E）がフォールバックとなります。 フラグ（パネルの脱落やバンドの順序不備など）がある状態でQAに合格したターゲットは、自動的に優先されません。ターゲット、ターゲット＋DAQ、DAQのみのチェーンが、除外されたパネルでの測定スコア順に試行されます。 |
| `daq` | DAQを優先 |
| `target` | 厳格なインフレームターゲット；DAQによる置換なし |

ターゲットのワークフローについては [キャリブレーション・ターゲット](../calibration-targets.md) を参照し、 [LATTICEの章](../lattice/README.md)および[CLI
リファレンス](../reference/cli-reference.md)を参照してください。エクスポートされた反射率ピクセルを読み込む際は、スタンプされたスケール （LATTICE：32768 = ρ 1.0、XMP `Chloros:PixelScale`；Survey3
：65535）を使用してください — [出力画像形式](../output-image-formats.md)を参照してください。

### DAQの校正範囲外のバンド

DAQの放射測定校正範囲は、約374～974 nmです。Chloros
は、その範囲内にスペクトル重みの半分未満しか含まれないカメラバンドについて、DAQベースの反射率データを拒否し、スキップ理由として`dls-uncalibrated-band-<nm>`を報告します。 現在出荷されているSKUのうち、この影響を受けるのはF988のみです。F988の反射率は、シーン内反射率パネルを使用して校正されます。このバンドはDAQの光センサーの校正範囲外にあるため、Chloros
は最新のパネルキャプチャ値を適用し、パネル測定の合間もその値を維持します。 F988カメラをDAQ専用モードで動作させた場合、Chloros
はそのバンドのDAQベースの反射率をスキップ理由「`dls-uncalibrated-band-988`」として拒否します。パネルによるワークフローがサポートされる方法です。

## デュアルセンサー（周囲光＋被写体）

2つのDAQセンサー（どの組み合わせでも、どのトランスポート間でも）があれば、カメラなしでリアルタイムの反射率スペクトルが得られます。1つのセンサーは空に向けられ（**周囲光源**）、もう1つは被写体に向けられ（**被写体スキャナー**）、Chloros
は波長ごとに次のように計算します：

> R(λ) = 被写体(λ) / 周囲光(λ)

（周囲光が 0 以下の場合は 0 となります）。

### GUIでの操作

「Light Sensors」タブで両方のセンサーが接続されている状態で、センサー追加オーバーレイ（グリッドビューのチャートタイルにある「+」ボタン）を開き、**Combine Ambient + Object**を選択します。 「周囲光源」および「被写体スキャナー」のドロップダウンから2つのセンサーを選択し、「作成」をクリックします。このグループは、独立したチャートとして、また緑色の**REF**バッジが付いたサイドバーの行として表示されます。

### 見かけの反射率と相対反射率 — ラベル付けのルール

Chloros
は、センサーペアが実際に主張できる内容に基づいて、デュアルセンサー出力をラベル付けします：

| センサーペア | ラベル |
| --- | --- |
| 両方のセンサーが校正済み — 工場出荷時のバンドルが読み込まれている | **見かけの反射率** |
| いずれかのセンサーが未校正 | **相対反射率** |

3つのモデルはすべて放射測定法に基づいています。センサーの工場出荷時校正バンドルが読み込まれると、そのスペクトルは絶対値（W/m²/nm）となるため、校正済みのセンサーペアの比率は絶対的な見かけの反射率となります。これは輸送関数によって決定されるものではありません。 生カウントをストリーミングし続けているセンサー（バンドルにアクセスできない場合）がある場合、結果は相対曲線に格下げされます（スペクトル形状は依然として有効です）。両方のセンサーには、正しく宣言されたキャップが設定されている必要があります（[キャッププロファイルと校正範囲](caps-and-range.md)）。

### Python
からの操作

プールされた SDK
インターフェースには、デュアルセンサー専用の呼び出し関数は存在しません。`chloros_sdk.connect_daq_sensor()` を使用して 2 つのセッションを開き、同じラベル付け規則を適用して、`latest()` のスペクトルを自分で比率計算してください。 （完全を期すために、MAPIR
の内部ダイレクトハードウェアインターフェースにもデュアルセンサー記録ツールが存在し、[CLI
リファレンス](../reference/cli-reference.md)に記載されていますが、これは出荷版のCLI
には含まれていません。上記のGUIワークフローがサポートされている正規の操作手順です。）
