# 反射率のワークフロー

DAQ用光センサーは、放射計画像を反射率に変換します。これには、2つの異なるワークフローがあります：

1. **シングルセンサー** — 1つのDAQが下向きの放射照度を測定し、カメラが画像を撮影します。Chlorosは、カメラが捉えた放射輝度をその基準値で割って算出します。
2. **デュアルセンサー** — 2つのDAQセンサー（1つは空を、もう1つは対象物を監視）が、カメラを使用せずにリアルタイムの分光反射率曲線を生成します。

## シングルセンサー + カメラ（降射光基準）

DAQは降射光センサー（DLS）として機能します： カメラは上向きの放射度 **L**(W/m²/sr/nm) を測定し、DAQは下向きの放射照度**E** (W/m²/nm) を測定し、Chlorosは各バンドごとの反射率を次のように計算します：

> ρ = π · L / E

DAQの測定値は常に**露光時間とタイムスタンプが一致**しています。これが、DAQとカメラがPTP準拠のクロックを共有している理由です（[DAQ-E ネットワークおよび時刻同期](ethernet-ptp.md)を参照）。 屋外作業ではサンシャイン・コサイン・キャップを装着し、正しく宣言してください。キャップの宣言により、Eの値が直接スケーリングされます（[キャッププロファイルと校正範囲](caps-and-range.md)を参照）。 定量的な作業を行う場合は、機器の特性を覚えておいてください。定量的な放射照度は、少なくとも 15 秒間の測定値の平均から算出されます。

### ライブキャプチャ

[Cameras]タブでDAQをカメラに紐付けます。各カメラの設定パネルには**Light Sensor**ドロップダウンがあり、[Light Sensors]タブから接続されたすべてのDAQ（DAQ-U/M/E）が一覧表示されます。同期化されたアレイの場合、アレイ全体に対するLight Sensorの選択はすべての構成要素に反映されます （個々のカメラでは上書き設定が可能です）。紐付けが完了すると、センサーのスペクトルデータがカメラのDLSスロットに供給され、エクスポートされる反射率は対応する測定値で除算されます。

知っておくべき2つの挙動：

* **DAQがバインドされていない場合 → 反射率は拒否され、偽の値は生成されません。** Chlorosは、反射率データを拒否し、スキップ理由を記録します。単に品質の低いデータを黙って返すようなことはしません。
* **使用された測定値は保持されます。** 各反射率フレームについて、実際に適用されたDAQ測定値は、画像の隣に`.daq`サイドカーとして書き込まれるため、後でキャプチャを再処理することができます（[記録と.daq形式](recording.md)）。

### 記録された画像の処理

フライト後の処理を行うには、セッション中に `.daq` を記録し、画像と一緒に保存しておいてください。パイプラインは、タイムスタンプが一致するダウンウェルリングを自動的に解決し、 初回使用時には、MAPIRのクラウドから欠落している工場出荷時キャリブレーションデータを自動的に取得します。GUIの記録は、停止すると自動的に開いているプロジェクトに追加されます。

反射率の基準は処理時に選択可能です。`--reflectance-source`上の`chloros-cli process`、またはGUIの「プロジェクト設定」にある「反射率ソース」設定から選択できます：

| 値 | 動作 |
| --- | --- |
| `auto`（既定値） | QAに合格したインフレーム校正ターゲットを絶対基準とし、DAQダウンウェルリング（ρ = π·L/E）をフォールバックとする |
| `daq` | DAQを優先 |
| `target` | 厳密なフレーム内ターゲット；DAQによる置換なし |

ターゲットのワークフローについては [キャリブレーションターゲット](../calibration-targets.md) を、[LATTICEの章](../lattice/README.md) および完全な処理パイプラインについては [CLI リファレンス](../reference/cli-reference.md) を参照してください。 エクスポートされた反射率ピクセルを読み込む際は、スタンプされたスケール（LATTICE：32768 = ρ 1.0、XMP `Chloros:PixelScale`; Survey3: 65535）を使用してください — [出力画像フォーマット](../output-image-formats.md)を参照してください。

### DAQの校正範囲外のバンド

DAQの放射測定的に校正された範囲は、約374～974 nmです。 Chlorosは、その範囲内のスペクトル重みが半分未満のカメラバンドについては、DAQベースの反射率を拒否し、スキップ理由として`dls-uncalibrated-band-<nm>`を報告します。 出荷されているSKUのうち、この影響を受けるのはF988のみです。F988の反射率は、シーン内の反射率パネルを使用して校正されています。このバンドはDAQの光センサーの校正範囲外にあるため、Chlorosは最新のパネルキャプチャを適用し、パネル観測の合間にその値を保持します。 F988 カメラが DAQ 専用で動作している場合、Chloros はそのバンドの DAQ ベースの反射率をスキップ理由 `dls-uncalibrated-band-988` で拒否します。パネルワークフローがサポートされている方法です。

## デュアルセンサー（周囲光 + 被写体）

2つのDAQセンサー（任意の組み合わせ、任意のトランスポート間）を使用することで、カメラなしでリアルタイムの反射率スペクトルが得られます。1つのセンサーは空に向けられ（**環境光源**）、もう1つは被写体に向けられます（**オブジェクトスキャナー**）。Chlorosは波長ごとに次のように計算します：

> R(λ) = 被写体(λ) / 周囲(λ)

（周囲光が 0 以下の場合は 0 となります）。

### GUIでの操作

「Light Sensors」タブで両方のセンサーが接続されている状態で、センサー追加オーバーレイ（グリッドビューのチャートタイル上の「+」ボタン）を開き、**Combine Ambient + Object**を選択します。 [Ambient Light Source]および[Object Scanner]のドロップダウンから2つのセンサーを選択し、[Create]をクリックします。このグループは、独立したチャートとして、また緑色の**REF**バッジが付いたサイドバーの行として表示されます。

反射率チャート（リストビュー）の下には、ライブの**植生指数テーブル**が表示され、青 450 / 緑 550 / 赤 670 / NIR 800 nm のバンド中心を用いて、曲線から指数が算出されます。 絶対スケールを相殺する比率ベースの指数（NDVI、GNDVI、 ENDVI、WDRVI、GRVI、CVI、GCI、MSR）は常に表示されます。 絶対反射率が必要な指標（EVI、SAVI、OSAVI、GSAVI、GOSAVI、MSAVI2、RDVI、 TDVI、LAI、NLI、MNLI、FCI、GEMI）は、両方のセンサーがパワーキャリブレーション済みのモデルの場合にのみ表示されます。

### 見かけの値と相対値 — ラベル付けのルール

Chlorosは、センサーペアが実際に主張できる内容に基づいて、デュアルセンサーの出力をラベル付けします：

| センサーペア | ラベル |
| --- | --- |
| 両方のセンサーが校正済み — 工場出荷時のバンドルが読み込まれている | **見かけの反射率** |
| いずれかのセンサーが未校正 | **相対反射率** |

3つのモデルはすべて放射測定式です。センサーの工場校正バンドルが読み込まれると、そのスペクトルは絶対値（W/m²/nm）となるため、校正済みのセンサーペアは絶対的な見かけの反射率に対する比率を示します。この値はトランスポートによって決定されるものではありません。 生カウントをストリーミングし続けているセンサー（バンドルにアクセスできない場合）があると、結果は相対曲線に格下げされます（スペクトル形状自体は有効です）。両方のセンサーには、正しく宣言されたキャップが設定されている必要があります（[キャッププロファイルと校正範囲](caps-and-range.md)）。

### Pythonより

プールされた SDK サーフェスには、デュアルセンサー専用の呼び出し関数は存在しません。`chloros_sdk.connect_daq_sensor()` を使用して 2 つのセッションを開き、同じラベル付け規則を適用して、それらの `latest()` スペクトルを自分で比率計算してください。 （完全を期すために、MAPIRの内部ダイレクトハードウェアサーフェスにもデュアルセンサー記録ツールが存在しますが、[CLIリファレンス](../reference/cli-reference.md) に記載されています — これは出荷時の CLI には含まれていません。上記の GUI ワークフローがサポートされている実行手順です。)
