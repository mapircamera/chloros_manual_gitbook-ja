# 画像レイヤー

画像ビューアの右上にある**レイヤードロップダウン**を使用すると、ビューアを離れることなく、表示中の画像のすべてのバージョン（ソース画像から、各処理済み製品、計算されたインデックス画像まで）を切り替えることができます。

## 画像レイヤーとは？

Chloros

における「レイヤー」とは、1つのソース画像に対して登録された1つの**プロダクトファイル**のことです。インポートによってソースファイルが取得され、処理によって実行で生成された各プロダクトごとにレイヤーが追加されます。 エクスポートされたファイルはソースファイル名を保持します。製品を識別するのは**フォルダ**であり、レイヤー名はChloros

がそのフォルダに付けたラベルです。

## レイヤー一覧

### 常に表示されるもの

| レイヤー | 内容 |
| --- | --- |
| **JPG**（または**PNG

**/**TIFF

**） | キャプチャ時に取り込まれたベースファイル。Survey3

は、各`.RAW`の隣に`.JPG`をインポートします。LATTICEによるキャプチャでは、PNG

またはTIFF

| **RAW (オリジナル)** | ソースとなるRAWフレーム。表示用にデベイヤー処理が施されているが、補正は一切適用されていない。インポート直後から利用可能 — 処理は不要 |

ベースファイルが**その**生フレームであるLATTICEキャプチャには、個別のベースエントリはありません。`RAW (Original)`がすでにそれを網羅しています。

### Survey3

処理成果物

| レイヤー | 書き込み先 | 存在する時期 |
| --- | --- | --- |
| **RAW (ターゲット)** | — | フレームにキャリブレーションターゲットが含まれていると識別された |
| **RAW (反射率)** | `Reflectance_Calibrated_Images/` | このフレームで反射率キャリブレーションが正常に実行された |
| **ヴィネット補正済み** | `Vignette_Corrected_Images/` | フレームの反射率キャリブレーションが実行できず、かつ *ヴィネット補正* が有効だった |
| **センサー応答** | `Sensor_Response_Images/` | フレームの反射率キャリブレーションは実行できず、かつ *ヴィネット補正* がオフでした |
| **ホワイトバランス調整済み** | `White_Balanced_Images/` | ホワイトバランス調整済みのデータが出力されました |

{% hint style="info" %}
**「ヴィネット補正」と「センサー応答」は互いに排他的な設定であり、両方を同時に有効にすることはできません。** 各カメラモデルにつき、1回の実行ごとに校正されていないフォールバック製品が正確に1つ存在し、*ヴィネット補正*の切り替えによってその製品が選択されます。[プロジェクト設定](../project-settings/project-settings.md)を参照してください。
{% endhint %}

### LATTICE レベル

LATTICE は、1回の処理パスでこれらへのファンアウトをキャプチャします。どのレベルが存在するかは、[プロジェクト設定](../project-settings/project-settings.md) における製品ごとのエクスポート設定およびカメラに適用される設定によって異なります。

| レイヤー | 書き込み先 | 適用対象 |
| --- | --- | --- |
| **RAW (デベイヤー処理済み)** | `Debayered_Images/` | RGB

およびマルチスペクトル |
| **RAW (プレビュー)** | `Preview_Images/` | マルチスペクトル (偽色伸張) |
| **ホワイトバランス調整済み** | `Preview_Images/` | RGB

マスターカメラ — RGB

プレビューはこの名前で登録されており、同名のSurvey3

レイヤーと整合する |
| **RAW (放射輝度)** | `Radiance_Images/` | マルチスペクトルのみ |
| **RAW（放射輝度）** | `Reflectance_Calibrated_Images/` | マルチスペクトルのみ。かつ、対応する `.daq` のダウンウェルリング記録、またはQAに合格したフレーム内ターゲットがフレームを覆っている場合に限る |

RGB

マスターカメラにはバンドごとの放射測定機能がないため、これらのカメラについては放射度および反射度は**適用不可**としてスキップされます。ログにその旨が記録されるため、エラーが黙って発生することはありません。

{% hint style="info" %}
**RAWおよびデベイヤー処理済みレイヤーがプロダクトと位置合わせされます（1.3.0の新機能）。**LATTICEのRAWおよびデベイヤー処理済みファイルは、センサーのネイティブ方位で保存され、XMPにその方位が記録されます。その他のプロダクトは、その方位がすでに適用された状態で保存されます。 ビューアと画像グリッドは、表示時にその記録に基づいて**RAW (オリジナル)**および**RAW (デベイヤー済み)** を切り替えるため、生成レイヤーとRAWレイヤーを切り替えてもフレームが反転しなくなりました。これは表示上の処理のみであり、ファイルが上書きされることはありません。 向き情報が記録されていないファイル（バージョン1.3.0以前に撮影されたもの、または他のソフトウェアで書き込まれたもの）は、保存されたままの状態で表示されます。[出力画像形式](../output-image-formats.md#orientation)を参照してください。
{% endhint %}

クランプマスク（`*_clampmask.tif` フォルダ内の `clamp_masks/`）はレイヤーではありません。Chloros

はインポート時にこれらをスキップします。[出力画像形式](../output-image-formats.md#clamp-masks)を参照してください。

### インデックス、LUT、およびサンドボックスレイヤー

| レイヤーパターン | 例 | 由来 |
| --- | --- | --- |
| **RAW (`<INDEX>` インデックス)** | `RAW (NDVI Index)` | プロジェクト設定で構成されたインデックスごとに1つ、処理中に計算される |
| **`<INDEX>` LUT** | `NDVI LUT` | インデックスのカラーマッピング済みバージョン |
| **サンドボックス (`<Name>` `<Index\|LUT>` `<NNN>`)** | `Sandbox (NDVI LUT 003)` | [インデックス/LUTサンドボックス](index-lut-sandbox.md) エクスポート実行ごとに1つ |

同じインデックス名が異なる設定で複数回設定されている場合、2番目以降は名前に番号（`RAW (NDVI2 Index)`）が付与され、レイヤーを区別できるようになります。

## レイヤーセレクターの使用方法

1. グリッド内のサムネイルをクリックして、画像を全画面表示します
2. ビューアの右上にある **レイヤードロップダウン** をクリックします
3. レイヤーを選択すると、画像が即座に更新されます

ドロップダウンメニューには、**JPG、RAW（オリジナル）、RAW（ターゲット）、RAW（反射率）**が順に先頭に表示され、その後に製品が登録された順に他のすべてのレイヤーが一覧表示されます。

### 画像移動時のレイヤー優先順位

**←**/**→** キーを押すと次の画像に移動し、同じレイヤーを維持しようとします：

1. **完全一致を優先** — 次の画像に同じ名前のレイヤーがある場合、そのレイヤーが表示されます。 これにより、セット全体を順に確認する際も、`RAW (NDVI Index)` レイヤーに留まることができます。
2. **次に、タイプによる一致** — インデックスレイヤーは任意のインデックスレイヤーを、LUTは任意のLUTを、反射率レイヤーは反射率レイヤーを、ターゲットレイヤーはターゲットレイヤーを、オリジナルレイヤーはオリジナルレイヤーを、ベースレイヤーはベースレイヤーを検索します。
3. **さらに、エクスポート用レイヤーのみ** — レイヤーリストがまだ追いついていなくても、ファイルはディスク上にすでに存在するため、名前は保持されます。これにより、処理がまだ書き込み中の段階でも成果物を確認できます
4. **それ以外の場合** — 最初に利用可能なレイヤー（通常はベース画像）

プロジェクト内の `.daq` および `.csv` サイドカーファイルは、矢印キーによるナビゲーションではスキップされるため、画像を順次移動しても光センサーの記録画像に到達することはありません。

ズームやパン操作も画像間で引き継がれるため、同じフィールド位置の「前」と「後」の比較が簡単に行えます。

## レイヤーごとのピクセル値の理解

[カーソル値パネル](opening-an-image-full-screen.md#cursor-values) は、カーソルの位置にある各チャンネルの実際の値を、そのレイヤーが保存されている単位で表示します。表示される列はレイヤーによって異なります：

| レイヤー | 表示単位 | 備考 |
| --- | --- | --- |
| ベース（JPG / PNG

/ TIFF

プレビュー） | DN、0–255 | RGB

に対してガンマ補正された表示値。目視確認のみ |
| RAW（オリジナル） | DN | センサーの生データ（デジタル数値）。ヒストグラムの軸から深度がわかります：255（8ビット）、4095（12ビット）、または65535（16ビット） |
| RAW（デベイヤー処理済み） | DN | 線形、表示の伸縮なし |
| RAW（プレビュー）／ホワイトバランス調整済み | DN | 表示用データ — 伸縮またはガンマ補正済み。測定用ではない |
| RAW（放射輝度） | **W/m²/sr/nm** | Float32 物理放射輝度。DN 列なし |
| RAW（反射率） | DN **および %** | そのファイル独自のスケールで計算されたパーセント値 — 下記参照 |
| インデックス / LUT / サンドボックスエクスポート | インデックス値、またはRGB

成分 | シングルチャンネルのインデックスファイルはインデックス値を報告し、カラーマッピングされたLUTファイルはRed

/Green

/Blue

成分を報告します |

### 反射率：スケールはファイルごとに異なります

{% hint style="warning" %}
**「65,535で割る」のはSurvey3

の場合にのみ正しい。** LATTICEの反射率は異なるスケールで保存されており、これら2つの除数を混同すると、反射率が本来あるべき値のちょうど半分になってしまうことが最もよくある。
{% endhint %}

| ソース | 反射率 1.0 に相当する DN | 識別情報 |
| --- | --- | --- |
| **LATTICE**(M3C / M3M) |**32768** | すべての LATTICE 反射率エクスポートに埋め込まれている XMP タグ `Chloros:PixelScale=32768`。2 倍のヘッドルームにより、1.0 を超える ρ もクリップされずに表現可能 |
| **Survey3**| **65535** | Chloros

のXMPスケールタグなし — Survey3

のキャリブレーションではρ × dtype-maxが書き込まれ、1.0でクリップされる |

GISおよびスクリプト作成の場合：ファイルから`Chloros:PixelScale`を読み取り、それを除算する。 タグが存在しない場合、ファイルはSurvey3

スケール（65535）です。ビューア、インデックス/LUTサンドボックス、およびインデックスエクスポートはすべて、この同じ方法でスケールを処理するため、カーソル位置で読み取れる数値は、インデックスの計算で使用された数値そのものです。

そのスケールに基づくフォーマット固有の保存方法：

* **TIFF

（32ビット、パーセント）** は、DN / 65535 を浮動小数点数として保存します
* **PNG

（8ビット）**および**JPG（8ビット）** は、DN × 255 / 65535 を保存します
* **8ビットキャプチャによる8ビットDNデータ**、またはバージョン1.3.0以前に書き込まれた反射率ファイルは、0～255にクリップされ、スケールタグは含まれません。パネルでは、これらのファイルについてはDNのみが表示され、パーセントの列は表示されません

### 指数値の範囲

| 指数ファミリー | 典型的な範囲 | 読み取り値 |
| --- | --- | --- |
| 正規化差分 (NDVI

、GNDVI

、NDRE

、ENDVI…) | −1 ～ +1 | 健全な植生は通常 0.4～0.9、裸地は 0 付近、水域は負の値 |
| 土壌補正済み（SAVI

、OSAVI

、MSAVI2…） | 概ね −1 ～ +1.5 | NDVI

と同様の読み取り値だが、土壌の背景が抑制されている |
| 比（GRVI

、GCI

、MSR、CIRE…） | 上限なし | 分母となるバンドがゼロに近づくにつれて、比が無限大になる |
| EVI

/ LAI

| 0 ～ 約1、0 ～ 約3.5 | 雲やその他の飽和ピクセルにより両指標が範囲外となるため、まずそれらをマスクする |

各プリセットの正確な計算式については、[マルチスペクトル指数の計算式](../project-settings/multispectral-index-formulas.md)を参照してください。

## 一般的なワークフロー

### 処理前／処理後の比較

1. **RAW (オリジナル)** を選択し、ヴィネット現象と未補正の値を確認します
2. **RAW (反射率)** に切り替えます
3. 比較します — ヴィネットが除去され、値がキャリブレーションされています。ズームやパンは固定されたままなので、同じ地面を見ていることになります

### セット全体にわたって1つのインデックスを確認する

1. 最初に処理した画像を開き、インデックスレイヤーを選択します
2. **→** キーを繰り返し押します。インデックスレイヤーが画像ごとに追従します
3. 作業中にサイドバーのヒストグラムを確認してください。分布に急激な変化が見られるフレームは、詳しく調べる価値があります

### キャリブレーションターゲットの確認

1. ターゲットフレーム上で **RAW (Target)** を選択します
2. ターゲットがはっきりと確認でき、検出されていることを確認します
3. 次のターゲットフレームに移動します — ターゲットレイヤーが追従します

### 反射率値の正確性を確認する

1. **RAW (Reflectance)** を選択します
2. 「カーソル値」パネルの **%** 列を確認します。この値は、そのファイルに対してすでに正しくスケーリングされています
3. フレーム内の既知の素材と照らし合わせて妥当性を確認します。健全な植生はNIR

域で高く、赤域で低くなります。キャリブレーションターゲットの値は、公表されている反射率に近い値を示すはずです

## トラブルシューティング

### 期待していたレイヤーがドロップダウンメニューに表示されない

**考えられる原因**

* 画像が処理されていない — ベースと`RAW (Original)`のみが存在する
* プロジェクト設定で、プロダクトのエクスポートトグルがオフになっている
* そのプロダクトが当該カメラに適用されない（RGB

マスターでは放射輝度および反射率、シングルバンドM3Mモノクロカメラでは任意のインデックス）
* 反射率キャリブレーションの処理対象が存在しない — `.daq`のダウンウェルカバレッジがなく、QAに合格したフレーム内のターゲットもない — そのため、そのフレームは「Vignette Corrected」または「Sensor Response」にフォールバックした

**対処方法**

1. 実行ログを確認してください：Chloros

は、要求されたエクスポートプロダクトが作成不可能だった場合、その理由を明記しています
2. [プロジェクト設定](../project-settings/project-settings.md)内のプロダクトごとのエクスポート切り替え設定を確認してください
3. プロジェクトの出力ツリー内に、そのプロダクトのフォルダが存在することを確認してください
4. 該当プロダクトを有効にして再処理してください

### レイヤーリストが古くなっているようです

Chloros

は、実行中にプロジェクトの製品フォルダを再スキャンし、ディスク上に実際に存在するデータに基づいて欠落したレイヤーの登録を修復します。そのため、エクスポートが正常に完了したレイヤーは、ポーリング中に自動的に表示されます。画像から別の画面に切り替えてから戻ると、再解決が強制されます。

### 反射率の値が本来あるべき値の半分になっている

ほぼ間違いなく、LATTICEファイルを65535で割っている可能性があります。`Chloros:PixelScale` (32768) を使用するか、すでにこの処理が適用されている **%** 列の値を確認してください。

### インデックスレイヤーは存在するが、画像が空白である

インデックスには、そのレイヤーにないバンドが必要です。例えば、1チャンネルまたは2チャンネルのファイルに、第3チャンネルを読み取るインデックスが適用されている場合などです。マルチバンドレイヤー（反射率またはデベイヤー処理済み）に切り替えるか、カメラのフィルターに適したインデックスを選択してください。
