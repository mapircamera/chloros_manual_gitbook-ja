# 画像レイヤー

画像ビューアの右上にある**レイヤードロップダウン**を使用すると、ビューアを離れることなく、表示中の画像のすべてのバージョン（ソース画像から、各処理済み画像、計算されたインデックス画像まで）を切り替えることができます。

## 画像レイヤーとは？

Chlorosにおける「レイヤー」とは、1つのソース画像に対して登録された1つの**プロダクトファイル**のことです。インポートによってソースファイルが取得され、処理によってその実行で生成された各プロダクトごとにレイヤーが追加されます。 エクスポートされたファイルはソースファイル名を保持します。プロダクトを識別するのは**フォルダ**であり、レイヤー名は、そのフォルダに対するChlorosのラベルです。

## レイヤー一覧

### 常に存在するレイヤー

| レイヤー | 内容 |
| --- | --- |
| **JPG**(または**PNG**/**TIFF**) | キャプチャとともに取り込まれたベースファイル。Survey3は、すべての`.RAW`の隣に`.JPG`を取り込みます。 LATTICEキャプチャには、PNGまたはTIFFの表示プレビューが含まれます。実際にインポートされた内容に応じてラベル付けされています |
| **RAW (オリジナル)** | ソースとなるRAWフレーム。表示用にデベイヤー処理済みですが、補正は一切適用されていません。 インポートした直後から利用可能 — 処理は不要 |

ベースファイルが **その** RAW フレームである LATTICE キャプチャには、個別のベースエントリはありません。`RAW (Original)` がすでにそれを網羅しています。

### Survey3 処理結果

| レイヤー | 書き込み先 | 存在するタイミング |
| --- | --- | --- |
| **RAW (ターゲット)** | — | フレームにキャリブレーションターゲットが含まれていると識別された |
| **RAW (反射率)** | `Reflectance_Calibrated_Images/` | このフレームで反射率キャリブレーションが正常に実行された |
| **ヴィネット補正済み**| `Vignette_Corrected_Images/` | フレームの反射率キャリブレーションが実行できず、**かつ** *ヴィネット補正* が有効だった |
| **センサー応答** | `Sensor_Response_Images/` | フレームの反射率キャリブレーションは実行できず、かつ *ヴィネット補正* はオフでした |
| **ホワイトバランス調整済み** | `White_Balanced_Images/` | ホワイトバランス調整済みのデータが出力されました |

{% hint style="info" %}
**「ヴィネット補正」と「センサー応答」は互いに排他的であり、両方が有効になることはありません。** 各実行につき、各カメラモデルごとに、キャリブレーションされていないフォールバック製品が正確に1つ存在し、*ヴィネット補正*の切り替えによってその製品が選択されます。[プロジェクト設定](../project-settings/project-settings.md)を参照してください。
{% endhint %}

### LATTICE レベル

LATTICE は、1回の処理パスでこれらへのファンアウトをキャプチャします。どのレベルが存在するかは、「プロジェクト設定」内の製品ごとのエクスポート切り替え設定およびカメラに適用される設定によって異なります。

| レイヤー | 書き込み先 | 適用対象 |
| --- | --- | --- |
| **RAW (デベイヤー処理済み)** | `Debayered_Images/` | RGB およびマルチスペクトル |
| **RAW (プレビュー)** | `Preview_Images/` | マルチスペクトル (偽色伸張) |
| **ホワイトバランス調整済み** | `Preview_Images/` | RGB マスターカメラ — RGBのプレビューは、同名のSurvey3レイヤーと位置が一致するように、この名前で登録されています |
| **RAW（放射輝度）** | `Radiance_Images/` | マルチスペクトルのみ |
| **RAW (放射度)** | `Reflectance_Calibrated_Images/` | マルチスペクトルのみ。かつ、対応する `.daq` 下向き記録、または品質保証（QA）に合格したフレーム内ターゲットが当該フレームをカバーしている場合に限る |

RGB マスターカメラにはバンドごとの放射測定機能がないため、これらのカメラについては放射度および反射度は **適用不可** としてスキップされます。この場合、ログにその旨が記録され、エラーが黙って発生することはありません。

### インデックス、LUT、およびサンドボックスレイヤー

| レイヤーパターン | 例 | 出典 |
| --- | --- | --- |
| **RAW (`<INDEX>` インデックス)** | `RAW (NDVI Index)` | プロジェクト設定で構成されたインデックスごとに1つ、処理中に計算される |
| **`<INDEX>` LUT** | `NDVI LUT` | インデックスのカラーマッピング済みバージョン |
| **サンドボックス (`<Name>` `<Index\|LUT>` `<NNN>`)** | `Sandbox (NDVI LUT 003)` | [インデックス/LUTサンドボックス](index-lut-sandbox.md)のエクスポート実行ごとに1つ |

同じインデックス名が異なる設定で複数回設定されている場合、2回目以降は名前に番号（`RAW (NDVI2 Index)`）が付与され、レイヤーが区別できるようになります。

## レイヤーセレクターの使用方法

1. グリッド内のサムネイルをクリックして、画像を全画面表示します
2. ビューアの右上にある**レイヤードロップダウン**をクリックします
3. レイヤーを選択すると、画像が即座に更新されます

ドロップダウンメニューには、**JPG、RAW（オリジナル）、RAW（ターゲット）、RAW（反射率）**が順に先頭に表示され、その後に製品が登録された順序で他のすべてのレイヤーが一覧表示されます。

### ナビゲーション時のレイヤー優先順位

**←**/**→** キーを押すと次の画像に移動し、同じレイヤーのままになるよう処理されます：

1. **完全一致を優先** — 次の画像に同じ名前のレイヤーがある場合、そのレイヤーが表示されます。 これにより、セット全体を順に確認する際も、`RAW (NDVI Index)` レイヤーに留まることができます。
2. **次に、タイプによる一致** — インデックスレイヤーはインデックスレイヤーを、LUTはLUTを、反射率レイヤーは反射率レイヤーを、ターゲットレイヤーはターゲットレイヤーを、オリジナルレイヤーはオリジナルレイヤーを、ベースレイヤーはベースレイヤーをそれぞれ探します。
3. **さらに、エクスポート用レイヤーのみ** — レイヤーリストがまだ追いついていなくても、ファイルはディスク上にすでに存在するため、名前は保持されます。これにより、実行中にファイルが書き込まれている最中でも、成果物を確認できるようになります
4. **それ以外の場合** — 最初に利用可能なレイヤー（通常はベース画像）

プロジェクト内の `.daq` および `.csv` サイドカーファイルは、矢印キーによるナビゲーションではスキップされるため、画像を順次閲覧しても、光センサーによる記録画像に到達することはありません。

ズームやパン操作は画像間でも引き継がれるため、同じフィールド位置の「前」と「後」の比較が簡単に行えます。

## レイヤーごとのピクセル値の理解

[カーソル値パネル](opening-an-image-full-screen.md#cursor-values) には、カーソルの位置にあるチャンネルごとの実際の値が、そのレイヤーが保存されている単位で表示されます。表示される列はレイヤーによって異なります：

| レイヤー | 表示単位 | 備考 |
| --- | --- | --- |
| ベース (JPG / PNG / TIFF プレビュー) | DN、0–255 | RGB でガンマ補正された表示値。目視確認のみ |
| RAW（オリジナル） | DN | センサーの生のデジタル数値。ヒストグラムの軸には深度（255（8ビット）、4095（12ビット）、または65535（16ビット））が表示されています |
| RAW（デベイヤー処理済み） | DN | 線形、表示ストレッチなし |
| RAW（プレビュー）／ホワイトバランス済み | DN | 表示用データ — ストレッチまたはガンマ補正済み。測定用ではありません |
| RAW（放射度） | **W/m²/sr/nm** | Float32 物理放射度。DN 列なし |
| RAW (反射率) | DN **および %** | そのファイル固有のスケールに基づいて計算されたパーセント値 — 下記参照 |
| インデックス / LUT / サンドボックスエクスポート | インデックス値、または RGB コンポーネント | シングルチャンネルのインデックスファイルはインデックス値を報告します。 カラーマッピングされたLUTファイルはRed/Green/Blueの各コンポーネントを報告します |

### 反射率：スケールはファイルごとに異なります

{% hint style="warning" %}
**「65,535で割る」という方法は、Survey3の場合にのみ正しいです。** LATTICEの反射率は異なるスケールで保存されており、この2つの除数を混同することが、反射率が本来あるべき値のちょうど半分になってしまう最も一般的な原因です。
{% endhint %}

| ソース | 反射率1.0に相当するDN | 識別子 |
| --- | --- | --- |
| **LATTICE**(M3C / M3M) |**32768** | すべてのLATTICE反射率エクスポートに埋め込まれているXMPタグ「`Chloros:PixelScale=32768`」。 2倍のヘッドルームがあるため、1.0を超えるρもクリップされることなく表現可能 |
| **Survey3**|**65535** | Chloros XMPスケールタグがない場合 — Survey3キャリブレーションにより、ρ × dtype-maxが書き込まれ、1.0でクリップされる |

GISおよびスクリプトの場合：ファイルから`Chloros:PixelScale`を読み取り、それで割ります。タグが存在しない場合、ファイルはSurvey3スケール（65535）となります。 ビューア、インデックス/LUTサンドボックス、およびインデックスエクスポートはすべて、この同じ方法でスケールを解決するため、カーソル位置で読み取れる数値は、インデックスの計算で使用された数値そのものです。

そのスケールに基づくフォーマット固有の保存方法：

* **TIFF (32ビット、パーセント)** は、DN / 65535 を浮動小数点数として保存します
* **PNG (8ビット)**および**JPG (8ビット)** は、DN × 255 / 65535 を格納します
* **8ビットソースのキャプチャを8ビットのTIFF形式でエクスポートした場合**、リスケールされるのではなく0～255にクリップされ、意図的にスケールタグは付加されません。パネルには、これらのファイルについてDNのみが表示され、パーセントの列は表示されません

### インデックス値の範囲

| インデックスファミリー | 代表的な範囲 | 読み方 |
| --- | --- | --- |
| 正規化差分 (NDVI, GNDVI, NDRE, ENDVI…) | −1 ～ +1 | 健全な植生は通常 0.4～0.9；裸地は 0 付近；水域は負の値 |
| 土壌補正済み (SAVI, OSAVI, MSAVI2…) | 概ね −1 ～ +1.5 | NDVIと同様の測定値だが、土壌のバックグラウンドが抑制されている |
| 比率（GRVI、GCI、MSR、CIRE…） | 上限なし | 分母となるバンドがゼロに近づくにつれて、比率は無制限に増加する |
| EVI / LAI | 0 ～ ~1、0 ～ ~3.5 | 雲やその他の飽和ピクセルにより、両方が範囲外となるため、まずそれらをマスクする |

各プリセットの正確な計算式については、[マルチスペクトル指数の計算式](../project-settings/multispectral-index-formulas.md)を参照してください。

## 一般的なワークフロー

### 処理前／処理後の比較

1. **RAW (オリジナル)** を選択し、ヴィネット効果とキャリブレーション前の値を確認します
2. **RAW (反射率)** に切り替えます
3. 比較します — ヴィネット効果が除去され、値がキャリブレーションされています。ズームやパン操作は固定されたままなので、同じ地面を見ている状態になります

### 一連の画像全体にわたって 1 つのインデックスを確認する

1. 最初に処理した画像を開き、インデックスレイヤーを選択します
2. **→** キーを繰り返し押します — インデックスレイヤーが画像ごとに追従します
3. 作業中にサイドバーのヒストグラムを確認してください。分布に急激な変化が見られるフレームは、詳しく調べる価値があります

### キャリブレーションターゲットの確認

1. ターゲットフレームで **RAW (Target)** を選択します
2. ターゲットがはっきりと確認でき、検出されていることを確認します
3. 次のターゲットフレームに移動します — ターゲットレイヤーが追従します

### 反射率値の正確性を確認する

1. **RAW (Reflectance)** を選択します
2. 「カーソル値」パネルの **%** 列を確認してください。このファイル用にすでに正しくスケーリングされています
3. フレーム内の既知の素材と照らし合わせて妥当性を確認してください。健全な植生は NIR の値が高く、赤の値が低くなります。キャリブレーションターゲットの値は、公表されている反射率に近い値になるはずです

## トラブルシューティング

### 期待していたレイヤーがドロップダウンメニューに表示されない

**考えられる原因**

* 画像が処理されていない — ベースレイヤーと `RAW (Original)` のみが存在する
* プロジェクト設定で、そのプロダクトのエクスポートトグルがオフになっている
* そのプロダクトが当該カメラに適用されない（RGBマスターでは放射輝度および反射率、シングルバンドM3Mモノクロカメラではどの指数も適用されない）
* 反射率キャリブレーションの処理対象となるデータがなかった — `.daq`のダウンウェルカバレッジがなく、QAに合格したフレーム内ターゲットもなかった — そのため、そのフレームは「ヴィネット補正済み」または「センサー応答」にフォールバックした

**対処方法**

1. 実行ログを確認する：Chlorosには、要求されたエクスポート製品が作成できなかった場合とその理由が記載されています
2. [プロジェクト設定](../project-settings/project-settings.md)内の製品ごとのエクスポート切り替え設定を確認する
3. プロジェクトの出力ツリー内に、そのプロダクトのフォルダが存在することを確認してください
4. 該当プロダクトを有効にして再処理してください

### レイヤーリストが古くなっているようです

Chlorosは、実行中にプロジェクトの製品フォルダを再スキャンし、ディスク上に実際に存在するデータに基づいて欠落しているレイヤーの登録情報を修正します。そのため、エクスポートが正常に完了したレイヤーは、ポーリング中に自動的に表示されるようになります。画像から一度切り替えてから戻すと、新しい解決が強制されます。

### 反射率の値が本来あるべき値の半分になっている

ほぼ間違いなく、LATTICEファイルを65535で割っているためです。`Chloros:PixelScale`（32768）を使用するか、すでにその処理が適用されている**%**列の値を確認してください。

### インデックスレイヤーは存在するが、画像が空白である

インデックスには、そのレイヤーにないバンドが必要です。例えば、1チャンネルまたは2チャンネルのファイルに、第3チャンネルを読み取るインデックスが適用されている場合などです。マルチバンドレイヤー（反射率またはデベイヤー処理済み）に切り替えるか、カメラのフィルターに適したインデックスを選択してください。
