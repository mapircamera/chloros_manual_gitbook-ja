# インデックス/LUT サンドボックス

インデックス/LUT サンドボックスは、Chloros 画像ビューアのサイドバーにあるインタラクティブなワークスペースです。 フォーミュラを選択し、カメラのチャンネルをそれにバインドし、グラデーションで色を付け、値の範囲を調整すると、操作に合わせて画像がリアルタイムで更新されます。バージョン 1.2.0 以降では、再処理することなく、1 枚の画像またはプロジェクト全体に対して、**作成した設定を保存**することも可能になりました。

## サンドボックスの用途

| Index/LUT サンドボックス (インタラクティブ)        | プロジェクト処理 (バッチ)       |
| -------------------------------------- | -------------------------------- |
| 1 画像ずつ、即座に結果が反映される  | データセット全体を一括処理     |
| 実験的かつ反復的な作業             | あらかじめ設定された設定          |
| リアルタイムでレンダリング；保存は要求時のみ  | 常に出力ファイルを書き込み      |
| 適切な設定を見つけるのに最適 | 設定が確定した後に最適 |

{% hint style="success" %}
**通常のワークフロー**：サンドボックスで、可視化結果が希望通りになるまで調整し、その後、サンドボックスから直接エクスポートするか、同じインデックスとLUT設定を [プロジェクト設定](../project-settings/project-settings.md)にコピーします。これにより、次回の処理実行時にそれらの設定がすべての画像に反映されます。
{% endhint %}

## Sandboxの起動

1. グリッド内の画像をクリックします。**画像ビューア**の<img src="../.gitbook/assets/icon_image-viewer.JPG" alt="" data-size="line">タブで全画面表示されます
2. **画像ビューア**の<img src="../.gitbook/assets/icon_image-viewer.JPG" alt="" data-size="line">アイコンをクリックして、左サイドバーがまだ開いていない場合はスライドさせて表示します
3. 右上のレイヤードロップダウンからマルチバンドレイヤーを選択します。校正済みの反射率に基づいて計算されたインデックス値は画像間で比較可能であるため、通常は **RAW (反射率)** を選択します

サイドバーには、上から順に以下の情報が表示されます：

* 画像名とそのカメラモデル
* **画像のエクスポート/保存** ボタン — 「インデックス」または「LUT」にチェックを入れると表示されます
* **インデックス**および**LUT** チェックボックス
* インデックス設定パネル
* 読み取り値、ヒストグラム、GSD コントロールを備えた **カーソル値** パネル

{% hint style="warning" %}
**モノクロカメラでは利用できません。** シングルバンドの LATTICE M3M 画像では、両方のチェックボックスが無効になり、ツールチップに _「モノクロ (M3M) センサーでは利用できません」_ と表示されます — 1つのバンドでは、マルチバンドインデックスは定義されません。M3Mカメラからインデックスを算出するには、2つ以上の画像を位置合わせしたマルチバンドスタックに結合し、LATTICEインデックスエンジンを使用してください。
{% endhint %}

## インデックスの適用

1. サイドバー上部の **インデックス** チェックボックスにチェックを入れます
2. 左側のドロップダウンからカメラのフィルターを選択します（`RGN`、`OCN`、 `NGB`、`RGB`、`RE`、`NIR`）
3. 右側のドロップダウンからインデックス数式を選択します。27種類の組み込み数式に加え、保存済みのカスタム数式も選択可能です
4. 数式は以下のように数式として表示され、各バンドスロットには空の円が表示されます。**色付きのチャンネル円をスロットにドラッグ**して紐付けます
5. 数式で使用されるすべてのスロットがバインドされると、画像が更新され、インデックス値が表示されます
6. 画像上にカーソルを合わせると値を確認できます。**カーソル値**パネルには、カーソルの下にある値を含むインデックス行が追加されます

バインドされたスロットをダブルクリックすると、そのスロットの内容がクリアされます。 数式が未完成の状態は、ドラッグ中の通常の状態であり、エラーではありません。数式が完成するまで、画像は更新されません。

チャンネルサークルには色分けがされています：赤 = Red、緑 = Green、 青 = Blue、オレンジ = Orange、シアン = Cyan、紫 = NIR、マゼンタ = RE。 「カーソル値」パネルのチャンネルドットおよびヒストグラム曲線にも、同じ色が使用されています。

### NDVI の例

```

Formula: (NIR - Red) / (NIR + Red)

For a Survey3W RGN camera:
  NIR = 850 nm band
  Red = 661 nm band

Result range:          -1.0 to +1.0
Typical vegetation:     0.4 to 0.9
Stressed vegetation:    0.2 to 0.4
Bare soil:              0.0 to 0.2
Water:                 -0.1 to 0.1
```

完全な式のリファレンス（3つのプリセットリストすべてと、どの名前がどこで機能するか）については、[マルチスペクトルインデックス式](../project-settings/multispectral-index-formulas.md)を参照してください。

### 「インデックス」にチェックを入れ、LUTを使用しない場合

画像は**グレースケール**で描画され、2つの閾値の間で伸縮されます。これは意図的な仕様です。インデックス画像はスカラーデータであり、グレースケール表示こそがそのデータを忠実に再現したものです。カラー表示が必要な場合は、LUTを追加してください。***

## LUT（ルックアップテーブル）の操作**ルックアップテーブル**は、インデックス値を色にマッピングします。例えば、入力値 NDVI 0.65 に対して、特定の緑色を出力します。これはデータ自体を変更するものではなく、データの読み取り方を変更するものです。

### LUTの追加

1. 数式のすぐ下にある「<img src="../.gitbook/assets/image (1) (1) (1).png" alt="" data-size="line">」の**「+ LUTを追加」**ボタンをクリックします
2. カラーグラデーションを選択します
3. クリッピングの最小値と最大値を設定します
4. クリッピングモードを選択します
5. サイドバーの **LUT** チェックボックスにチェックを入れてレンダリングします

LUT がインデックス上で実際に設定されるまで、LUT チェックボックスは無効のままです。

### カラーグラデーションの選択

**グラデーションバー**にカーソルを合わせると、プリセットリストが開きます。Chlorosには**7つ**のグラデーションプリセットが搭載されています：

| # | グラデーション                            | 形状                                                               |
| - | ----------------------------------- | ------------------------------------------------------------------- |
| 1 | Red → 黄色 → Green (**デフォルト**)  | 発散型 — 一般的な植生の直感（緑＝健全）に合致 |
| 2 | 紫 → 黄色 → Green             | 発散型、低域が明確に区別される                                  |
| 3 | 茶色 → 白 → Blue                | 明るい中間値を軸に発散                                   |
| 4 | 黒 → 紫 → ピンク → 淡黄色 | 順次変化、暗い色から明るい色へ                                           |
| 5 | Red → 黄色 → Blue                 | 明るい中間点を軸に発散                                   |
| 6 | 紫 → Blue → Green → 黄色      | 順次変化（暗い色から明るい色へ）                                           |
| 7 | Orange → 白 → 紫             | 明るさの中間点を軸に発散する                                   |

**発散型**のグラデーションは、ウィンドウの中央に中間色を配置します。これは、中間点が何らかの意味（閾値、基準日など）を持つ場合に視認性が高くなります。**順次**グラデーションは、暗い色から明るい色へと単調に変化するため、「多い」と「少ない」しか表現しない量を示す場合に読みやすくなります。

各プリセットには7つのカラーストップがあります。プリセットをクリックすると、画像が即座に更新されます（LUTボックスにチェックが入っている場合）。

### カラーストップの編集

グラデーションバーの下には、ストップごとに1つずつ、カラースウォッチが並んでいます：

* **色の変更**：スウォッチをクリックしてカラーピッカーを開きます（カラーホイール、RGB/HSVスライダー、または`#FF0000`などの16進数コード）
* **ストップの追加**：行の末尾にある**+** ボタンをクリックすると、白いストップが追加されます
* **ストップの削除**：スウォッチを**ダブルクリック** します
* **編集したグラデーションを保存**：グラデーションバーの横にある保存アイコンをクリックすると、編集したグラデーションがプリセットリストに追加され、再度選択できるようになります

インデックスで設定したグラデーションは、プロジェクトの設定内でそのインデックスと共に保存されるため、プロジェクトを閉じて再開しても維持されます。

**ストップの数が少ない**と、分類のように認識される明確なゾーンが形成されます。**ストップの数が多ければ**、滑らかで写真のような自然なグラデーションが得られます。3～5ストップはプレゼンテーション用スライドや分類図に適しており、6～10ストップは一般的な分析に適しています。15ストップ以上は、詳細な検査や出版用の図表に適しています。

### 値の範囲の設定

しきい値コントロールは、−1 から +1 までの範囲を持つ **デュアルハンドルスライダー**で、両端には正確な値を入力するための編集可能なテキストボックスと、**AUTO** ボタンがあります。

* どちらかのハンドルをドラッグするか、ボックスに数値を入力して Enter キーを押します
* **AUTO**を選択すると、範囲が画像の有効なインデックス値の**2パーセンタイルおよび98パーセンタイル** に設定されます。これは外れ値を無視する良い出発点となります。 Chlorosは、結果の丸めを状況に応じて適応的に行います。範囲が非常に狭い場合は小数点以下4桁、狭い場合は3桁、それ以外は2桁に丸めます。
* 手動での調整を行った場合、再度**AUTO**ボタンを押すまで、その設定が**AUTO**設定よりも優先されます

NDVI ウィンドウの例：

| 目標                                    | 最小  | 最大 |
| --------------------------------------- | ---- | --- |
| すべてを表示                         | −1.0 | 1.0 |
| 植生のみ（土壌および水域を除く） | 0.2  | 0.9 |
| 健全な植生のみ                 | 0.5  | 0.9 |
| ストレスを強調                        | 0.2  | 0.5 |

ウィンドウの範囲を狭めると、対象領域内のコントラストが高まり、それ以外の部分は範囲外となります。その際、**クリッピングモード**によって、範囲外のピクセルがどのように扱われるかが決定されます。***

## クリッピングモード

ピクセルのインデックス値が最小/最大ウィンドウの範囲外になった場合、クリッピングモードによってそのピクセルの描画方法が決定されます。

| ドロップダウンラベル                  | 保存値      | 範囲外のピクセルは次のように描画されます                                                                                                |
| ------------------------------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| **最小値と最大値**（デフォルト） | `clip`            | グラデーションの最も近い端の色 — 最小値未満の値は最初の色になり、最大値を超える値は最後の色になります |
| **透明な背景**      | `transparent`     | 完全に透明（真のアルファ）                                                                                                  |
| **インデックス背景**| `indexColor`      | グレースケールで、画像の**全**インデックス範囲に引き伸ばされるため、範囲外の構造もグレーで表示される                |
| **元の背景**         | `backgroundColor` | 基になる画像そのもののため、色のオーバーレイが実際のシーンの上に重なる                                                |

| モード                       | 最適な用途                               | 外観                                      |
| -------------------------- | -------------------------------------- | ----------------------------------------- |
| **最小値および最大値**      | データの完全表示、科学的な分析 | すべてのピクセルに色が付く                      |
| **透明な背景** | GISオーバーレイ、値の範囲を抽出   | ウィンドウ内は色付き、外側は無色              |
| **インデックス背景**       | データの文脈を維持しつつ強調    | 範囲内は色付き、範囲外はグレー               |
| **元の背景**    | レポートやプレゼンテーション              | 範囲内は色付き、範囲外は写真         |

{% hint style="info" %}
**どのモードにおいても、データのないピクセルは常に透明です。** インデックスが有限でない（0/0の除算）か、あるいは正確に−1.0または+1.0である（飽和セネタル：一方のバンドがゼロを示し、もう一方が示さない場合）ピクセルは、極端な値としてではなく、データなしとして扱われます。 これにより、ハイライトの白飛びやシャドウの黒つぶれが、フレーム内の最も極端な値として描画されるのではなく、カラースケールから除外されます。この同じルールが、AUTOしきい値およびインデックスヒストグラムにどのピクセルが反映されるかを定義するため、これら3つはすべて一致します。
{% endhint %}

PNG形式でエクスポートする場合、透明度は保持されます。JPG形式では透明度を表現できません。

## 調整中の値の読み取り

設定パネルの下にある**カーソル値**パネルは、サンドボックスの測定ツールです：

* カーソルを画像上に移動させ、チャンネルごとのソース値と、その行にあるインデックス値を読み取ります
* ヒストグラムの上にある **INDEX** ボタンをオンにすると、フレーム内のインデックス値の分布が表示されます。2つのクリップ閾値はオレンジ色の破線で、カーソルの値は白い線で表示されます。これは、実際にデータを含むウィンドウを選択するための最も迅速な方法です
* **CURSOR** をオンにすると、ポインタの下にある値の位置にマーカー線が表示されます
* 60倍以上（GSDブロックサイズが設定されている場合はそれ以下）にズームすると、表示された個々のピクセルが浮動値付きでハイライト表示されます

実用的な手順：

1. 健全な植生、ストレスを受けた植生、裸地、および水域上の値を記録します
2. それらの値のクラスターが、インデックスヒストグラムのどこに位置しているかを確認する
3. 関心のあるクラスターを囲むように最小値/最大値を設定する
4. クリッピングモードを選択する — _Original Background_ を選択すると、その周囲のシーンが見えるままになる

## サンドボックスからのエクスポート

上記の内容は、保存するまではすべてライブプレビューです。サイドバー上部の **「画像をエクスポート／保存」** ボタンをクリックすると、サイドバーの上にスライドして表示されるペインが開きます（画像を覆うわけではないため、判断対象となる部分を常に確認できます）。

<figure><img src="../.gitbook/assets/image (35).png" alt=""><figcaption></figcaption></figure>### オプション

| オプション                          | 効果                                                                                                                                            |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| **現在の画像に適用**      | 表示されている画像を、これらの設定でそのまま保存します                                                                                                |
| **プロジェクト内の全画像に適用** | プロジェクト内のすべての画像に対して、同じ設定を再実行します。このインデックスに必要なバンドを持たない画像はスキップされ、エラーとして扱われることはありません |
| **インデックス/LUT グラデーションバー**      | エクスポートごとに、値の範囲がラベル付けされた個別の凡例画像も書き出します                                                                     |
| **インデックスヒストグラム**             | エクスポートごとに、データの最小値/最大値およびクリップ閾値を示す個別のヒストグラム画像も書き出します                                               |

画像タブの**GSDブロックサイズ**が1より大きい場合、確定する前にペインにその旨が表示されます。エクスポートでは、ブロック平均処理を含む、現在表示されている内容が保存されます。フル解像度で保存したい場合は、まずGSDコントロールを1に戻してください。

### ファイルの保存先

**エクスポート**をクリックするたびに、**新しい、二度と再利用されないフォルダ**が割り当てられます：

```
<project folder>/Sandbox_Exports/<IndexName>_<Index|LUT>_<NNN>/
```

例：`Sandbox_Exports/NDVI_LUT_001/`、次の実行では`Sandbox_Exports/NDVI_LUT_002/`となります。この番号付けはディスク上の既存データをスキャンして割り当てられるため、再起動や手動でフォルダを削除しても番号は維持されます。 データが上書きされることは一切ありません。サンドボックスの最大の目的は、現在の試行結果を前回の結果と比較することだからです。

フォルダ内には、画像ごとに以下の内容が含まれます：

| ファイル                                                   | 内容                                                   |
| ------------------------------------------------------ | ---------------------------------------------------------- |
| `<source name>_<IndexName>_<Index\|LUT>.png`           | レンダリングされた画像。ビューアに表示された内容とピクセル単位で一致 |
| `<source name>_<IndexName>_<Index\|LUT>_legend.png`    | 要求された場合のグラデーションバー・サイドカー                     |
| `<source name>_<IndexName>_<Index\|LUT>_histogram.png` | 要求された場合のインデックスヒストグラム・サイドカー                  |

2つのサイドカーは、メイン画像がブロック平均化されている場合でも、常に**フル解像度**で書き込まれます。ブロックサイズは表示解像度と同じであり、両方のサイドカーはピクセルごとの実際のインデックス値を読み取ります。 また、画面上に表示されるバージョンよりも多くの情報を出力します。どちらもストレッチウィンドウ _および_ 実際のデータの最小値/最大値を記載するため、プロジェクトを開かなくても、保存された凡例は数ヶ月後でも読み取ることができます。

### 進行状況と結果

プロジェクト全体のエクスポートには数分しかかからないため、実行中は処理をブロックすることなく、ライブの進行状況チャネルを通じて報告が行われます：

* 進行状況バーには「`current / total`」と、書き込み中のファイルが表示されます
* 完了すると、ペインにエクスポートされた画像数、スキップされた画像数、および出力フォルダのパスが表示されます
* スキップされた画像は、その理由とともに一覧表示されます（最大5件が表示され、その後は「+N件」という行が表示されます）。一般的な理由は、このインデックスが必要とするチャンネルをレイヤーが持っていないことです
* プロジェクト内の**どの**画像もそのインデックスを使用できない場合、実行結果は失敗として報告され、空のフォルダが残されることはありません

サンドボックスによるエクスポートは、一度に1つしか実行されません。実行中の処理がある状態で2つ目の実行を開始しようとすると、2つの実行が同じプロジェクトファイルを巡って競合するのを防ぐため、明確なメッセージが表示されて拒否されます。

### グリッドが実行結果を取り込みます

完了した各実行は、[画像グリッド](image-grid.md) ツールバー上に「`<IndexName> <Index|LUT> <NNN>`」というラベルのついた個別のボタンとして表示されます。 これが実行結果を比較する方法です。異なるグラデーションや閾値で2回エクスポートし、グリッド上の2つのボタンを切り替えて比較します。

## カスタムインデックス式 (Chloros+)

{% hint style="info" %}
**作成場所**：サンドボックスのサイドバー、または処理前の**プロジェクト設定**内。どちらでも、同じプロジェクトレベルのリストに書き込まれます。
{% endhint %}

1. インデックス数式のドロップダウンからカスタム数式計算機を開きます （対象となる Chloros+ サブスクリプションでのサインインが必要です）
2. **バンド・スロット記号** `x`、`y`、 `z`、`y`、`a`、`b`、`c` を使用して数式を入力してください（これらはバンド名ではありません）
3. 利用可能な演算子：`+`、`-`、`*`、`/`、 `^`、および `()`（グループ化用）
4. 利用可能な関数：`sqrt()`、`log()`、 `ln()`、`abs()`、`sign()`、`log1p()`、`log2()`
5. 名前を付けて保存します。これにより、フォーミュラドロップダウンの一番下に表示され、組み込みのプリセットとまったく同じように、チャンネルの円をドラッグしてスロットをバインドできます。

```

Modified NDVI with an offset:   (y-x)/(y+x+0.5)
Simple ratio:                   y/x
Three-band difference:          (y-x)/(y+x-z)
Squared ratio:                  (y/x)^2
```

{% hint style="warning" %}
**カスタム数式はGUIでのみ利用可能です。** CLI/SDK `--indices` オプションは、22個の組み込みプリセット名を拡張し、カスタム数式を含むそれ以外の項目を自動的にスキップします。 カスタム数式を一括処理するには、プロジェクト設定で設定して処理を実行するか、サンドボックスの「すべてのプロジェクト画像に適用」エクスポート機能を使用してください。
{% endhint %}

## トラブルシューティング

### 「このレイヤーには、このインデックスに必要なチャンネルがありません」

式が、現在のレイヤーに存在しないチャンネルの位置を読み取ろうとしています。たとえば、1チャンネルまたは2チャンネルのファイルで3スロットのインデックスを指定している場合などです。 マルチバンドレイヤー（反射率またはデベイヤー処理済み）に切り替えるか、お使いのカメラのフィルターに適したインデックスを選択してください。

### 「画像処理バックエンドに接続できませんでした」

バックエンドから応答がありません。 [ログ] タブを確認してください。バックエンドが再起動中の場合、バックエンドが復旧するとサンドボックスは自動的に回復します。

### 円をドラッグしても画像が変わらない

数式がまだ完成していません。未完成の数式は、通常のドラッグ中の状態として扱われます。レンダリングは行われず、エラーとしても報告されません。 数式が使用するすべてのスロットを埋めてください。

### 画像全体が単一の色になっている

クリップウィンドウがデータの範囲から大きく外れている可能性があります。**AUTO**を押して2パーセンタイルまたは98パーセンタイルにスナップするか、**INDEX**ヒストグラムをオンにして、データが実際にどこにあるかを確認してください。

### エクスポートされた色が、表示されていた色と一致しない

一致するはずです。エクスポートパスは、クリッピングモードのアルファを含むライブプレビューを意図的に反映しており、ブロック平均化は、ビューアが行うのと同じように、色付けの_後_に適用されます。 もし異なる場合は、表示時とエクスポート時にGSDのブロックサイズが変更されていないか確認してください。
