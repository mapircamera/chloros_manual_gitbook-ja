# 画像を全画面表示にする

<figure><img src="../.gitbook/assets/image (34).png" alt=""><figcaption><p>画像を全画面表示で開き、右上にレイヤーセレクターを表示</p></figcaption></figure>

Chloros 画像ビューアは、画像の表示、検査、測定を行うための全画面インターフェースです。 ここでは、画面に表示される引き伸ばされたプレビューではなく、**実際のピクセル値**（チャンネルごとのDN、反射率（％）、または放射輝度（W/m²/sr/nm））を読み取ることができます。

## 画像ビューアの起動

### ファイルブラウザから

1. **ファイルブラウザ**タブ<img src="../.gitbook/assets/icon_file-browser.JPG" alt="" data-size="line">を開きます
2. [画像グリッド](image-grid.md)内の任意の**サムネイル**をクリックします
3. 画像が**画像ビューア**タブで全画面表示されます

画像は、グリッドに表示されていた製品で開きます。グリッドが `RAW (Reflectance)` に設定されている場合、そのレイヤーが開きます。

### 画像ビューアのサイドバーを開く

左サイドバーの **画像ビューア** <img src="../.gitbook/assets/icon_image-viewer.JPG" alt="" data-size="line"> アイコンをクリックすると、分析パネルがスライドして表示されます。パネルには、上から順に以下の項目が含まれます：

* 画像名とそのカメラモデル
* **画像のエクスポート/保存** ボタン（インデックスまたはLUTが有効になっている場合のみ）
* **インデックス**および**LUT** チェックボックス、ならびにインデックス設定パネル — [インデックス/LUTサンドボックス](index-lut-sandbox.md)を参照
* **カーソル値** パネル：チャンネルごとの読み出し値、レイヤーヒストグラム、および GSD コントロール***

## ナビゲーションとズーム

### 画像の閲覧

* **次の画像**：→ ボタン、または**→**（右矢印）キー
* **前の画像**：←ボタン、または**←**（左矢印）キー
* **特定の画像へジャンプ**：グリッド画面に戻り、そのサムネイルをクリック

画像間を移動してもズームとパン設定は維持されるため、フレームの同じ位置に留まったまま一連の画像を順に閲覧できます。

### ズーム

ズームは**マウスホイール**で操作し、15%刻みで変更されます。カーソルを基準としており、ポインタの下の点は常にポインタの位置に固定されます。 ズーム範囲は画像とウィンドウのサイズによって制限されます。「ウィンドウに合わせる」状態よりさらに縮小することはできず、上限は画像のネイティブ解像度によって決まります。

フルスクリーンビューアには、ズーム専用のキーはありません。 （グリッド内では、**Ctrl + `+` / `−`** でサムネイルのサイズを変更できます。これは別の操作です。）

### ズーム時のパン

画像上でマウスの左ボタンをクリックしたままドラッグします。 パン操作には制限があり、画像を画面外にドラッグすることはできません。

### 高倍率でのピクセル単位の検査

実効倍率が **60×** を超えると、Chloros はカーソルの下にある個々の表示ピクセルの周囲にハイライトボックスを描画し、その横に浮動値を表示します。

「実効」倍率は GSD ブロックサイズを考慮して計算されます。ブロックサイズが 8 の場合、表示される 1 ピクセルはすでに 8 × 8 のソースピクセルに相当するため、ハイライトは 60× ではなく 7.5× のズーム時に表示されます。閾値以下にズームアウトすると、ハイライトは消えます。

### キーボードショートカット

| キー                             | 位置       | 動作                              |
| ------------------------------- | ----------- | ----------------------------------- |
| **→**                           | フルスクリーン | 次の画像                          |
| **←**                           | フルスクリーン | 前の画像                      |
| **Ctrl + R**                    | フルスクリーン | インデックス/LUTサンドボックスのリセット         |
| **Ctrl + `+`**/**Ctrl + `=`** | グリッド        | サムネイルを拡大（1回の押下につき4ピクセル）  |
| **Ctrl + `−`**                  | グリッド        | サムネイルを小さく（1回の押下につき4ピクセル） |***

## カーソル値

画像の上にカーソルを合わせると、**カーソル値**パネルに、その下の各チャンネルの値が表示されます。

{% hint style="success" %}
**これらはファイルの実際の数値です。** 画面上のキャンバスは8ビットに伸縮されたプレビューであり、これらの数値を提供できないため、Chlorosは実際の製品ファイルからサンプルを抽出して表示しています。そのため、12ビットのRAWフレームでは255を超える値が表示され、 また、float32 ラディアンスレイヤーが物理単位で値を報告する理由でもあります。
{% endhint %}

### 各列の意味

このパネルは、現在表示中のレイヤーに合わせて表示内容が変化します：

| 表示中のレイヤー              | 表示される列    | 備考                                                                                           |
| ---------------------------------- | ---------------- | ----------------------------------------------------------------------------------------------- |
| 反射率                        | **DN**および**%** | パーセント値はそのファイル独自のスケールに基づいて計算されます — 下記を参照                                      |
| 放射度                           | **W/m²/sr/nm**   | 浮動小数点数の物理値。ここではDNに意味がないため、DN列は表示されません                           |
| 生データ / デベイヤー処理済み / プレビュー / JPG    | **DN**           | 整数のデジタル値                                                                         |
| 32ビット反射率（％）のエクスポート | **%** のみ       | 保存されている浮動小数点値はDNではないため、整数に丸めると「`0`」や「`1`」といった意味のない値が表示されてしまう |

各行には、お使いのカメラのフィルターに対応するチャンネル名がラベルとして付いています。たとえば、RGN には `Red / Green / NIR`、 OCN には `Orange / Cyan / NIR`、NGB には `NIR / Green / Blue`、 RGB には `Red / Green / Blue`、RE および NIRおよびモノクロM3Mカメラ。各ラベルには、インデックス式エディタで使用されるチャンネルサークルと一致する色のドットが付いています。

保存された**インデックスおよびLUT**画像は特殊なケースです。これらはスペクトルバンドではなくカラーマップのコンポーネントを保持しているため、 そのため、その行にはカメラのフィルター名ではなく、`Red / Green / Blue`（または単一チャンネルのインデックスファイルの場合は `Index`）というラベルが付けられます。

サンドボックスでインデックスがアクティブな場合、チャンネルの下に追加の行が表示され、カーソル位置の**インデックス値**、インデックス名、およびヒストグラム上のマーカーに対応する白いドットが表示されます。

### 反射率（％）は各ファイル固有のスケールを使用します

{% hint style="warning" %}
**65535 = 100% とは仮定しないでください。** Chloros は、生成したカメラに応じて異なるスケールで反射率を保存しており、ビューアはファイルごとに正しいスケールを判別します。
{% endhint %}

| ソース                  | 反射率 1.0 に相当する DN | 識別方法                                                                                                                               |
| ----------------------- | ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| **LATTICE**(M3C / M3M) |**32768**                      | すべての LATTICE 反射率エクスポートに XMP タグ `Chloros:PixelScale=32768` が書き込まれます。2×のヘッドルームにより、クリッピングすることなく ρ を 1.0 以上に設定できます |
| **Survey3**|**65535**                      | Chloros XMPスケールタグなし — Survey3キャリブレーションはρ × dtype-maxを書き込み、1.0でクリッピングされます                                                               |

ビューア、インデックス／LUTサンドボックス、およびインデックスエクスポートはすべて、単一の実装を通じてスケールを解決するため、カーソル位置で読み取った値は、インデックスの計算で使用された値と同じになります。

知っておくべき2つの点：

* **32ビットのパーセント**TIFFはDN/65535を浮動小数点数として格納し、**8ビット**のPNG/JPGエクスポートはDN × 255/65535を格納します — ビューアはパーセント記号を表示する前に、これら両方を元の値に変換します。
* 復元できないケースが1つあります。**8ビットソースのキャプチャを** **8ビットのTIFF形式でエクスポート**した場合、再スケーリングされず0～255にクリップされ、意図的にスケールタグが含まれていません。これらのファイルの場合、パネルにはDNのみが表示され、 パーセントの列は表示されません。これはバグではなく、仕様です。***

## レイヤーのヒストグラム

カーソル行の下には、表示中のレイヤーのリアルタイムヒストグラムが **256 ビン**で表示されます。デフォルトでは、LATTICE カメラのヒストグラムと同じ測定空間である、重み付けされた `(R + 2G + B) / 4` による 1 本の統合曲線が描画されます。**RGB**を有効にすると、チャンネルごとの曲線に置き換えられ、チャンネルごとの色で表示されます。これらは加算合成されるため、重なり部分も判別可能です。モノクロレイヤーでは常に単一の曲線が描画されます。

横軸はレイヤー固有の単位で表示されます：

| レイヤー       | 軸の単位  | 軸の最大値                                               |
| ----------- | ---------- | ---------------------------------------------------------- |
| 反射率    | パーセント    | 125% — 製品のヘッドルームにより、ρが1.0を超えることが可能           |
| 放射度    | W/m²/sr/nm | フレーム自身のピーク値（有効桁数2桁に切り上げ） |
| 8ビットデータ | DN         | 255                                                        |
| 12ビットデータ | DN         | 4095                                                       |
| 16ビットデータ | DN         | 65535                                                      |

軸がDN単位で表示され、これら3つの上限値のいずれかに達した場合、Chlorosは、表示対象のビット深度も認識します。

ヒストグラムの上部には3つのボタンがあります：

| ボタン     | デフォルト | 効果                                                                                                                                                                                                                                                                                   |
| ---------- | ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **カーソル** | オン      | 上記の行に表示されている正確な値の位置に、ヒストグラム上にマーカー線を引きます。これにより、カーソルの下にあるピクセルがフレーム内の分布のどこに位置しているかを確認できます。RGBモードでは、チャンネルごとに独自の色でマーカーが1つ表示されます。それ以外の場合は、合成値の位置に1つの白いマーカーが表示されます |
| **INDEX**| オン      | インデックスがアクティブな間のみ表示されます。ヒストグラムをソースバンドから**インデックス値の分布**に切り替えます。この際、2つのクリップ閾値がオレンジ色の破線として、カーソルのインデックス値が白線として描画されます                                                          |
| **RGB**| オフ     | 統合された曲線からチャンネルごとの曲線に切り替えます。モノクロセンサーでは、このボタンの表示は**MONO** となり、無効になります。表示するチャンネルは1つしかないためです                                                                                                                                  |

ヒストグラムは、その背後にあるソースピクセルではなく、**表示されているブロック**に基づいて計算されます。GSDブロックサイズを変更すると分布が再計算されるため、ヒストグラム、カーソルマーカー、および表示画像は常に一致します。***

## GSDブロックサイズ

パネルの下部には、**GSD (px)**コントロールがあります。これは、数値入力ボックス、**1 から 256**までのスライダー、および**RESET** ボタンで構成されています。

これは、N × N のソースピクセルブロックを 1 つの表示ピクセルに平均化することで、_表示_される画像の解像度を粗くします。`1` はネイティブ解像度です。

* この設定は、**全画面表示、グリッドサムネイル、カーソルの表示値、および両方のヒストグラム**に影響します。つまり、画像を表示するすべての要素が同じ地上解像度に基づいて表示されます。
* これは**表示のみ**に影響します。 処理やエクスポートには影響しません。唯一の例外は意図的なものです：[インデックス/LUTサンドボックス](index-lut-sandbox.md)でのエクスポートは、現在表示されている内容を保存するため、現在のブロックサイズが反映されます。また、ブロックサイズが1を超えると、エクスポートパネルで警告が表示されます。
* この値は、`viewer_display.gsd_bin` として `project.json` に **プロジェクトごとに** 保存されるため、アプリケーションを閉じて再起動しても保持されます。
* ブロックサイズが 1 を超える場合、カーソルの表示値はソースピクセルではなくブロック単位の値となります。表示される値は、カーソル下のブロックの平均値です。

{% hint style="info" %}
**なぜ「ブロックサイズ」であって、ピクセルあたりのセンチメートルではないのか？** cm/px の数値を算出するには、地上からの高度が必要です。単一フレームの EXIF データには、撮影対象の地形からの高さではなく、平均海面からの GPS 高度が記録されているため、Chloros は正確に算出できない地上距離を表示することはありません。ソースピクセル単位のブロックサイズは、地上サンプリング距離が不明な場合に MAPIR クラウドツールが、地上サンプル距離が不明な場合に採用しているのと同じ代替手段です。
{% endhint %}

## 表示可能な画像タイプ

ビューアの右上にあるレイヤードロップダウンには、現在の画像のすべてのバージョンが一覧表示されます。表示される項目は、カメラや処理内容によって異なります。完全なリストやドロップダウンの動作については、[画像レイヤー](image-layers.md)を参照してください。

### Survey3

* **JPG** — カメラ独自のプレビューファイル
* **RAW (オリジナル)** — ソースデータ（`.RAW`）を、表示用にデベイヤー処理したもので、補正は施されていません
* **RAW (ターゲット)** — キャリブレーションターゲットを含むと識別されたフレーム
* **RAW (反射率)** — キャリブレーション済みの反射率データ（65535 = ρ 1.0）
* **ヴィネット補正済み**/**センサー応答** — キャリブレーションされていないフォールバックデータ
* **ホワイトバランス補正済み** — ホワイトバランス補正済みの画像
* **RAW (`<INDEX>` インデックス)**および**`<INDEX>` LUT** — 算出されたインデックス画像

### LATTICE

LATTICEでのキャプチャでは、パイプラインのレベル名を含む同じドロップダウンが使用されます：

| レイヤー                 | 内容                                                        |
| --------------------- | -------------------------------------------------------------------- |
| **RAW (オリジナル)**    | キャプチャされたソースのRAWフレーム                                     |
| **RAW (デベイヤー処理済み)**   | 線形デベイヤー処理済みの画像                                           |
| **RAW (プレビュー)**     | 表示プレビュー — マルチスペクトルカメラ用の偽色ストレッチ |
| **ホワイトバランス調整済み**    | RGB マスターカメラ用の表示プレビュー（ホワイトバランス＋ガンマ）   |
| **RAW (放射輝度)**    | W/m²/sr/nm 単位の Float32 スペクトル放射輝度                              |
| **RAW (反射率)**    | uint16 反射率、32768 = ρ 1.0                                    |

放射度と反射率はマルチスペクトルのみに適用されます。RGBマスターカメラにはバンドごとの放射測定機能がないため、これらのレイヤーは生成されません。

## インデックスとLUTの適用

サイドバーからマルチスペクトルインデックスおよびカラーLUTを適用します：

1. **Image Viewer** <img src="../.gitbook/assets/icon_image-viewer.JPG" alt="" data-size="line"> サイドバーを開きます
2. **Index** にチェックを入れます
3. カメラのフィルターとインデックス式を選択し、チャンネルの円を式のスロットにドラッグします
4. LUTを追加し、グラデーション、閾値、クリッピングモードを選択します
5. カーソル位置の値を確認し、**エクスポート/画像の保存**で結果を保存します

完全な手順については、[Index/LUT Sandbox](index-lut-sandbox.md) をご覧ください。

## トラブルシューティング

### 画像が開かない

**考えられる原因**：インポート後にファイルが移動または削除された；データが書き込まれていない；非常に大きな画像に対してメモリが不足している。**対処法**：

1. プロジェクトの出力ツリー内に、そのレイヤーのファイルがまだ存在するか確認する
2. 外部ビューアでファイルを開き、破損していないことを確認する
3. 他のアプリケーションを閉じてメモリを解放する

### 画像が真っ黒、真っ白、または異常な色になっている

**考えられる原因**：表示のストレッチに処理対象となるデータがない（ほぼ一定値のフレーム）；異常な値を持つ float32 レイヤー；有効なデータを生成しなかったインデックス。**対処法**：

1. カーソルの値を確認する — すべてのチャンネルがゼロ、またはゼロに近い場合は、問題はデータ側にあり、表示側ではない
2. ヒストグラムを確認する：片端に単一のスパイクがある場合は、そのフレームがクリップされているか、空であることを示している
3. そのレイヤーを生成した実行の処理ログを確認する

### 値がおかしい

**考えられる原因**：想定しているレイヤーとは異なるレイヤーを扱っている；パーセント値と生のDN値を比較している；LATTICEファイルとSurvey3ファイルを、同じ除数を使って比較している。**対処法**：

1. ドロップダウンメニューで選択されているレイヤーを確認してください。パネルの単位はレイヤーに準じます
2. 反射率については、自分でDNを割るのではなく、**%**列を使用してください。どうしても割る必要がある場合は、そのファイルの`Chloros:PixelScale`を使用してください （LATTICEの場合は32768、指定がない場合はSurvey3で65535）
3. GSDブロックサイズを1に戻してください — 1より大きい値に設定すると、ピクセル単位ではなくブロック平均値が読み取られます
4. そのフレームに対して反射率のキャリブレーションが実際に実行されたか確認してください。キャリブレーションされていないフォールバック製品（Sensor Response / Vignette Corrected）は反射率ではありません
