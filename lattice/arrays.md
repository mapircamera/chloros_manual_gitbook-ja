# マルチカメラアレイ

LATTICE **アレイ**とは、2台以上のLATTICEカメラを1つの同期ユニットとして接続したものです。そのうち1台のカメラが**マスター**となり、共有の同期ライン（デフォルトは**Line2**）にハードウェアGPIOトリガーパルスを送信することで、すべてのカメラが同じ瞬間を撮影します。Chloros には、PTP タイムシンク、ライブプレビュー（カメラごとのタイル表示または単一の整列されたマルチバンド合成画像）、および同期キャプチャ機能が追加されています。キャプチャパスごとに 1 つの**フレームグループ** が生成され、その中ではすべてのカメラが同じタイムスタンプとフレーム ID を共有します （キャプチャ出力では `fid:N` として報告されます）。

アレイは、モノクロ（M3M）カメラが植生指数を生成するための仕組みです。1台のカメラが1つのバンドを提供し、アレイがそれらをマルチバンドスタックに位置合わせします。[モノクロカメラと植生指数](mono-indices.md)を参照してください。

アレイを接続するには3つの同等の方法があり、いずれも同一の「smart-prep」フローを実行します：

| インターフェース | 開始点 |
| --- | --- |
| GUI | [カメラ]タブ → **アレイの接続**（青いボタン） |
| CLI | `chloros-cli lattice array-connect --serials SN1,SN2,…`（最初のシリアル番号 = マスター） |
| Python SDK | `connect_array(serials=[…])` → `ArraySession`（最初のシリアル番号 = マスター） |

Smart-prepは、以下の順序で処理を実行します：ネットワーク機能の検出（ICMP DF ping + GVSPプローブ）、同期層の選択、回線に合わせてフレームサイズを自動縮小、PTPの有効化、カメラごとのピクセル形式の自動選択、 各カメラの保存状態に基づく自動露出の初期化、およびLine2でのGPIOトリガ設定を行います。

{% hint style="info" %}
これらの処理が機能するには、リンク上でカメラに到達可能である必要があります。検出、アドレス指定、 初回接続時のキャリブレーションダウンロードについては、[カメラの接続](connecting.md)を参照してください。マルチカメラ構成の場合、リンク速度と同様にホストNICの受信リング設定も重要です。症状と解決策の完全な一覧は、[CLIリファレンス § ホストNICの設定と調整](../reference/cli-reference.md#host-nic-setup--tuning-lattice-arrays)に記載されています。
{% endhint %}

## [Array Connect] ダイアログ

[Cameras] タブ → **[Connect Array]**を選択すると、3 ステップのウィザード（**[Select] → [Display Mode] → [Settings]**）が開始されます。

| バナー | 意味 |

カメラテーブルには、**カメラ / シリアル番号 / IP / マスター (ラジオ) / スレーブ (チェックボックス)** の列があります：

* **マスターを1台**、**スレーブを1台以上**、正確に選択してください。現在のマスターのラジオを再度クリックすると、選択が解除されます。
* **「同期ケーブルなし」**と表示されているカメラは、スレーブとして選択することはできません。トリガー配線のないスレーブは、同期ラインを永遠に待機し続け、無効な映像を送信することになります。 そのカメラは、代わりにスタンドアロンカメラとして接続してください。
* すでにスタンドアロンとして接続されているカメラは *無効化されません*：アレイ接続を行うと、スタンドアロンセッションが解除され、カメラがアレイ内で再起動します。

**次：表示モード →**は、マスターと少なくとも1台のスレーブが選択されると有効になります。**再スキャン** は、検出と配線プローブを再実行します。

{% hint style="warning" %}

****スキャンまたはプローブの実行中は****** **キャンセル**** が無効になります。LATTICE カメラのファームウェアでは、プローブ実行中にキャンセルするとカメラがクラッシュする可能性があります（SDK）。プログレスアイコンが完了するまでお待ちください。
{% endhint %}

## 帯域幅：接続可能なカメラ数

アレイが処理できる容量は、Chloros ではなく回線の特性によるものであるため、計画に必要な数値はハードウェアのマニュアルに記載されています：**[アレイの帯域幅計画](https://mapir.gitbook.io/lattice-camera/setup/array-bandwidth-planning)**。

Chlorosがこれらをどのように処理するか：接続ダイアログはネットワークプローブを実行し、達成可能なフレームレートを予測して、それに適合するティアを選択します。アレイが回線の許容帯域幅を超過している場合、はパケットを黙って破棄するのではなく、接続を拒否します。前述の「予測結果」パネルを参照してください。

## フレームが欠落する場合

公開されたグループからカメラが欠落している場合、その原因は全く異なる2つの理由による可能性があり、
それぞれに対処法も正反対になります。Chlorosは、原因を特定できない「不完全」という単一の数値を報告するのではなく、
これらを個別にカウントします：

| 発生した事象 | 意味 | 確認箇所 |
| --- | --- | --- |
| **破損**— フレームは到着したが構造的に不正だった | ネットワーク経路上のGVSPパケット損失 |**ワイヤーバジェット**、NICの受信リング、ジャンボフレーム、スイッチ |
| **未到着**— フレームが全く届かなかった | カメラが作動しなかった、またはカメラから何も送信されなかった |**M8同期ケーブル**、同期ライン、すべてのメンバーが作動状態にあるか |

アレイがストリーミングしている間、この分類は10秒ごとに再評価されます。 5 % を超えると、
両方の数値が明記されてログに記録され、各カメラごとに破損したバッファは最初に
発生した時点で報告され、その後1分ごとに集計されるため、長時間のセッションでも読み取り可能になります。

**「破損フレーム」があり、「未到着」がゼロである場合は、トリガーとケーブルの同期が完璧であることを意味します**であり、失われたフレームはすべてネットワーク経路上の問題です。対処法は、**Wire Budget**を下げて
再接続することです。

{% hint style="warning" %}
**トリガーレートを下げても、破損フレームの問題は解決しません。** カメラのパケット
ペーシングは、接続時に一度だけ設定されます。 トリガーレートを下げても、バーストが発生する頻度は
変わるものの、バースト自体がネットワーク上に送信される速度は変わりません。測定した4台のカメラで構成されたシステムでは、
トリガーレートを5分の1に削減しても変化は見られませんでしたが、ワイヤ・バジェットを240から
200 MB/sに下げることで、同じリグの破損率が10.4％からゼロになりました。
{% endhint %}

稼働中のアレイは再プランニングを行うことができません。接続を切断して再接続し、接続時の
ピッカーが新しい帯域幅に基づいて動作するようにしてください。

### USBネットワークアダプタは200 MB/sに制限されています

USBイーサネットアダプタは*イーサネット*のリンクレートを広告しますが、実際に
維持できる速度はUSBバスとそのドライバによって制限されます。かつてUSB 10GbEドングルには
約1000 MB/sのスループットが公称されていましたが（実際に測定されたことのない数値です）、その架空の余裕に対して
4台のカメラをその架空の余力に基づいて制御したところ、フレームの6～18％が破損した一方で、アレイは
依然として正常な目標フレームレートを報告していました。現在、USB接続のアダプターの上限は
**200 MB/s**に制限されている。この上限はパーセンテージではなく絶対値である。なぜなら、制限要因は
バスそのものだからだ。USB 1 GbEアダプタは約80 MB/sの転送速度しか得られず、この制限の影響を受けない。

ホストの速度が実際の上限よりも確実に速い場合は、**Wire Budget**をその値に設定して指定する。

## PTP 時刻同期

フレームの *同期* はハードウェアトリガーによって行われますが、**PTP** (IEEE 1588 PTPv2) はすべてのデバイス間で比較可能な *タイムスタンプ* を提供します。これはアレイ接続時にデフォルトで有効になります：

* **Chloros ホストバックエンドが PTP グランドマスターを実行します**。LATTICE カメラおよび DAQ-E 光センサーはドメイン 0 でこれにスレーブとして同期するため、画像のタイムスタンプと DAQ スペクトルは同一のクロック（約 1 ms）で記録されます。
* `--no-ptp` (CLI) は、ベンチワーク用にこれを無効にします。この場合、カメラ間のタイムスタンプは比較**できません**。
* CLI を使用して同期状態を確認します：

```bash
chloros-cli time-sync status     # grandmaster state, clock identity
chloros-cli time-sync peers      # slaves seen (cameras + DAQ-E sensors)
chloros-cli time-sync cameras    # per-camera PtpStatus / PtpOffsetFromMaster / PtpMeanPathDelay
```

「Cameras」タブ自体には PTP インジケーターはありません。各カメラの同期状態として、読み取り専用の **Role**（マスター/スレーブ）、**Sync Line**、およびアレイの Capabilities 階層が表示されます。 DAQ-EのPTP状態は、「Light Sensors」タブのセンサー詳細に表示されます。

## ライブアレイビュー

<!-- SCREENSHOT-NEEDED: Cameras tab with a connected combined array: sidebar showing the ARRAY row (color badge, array name, "DAQ · on" pill) with indented member camera rows, and the main area showing the combined index composite tile with the LUT-colored NDVI render, top-left array name pill, and top-right fps readout. -->

メインフィードエリアには 2 種類のレイアウトがあります（上部バーで切り替え可能）：**グリッドビュー**（各タイルがセルとなります。グリッドの鍵アイコンが解除されているときは、ドラッグして順序を変更できます）と**リストビュー**（上部に全幅のアレイ、その下にアクティブなカメラが 1 台表示されます）。**フィードズーム**スライダーでタイルのサイズを調整できます。セルの幅が200ピクセル未満の場合、名前やfpsのオーバーレイは自動的に非表示になります。**個別表示モード**では、カメラごとに1つのタイルが表示されます。各タイルには以下がオーバーレイ表示されます：

* カメラ名（左上）、
* **fps表示**（右上）— これはバックエンドから報告されるカメラの*実際の取得レート*であり、プレビューのポーリングレートではありません（ライブプレビューは取得レートに関係なく30 fpsに制限されます）、
* ステータスドット — 緑（ストリーミング中）／オレンジ（読み込み中）／赤（エラー）、
* 新しいフレームが2秒間到着しない場合の**古いフレームのスピナー** — 接続や切断後、バックエンドがカメラ間で帯域幅の再配分を行う間、約5秒間はこれが表示されるのが通常です。**複合モード**では、単一の合成タイルが表示されます： バックエンドは、デベイヤー処理、スケーリング、位置合わせ、ノイズ除去を行い、帯域ごとの放射輝度（光センサーがバインドされている場合はDLS反射率を含む）に変換し、配列のインデックス式を評価し、LUTを適用して、結果をMJPEGとしてストリーミングします。最初の位置合わせ済みフレームがレンダリングされるまで、タイルにはその状態が表示されます： 「アレイの準備中…」、「位置合わせのキャリブレーション中…」、「最初のフレームを待機中…」、あるいは — 自動位置合わせの再試行バジェット（約30秒）が消費された場合 — 「位置合わせが必要」というメッセージと**位置合わせのキャリブレーション** ボタンが表示されます。

コンバインドモードに関する有用な情報：

* 合成画像は**マスター**カメラのフレームに同期されます。合成画像に対するAE-ROIの照準合わせやスポット測光は、マスターカメラでは正確ですが、スレーブカメラでは近似値となります。追加のカメラ接続を開かずに、カメラごとのタイルをピクセル単位で正確に表示するには、**Split View**（アレイ設定 → 「メンバーカメラを表示」）を使用してください。
* **レイヤーの表示**（アレイ設定；デフォルトはオフ）では、前景レイヤーと背景レイヤー（メンバーカメラまたは**インデックス**のいずれか）を選択できます。前景レイヤーを「インデックス」に設定すると、LUTの最小/最大値の範囲外のピクセルには背景レイヤーが表示されます。
* ****レンダリング解像度**（デフォルト 720p）は、ライブストリームの高さ *および* 保存される合成画像のエクスポートサイズを設定します。カメラごとの画像は常にフル解像度でエクスポートされます。
* 位置合わせはセッションごとに計算され、保存されることはありません。RMS 残差および「再キャリブレーション」ボタンについては、アレイ設定ペインの位置合わせセクションを参照してください。

## キャプチャ：モニタリングと分析

アレイのキャプチャ領域は、**モニタリンググレード**（表示されているものを記録）と**分析グレード**（生データを記録し、後でキャリブレーションを行う）に明確に分かれています：

| ワークフロー | グレード | 保存内容 | GUI | CLI |
| --- | --- | --- | --- | --- |
| **キャプチャ**（静止画） | 分析 | パスごとに 1 つの同期済みフレームグループ；選択されたすべてのエクスポートレベル（生データ／デベイエリング済み／放射輝度／反射率／プレビュー／インデックス）におけるカメラごとのファイル ＋ `.daq` サイドカーファイル |**すべてキャプチャ**ボタン + キャプチャ設定 | `lattice array-capture` |
| **インデックス動画を記録** | モニタリング | 表示されているライブの複合インデックスコンポジット — 8ビット、プレビュー解像度、LUTが焼き込まれている；ライブストリームを開いている必要がある | ● インデックス動画の記録（結合配列） | `lattice array-record` |
| **生データバースト → ビデオ生成**| 解析 | フルグラブレートでの生センサーフレーム + マニフェスト + `.daq`、その後オフラインで校正済み放射輝度／反射率／インデックス動画へ再構成、DAQの測定値と時刻を同期 | ⦿ 生データバーストの記録 →**ビデオ生成** | `lattice array-burst` → `lattice array-build-video` |

経験則：ピクセルデータが *測定値* として使用される場合は、キャプチャまたはバースト （分析グレード）を使用する。アレイが捉えたものを単に*確認またはデモンストレーション*するだけなら、インデックス動画（モニタリンググレード）を記録する。

### キャプチャ設定（GUI）



<!-- SCREENSHOT-NEEDED: Capture Settings pane (gear next to Capture All) with a connected array: capture-mode buttons (Single/Continuous/Interval), the bulk export-type toggle row, the Fastest Capture toggle, and the per-array group card showing the Aligned checkbox and the "Record index video" / "Record raw burst" buttons. -->**Capture All** の横にある歯車アイコンをクリックすると、キャプチャ設定ペインが開きます（プロジェクトを開いている必要があります — キャプチャデータはそこに保存されます）：

* **キャプチャモード**：**シングル**（1回のみ） /**連続**（連続して実行； キャプチャ回数（デフォルト 1）または時間（デフォルト 10 秒）で制限されます）／**インターバル**（タイムラプス：X 間隔ごとに N 回のキャプチャを Y 回分実行、デフォルトは 5 秒ごとに 1 回、1 分間）。
* **カメラごとのエクスポート形式**：Raw、Debayered、Radiance、Reflectance、Preview、Index — 適用可能なものはすべてデフォルトで有効になっています。Radiance/Reflectanceは、RGB-filterカメラでは非表示になります。**Reflectanceは、カメラにDAQ光センサーがある場合にのみ表示されます**（カメラ固有のもの、またはアレイから継承されたもの）；インデックスには、設定済みのインデックス式が必要です。
* **アラインメント**（アレイ単位、デフォルトは**オン**）：メンバーのエクスポートをアレイのアラインメントプロファイルに合わせてワープし、エクスポートがピクセル単位で位置合わせされるようにします。Rawは常にワープされませんが、メタデータに変換情報が含まれます。
* **最速キャプチャ**（トグル）： raw-only + 割り当てられたDAQ測定値 + フリーの複合インデックスを組み合わせ、キャプチャ時のキャリブレーション計算をスキップして最大レートを確保 — 保存された`.daq`から後で放射輝度/反射率/インデックスを再構築します。
* 選択内容はプロジェクトとともに保持されます。非表示または一時停止中のカメラはスキップされます。

これと同等のCLI（同じバックエンドエンドポイント、同じセマンティクス）：

```bash
# One synced group, every applicable export level per camera (the default)
chloros-cli lattice array-capture -o output/

# Interval timelapse: one reflectance pass every 10 s for 5 minutes
chloros-cli lattice array-capture --interval 10 --duration 300 --processing reflectance -o timelapse/

# Fastest grab for a moving rig — raw + .daq now, calibrate later
chloros-cli lattice array-capture --fastest -o flightline/

# 30-second monitoring clip of the combined index view, plus a GIF
chloros-cli lattice array-record --duration 30 --fps 10 --gif -o monitoring/

# 5-second analysis-grade raw burst, then build the combined index video
chloros-cli lattice array-burst --duration 5 --build --products combined:index --fps 10 -o capture/
```

TIFF キャプチャの圧縮形式は、`deflate`（ロスレス、デフォルト）または`none`です。完全なフラグテーブル、キャプチャフォルダのレイアウト、および再処理ルールについては、[CLI リファレンス](../reference/cli-reference.md#capture-modes-recorders--offline-reprocess)に記載されています。

## DAQ 光センサーのペアリング

反射率および照度補正済みのプレビューを表示するには、DAQ センサー（**Light Sensors** タブで接続済み）からの下向き光データが必要です：

* サイドバーの **アレイ行**には、**「DAQ · オン/オフ」ピル**が表示されます。アレイレベルの光センサーが設定されている場合、**または** メンバーカメラのいずれかが独自の光センサーを持っている場合は *オン* になります。そのツールチップには、どのセンサーがどのカメラにデータを提供しているかが正確に一覧表示されます。
* アレイ設定 → **周囲光センサー**→**光センサー** ドロップダウンから、アレイ全体に割り当てます。この設定はプロジェクトに保存され、すべての構成カメラに反映されますが、個々のカメラは独自のセンサーでこの設定を上書きすることができます。
* その下のステータス行には、現在の状態が表示されます：**オフ**→ 「最初のスペクトルを待機中…」 →**「アクティブ — アレイ内のすべてのカメラで照度補正済み」** → または、過去 3 秒間に新しいスペクトルが到着しなかった場合は、古いデータである旨の通知が表示されます。この場合、最後の測定値が引き続き使用されます（キャプチャパス上では測定値の有効期限は切れません）。

センサーが割り当てられている場合：「反射率」のエクスポートタイプが利用可能になり、ライブプレビューは照度補正され、予測自動露出がスペクトルを利用できるようになり、すべての反射率キャプチャでは、実際に使用されたDAQの測定値が画像の横に **`.daq` サイドカー**として画像の横に書き込まれ、後でキャプチャを再処理できるようになります。

## `array-connect` CLI オプション

| フラグ | デフォルト | 説明 |
| --- | --- | --- |
| `--serials SN1,SN2,…` | すべての LATTICE カメラを自動検出（2台以上必要） | **最初のシリアルがマスターとなります。** |
| `--line {Line0,Line2,Line3}` | `Line2` | GPIO同期ライン。 |
| `--target-fps F` | auto | マスタートリガーの発射レート。 |
| `--binning {1,2,4}` | 自動 | ハードウェア・ビニング。 |
| `--force-tier {sim-capture-sim-emit, sim-capture-ftd-stagger, slip-emit-and-capture}` | 自動 | 同期階層ピッカーのエキスパートによる上書き。 |
| `--wire-ceiling-mbps MB_PER_S` | 自動検出 | ホストのワイヤ・バジェット（MB/s） — **Wire Budget** フィールドのCLI形式。アレイが破損フレームを報告する場合は、この値を小さくしてください。プロジェクトと共に保存されるため、後で再接続すると復元されます。 |
| `--no-recommend` | off | ネットワーク分析ステップをスキップします。 |
| `--no-ptp` | off | PTPを無効にします（この場合、カメラ間のタイムスタンプは比較できなくなります）。 |

`lattice array-list`、`array-status`、および `array-disconnect` は、永続的なセッションを管理します。アライメント （`align-calibrate` / `align-apply`）およびネットワークツールに関する完全なサブコマンドリファレンスは、[CLI リファレンス § chloros-cli lattice](../reference/cli-reference.md#chloros-cli-lattice)に記載されています。 SDKの対応する項目（`connect_array`、`ArraySession`、`attach_array`、`analyze_array_network`）は、[SDK リファレンス](../reference/sdk-reference.md) に掲載されています。Python によると、ワイヤ・バジェットは `connect_array(..., wire_ceiling_mbps=120)` であり、ライブ・コrupt/未到達（never-arrived）の区分は [`/api/camera/array/<id>/capability`](../reference/sdk-reference.md#array-health--which-subsystem-is-losing-frames)に記載されています。
