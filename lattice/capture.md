# 撮影設定とモード

[カメラ]タブでの撮影は、1つの赤い**[すべて撮影]**ボタンと、そのボタンによる出力内容（どのカメラが対象となるか、各カメラがどのエクスポート形式で保存するか、シャッターが1回だけ、連続して、あるいは一定間隔で切れるか）を決定する**[撮影設定]**ペインによって制御されます。 このページでは、設定、撮影そのもの、ファイルの保存先、および後でそれらをキャリブレーション済みの成果物へと再処理する方法など、一連のフロー全体について解説しています。カメラおよびアレイのコントロール自体は、[カメラ設定](camera-settings.md) にあります。

{% hint style="info" %}
**キャプチャを行うには、プロジェクトを開く必要があります。** プロジェクトが開かれているまで、「すべてキャプチャ」および「キャプチャ設定」の歯車アイコンは無効になります（「キャプチャを保存するには、プロジェクトを作成または開いてください」）。すべてのキャプチャは、`captures/`内のプロジェクトフォルダに保存されます。
{% endhint %}

## キャプチャ設定ペイン

サイドバーのカメラリストにある**「すべてキャプチャ」の横にある歯車アイコン**、または各カメラの設定ペイン下部にある**「キャプチャ設定を開く…」**ボタンから開くことができます。 ヘッダーには「キャプチャ設定」と表示され、← 戻るボタンがあります。

<!-- SCREENSHOT-NEEDED: the full Capture Settings pane — Single/Continuous/Interval mode buttons at top, the bulk export-type toggle rows (All Raw … All Index), the orange Fastest Capture toggle, an array group card with the Aligned checkbox and Record buttons, and an expanded per-camera row showing per-type checkboxes. -->

ここでの選択内容（対象カメラ、タイプごとのチェックボックス、キャプチャモード）は **プロジェクトごとに** 保存され、プロジェクトを再開した際に復元されます。

### キャプチャモード

ペイン上部には3つのモードボタンがあります：

| モード | 機能 | サブ設定（デフォルト） |
| --- | --- | --- |
| **シングル** *（デフォルト）* | 選択されたすべてのカメラで1回のキャプチャを行います。 | — |
| **連続**| 停止条件が満たされるまで連続してキャプチャします。 |**キャプチャ回数**（デフォルト 1）*または* **キャプチャ時間**（デフォルト 10 秒；単位：秒 / 分 / 時間 / 日）で停止します。 |
| **インターバル**（タイムラプス） | タイマーに合わせて連写します。 |**撮影枚数／インターバル**（デフォルト 1） ·**毎**N 単位（デフォルト 5 秒） ·**N 単位の間**（デフォルト 1 分）。 |

連続モードまたはインターバルモードでは、実行中に「すべてキャプチャ」ボタンが **「停止 (N)」** ボタンに変わり、キャプチャが成功するたびにカウントされます。

### カメラとエクスポート形式の選択

このペインのヘルプテキストに要点がまとめられています。「すべてキャプチャ」で生成されるカメラとエクスポート形式を選択します。デフォルトではすべてがオンになっており、選択内容はプロジェクトとともに保存されます。

* **すべて選択 / すべて選択解除** ボタンで、すべてのカメラの「含める」チェックボックスを一括で切り替えることができます。
* **一括エクスポート形式の切り替え**（2 行のボタン）：**All Raw / All Debayered / All Preview / All Radiance / All Reflectance / All Index**。 各トグルは3段階の色で表示されます：緑 ✓ = 対応するすべてのカメラで有効、オレンジ – = 一部のカメラで有効、灰色 = 対応するカメラなし。接続されたカメラのいずれもそのタイプに対応していない場合、トグルは無効になります。「Fastest Capture」がオンの間は、すべてのトグルがグレーアウトします。
* **カメラごとの行**：包含チェックボックスに加え、そのカメラに適用可能なエクスポートタイプの一覧（▸/▾で展開可能）と、個別のチェックボックスがあります。行には「4/6」のような有効数が表示されます。

### エクスポート形式と対応カメラ

6種類のエクスポート形式が存在します：**Raw、Debayered、Radiance、Reflectance、Preview、Index**。各カメラの行には、該当する形式のみが表示されます：

| エクスポートタイプ | 内容 | RGB (FRGB) | ベイヤー多波長 (FRGN/FOCN/FNGB) | モノクロ (M3M) |
| --- | --- | --- | --- | --- |
| **Raw** | センサーから直接読み込まれたベイヤーモザイク（モノクロ：単一バンド） | ✓ | ✓ | ✓ |
| **デベイヤー** | リニアデモザイク（モノクロ：1チャンネルグレースケール） | ✓ | ✓ | ✓ |
| **プレビュー** | 完全な表示処理チェーン（カメラのプロファイルに基づくホワイトバランス＋ガンマ補正；マルチスペクトル：偽色伸縮） | ✓ | ✓ | ✓ |
| **放射輝度** | 完全な放射測定チェーンを経由した float32 W/m²/sr/nm | —（非対応） | ✓ | ✓ |
| **反射率** | uint16 ρ (32768 = 1.0) | — (未提供) | ✓ — カメラにDAQ光センサー（カメラ自身のもの、またはアレイから継承されたもの）がある場合にのみ表示 | マルチスペクトルと同じ |
| **インデックス** | 植生インデックス (LUT) レンダリング | — | ✓ — カメラ上で有効かつ空でないインデックス式が必要であり、複合アレイのメンバーには提供されません（アレイが1つの共有インデックスを所有するため） | —（インデックスには2バンド以上が必要です；[モノカメラと植生インデックス](mono-indices.md)を参照） |

RGBカメラでは、放射輝度および反射率は提供されません。広帯域測光センサーにおいて、ベイヤー単位ごとの放射輝度は意味を成さないためです。

### 最速キャプチャ

**⚡ 最速キャプチャ — RAWのみ**トグル（オン時はオレンジ色）は、すべてのエクスポート設定を**RAWのみ**に上書きします（さらに、アレイ用の無料の複合インデックス合成画像が含まれます）。これにより、フレームは可能な限り速く保存されます： キャプチャ時には、放射度／反射率／表示の計算が完全に省略されます。

{% hint style="info" %}
**`.daq`は引き続き保存されます。** 光センサーが割り当てられている場合、「最速キャプチャ」でもRAWフレームの隣にDAQのダウンウェルリング測定値が書き込まれます。そのため、放射輝度、反射率、および屈折率の算出値は、後で再処理を行うことですべて生成可能です（[キャプチャの再処理](#re-processing-captures-into-calibrated-products)を参照）。 また、「Fastest Capture」はチェックボックスの選択設定を破壊しません。機能をオフにすると、元の設定が復元されます。
{% endhint %}

### アレイごとの制御

接続された各アレイには、ペイン内に独自のグループカードが表示されます：

* **「含める」チェックボックス**（メンバー間で 3 状態）と、アレイ名および表示モード：「(結合 | 個別)」
* **アラインメント**チェックボックス（デフォルトは**オン**）：メンバーのエクスポートデータをアレイのアライメントプロファイルに合わせて歪み補正し、カメラ間でピクセル単位の位置合わせが行われます。 RAWデータはワープ処理されませんが、メタデータに変換情報が格納されます。（プロファイル自体は[アレイ設定ペイン](camera-settings.md#alignment-co-registration-combined-only)で計算されます。）
* メンバーカメラの行はカード内にネストされています。

アレイカードには 2 つのレコーダーも搭載されています。これらを**モニタリングと分析**と捉えてください：

| レコーダー | グレード | 記録内容 |
| --- | --- | --- |
| **● インデックス動画の記録 / ■ 記録停止** *（コンバインド・アレイのみ）* | **モニタリング** | 10 fpsのライブ・コンバインド・インデックス・コンポジットを動画として記録 — 8ビット、プレビュー解像度、LUTが焼き込まれています。プロジェクトが開かれており、ライブビューがストリーミングされている必要があります。 録画中のフレーム数と経過時間を表示します。 |
| **⦿ 生データバーストの記録 / ■ RAWバーストの停止** *（すべてのアレイ）* | **分析**| ライブ取得レートでのRAWベイヤーフレーム（未処理）に加え、フレームごとのマニフェストおよび`.daq`の測定値を、`captures/bursts/`形式で記録します。 バースト終了後、**「ビデオを作成」**ボタンが表示されます。これにより、バーストデータがオフラインで再処理され、キャリブレーション済みのビデオ（統合インデックスおよび／またはカメラごとの放射度／反射率／屈折率）と、オプションのTIFFファイルが生成されます。統合インデックスによるビデオ作成は、バーストを停止すると自動的に開始されます。 |##

「すべてキャプチャ」フローサイドバーのカメラリストで **「すべてキャプチャ」** を

<!-- SCREENSHOT-NEEDED: the sidebar during a capture — Capture All showing live "Capturing… 3/6" progress text, and (second capture) the result flash "Saved N files". -->

押します：

1. 対象となり、表示され、一時停止されていないすべてのカメラが、選択されたエクスポート形式で撮影を行います。**アレイは、1つの同期されたトリガーとして動作します**（すべてのメンバーにまたがる単一の同期グループ — [マルチカメラアレイ](arrays.md)を参照）。スタンドアロンカメラは個別に撮影を行います。
2. 非表示（目マーク）または一時停止中のカメラはスキップされます。アレイが完全にブロックされるのは、そのメンバーが*すべて*非表示または一時停止状態の場合のみです。
3. 光センサーが割り当てられている場合、対応するDAQのダウンウェル測定値は、画像データとともに`.daq`ファイルとして保存されます（RAW形式のみのキャプチャの場合でも同様です）。これにより、後でいつでも放射測定データが導出可能です。
4. ボタンには進行状況（「キャプチャ中…完了/合計」）がリアルタイムで表示され、連続/間隔モードでは **停止 (N)** となります。各キャプチャ項目には 300 秒のタイムアウトが設定されています。
5. パスが完了すると、結果フラッシュに **「N ファイルを保存しました」**または**「N ファイルを保存しました、F 件が失敗しました」** と表示されます。また、カメラがスキップされた場合は「(S 非表示/一時停止/スキップ)」も表示されます。

## キャプチャデータの保存先

キャプチャデータは、開いているプロジェクト内の `<project>/captures/` に保存されます。各エクスポートタイプは**独自のサブフォルダ**に保存されるため、多階層のキャプチャであってもタイプが混在することはありません：

```
<project>/captures/
├── raw/           capture_<ts>_SN<serial>_raw.tif
├── debayered/     capture_<ts>_SN<serial>_debayered.tif
├── radiance/      capture_<ts>_SN<serial>_radiance.tif
├── reflectance/   capture_<ts>_SN<serial>_reflectance.tif
├── preview/       capture_<ts>_SN<serial>_display.tif
├── index/         per-camera vegetation-index (LUT) render, when Index is selected
├── composite/     array foreground/background live-view composite, when produced
├── bursts/        raw-burst recordings (frames + manifest + .daq per burst)
└── *.daq          the downwelling reading matched to the capture
```

* `<ts>` はキャプチャのタイムスタンプ、`<serial>` はカメラのシリアル番号です。 スタンドアロンのキャプチャは `capture_<ts>_SN<serial>_<level>` という名前で、1 つの同期トリガーによるアレイキャプチャは `sync_<ts>_SN<serial>_<level>` という名前で、**グループ内のすべてのカメラで共通のタイムスタンプが使用されます** （カメラが単一のレベルのみを保存する場合、レベルを表す接尾辞は省略されます）。
* **知っておくべき1つの例外：** 表示レベルは `preview/` という名前のフォルダに保存されますが、ファイル名には `_display` という形式が維持されます。このレベルのみ、フォルダ名と接尾辞が異なります。
* 不明なレベルの場合は、そのレベル名と同じ名前のフォルダに保存されます。サブフォルダを作成できない場合でも、ファイルは失われることなく、キャプチャのルートディレクトリに書き込まれます。
* キャプチャ TIFF ファイルはデフォルトで可逆圧縮（DEFLATE）されており、完全なキャリブレーションおよび処理メタデータが **ファイル内の XMP 内に** 格納されています。キャプチャデータは自己記述型であり、`.daq` ファイル以外のサイドカーファイルは存在しません。

これは、`chloros-cli lattice capture` / `array-capture` が `-o` ディレクトリに書き込むレイアウトと同じであり、 [CLI リファレンス § キャプチャフォルダの構成](../reference/cli-reference.md#what-a-captures-folder-looks-like)に記述されています。

## キャプチャを再処理して校正済みプロダクトを作成する

キャプチャされた生データフレームと保存された `.daq` があれば、処理パイプラインに必要なものはすべて揃います。これが、Fastest Capture が実際の作業でも安全に使用できる理由です。

* **GUI**: キャプチャフォルダをプロジェクトに追加し（[プロジェクトへのファイルの追加](../processing-images-gui/adding-files-to-a-project.md)）、通常通り処理します。
* **CLI**: `process`を**キャプチャのルート**に指定します:

```bash
chloros-cli process "C:/ChlorosProjects/MyField/captures"
```

`process`は通常、指定したフォルダのみをインポートしますが、そのフォルダに画像がなくサブフォルダが存在する場合、自動的に階層を辿ります。そのため、各レベルのサブフォルダとルートにある`.daq`ファイルが一度に取得されます。 各キャプチャは、レベルごとに1枚の画像としてではなく、**単一の画像**としてインポートされ、他のレベルは表示可能なモードとして添付されます。

レベルサブフォルダを直接指定して命名する場合（例：`…/captures/raw/`）も機能しますが、 ただし、ルートレベルの `.daq` ファイルは取り込まれません。`raw/` から放射測定プロダクトを再導出する際は、これらを併せてコピーしてください。そうしないと、タイムスタンプの一致を照合する対象がなくなります。

{% hint style="warning" %}
**処理は常に `raw` から開始されます。**各キャプチャ内では、生データフレームがパイプラインのソースとなります。 `debayered`、`radiance`、`reflectance`、および`preview`は表示用モードとして生成されますが、パイプラインを通じて再処理されることはありません — 派生したプロダクトを再処理すると、そのピクセルにすでに焼き込まれているヴィネット、色、および放射輝度の計算が再度適用されてしまうため、Chlorosは二重処理を避けるために拒否されます。 `index/` および `composite/` のレンダリングは、一切処理されません（これらは出力であり、キャプチャではありません）。 RAWのインポートを**行わずに**保存された「captures」フォルダは通常通り表示されますが、`process`はこれをスキップし、その旨を通知します。`--input-level {raw,debayered,processed}`は、意図的にエントリポイントを強制するための「脱出ハッチ」です。 正確なスキップメッセージについては、[CLI リファレンス](../reference/cli-reference.md#what-a-captures-folder-looks-like)を参照してください。
{% endhint %}

再処理のスクリプト作成時に知っておくべき、さらに2つの挙動があります：

* プロダクトを要求したものの、**画像プロダクトを一切書き出さなかった**`chloros-cli process` 実行は、明示的に失敗し、**非ゼロの終了コードで終了**します。静かに終了して空の結果を返すような実行は決してありません。成功した実行では、プロダクト数が報告されます。（意図的にメタデータのみを生成する実行も、成功としてカウントされます。）
* 再インポートされた処理済みエクスポートは、キャプチャの生データスロットを占有することはありません。元の生データが常にパイプラインのソースとして残ります。

## CLI 相当

このページに記載されている内容はすべて、ヘッドレスで実行可能です。GUI のキャプチャモードは、`chloros-cli lattice array-capture` に直接対応しています：

| GUI | CLI |
| --- | --- |
| シングル | `chloros-cli lattice array-capture` |
| 連続 | `array-capture --continuous [--count N] [--duration S]` |
| 間隔 | `array-capture --interval S [--duration S]` |
| 最速キャプチャ | `array-capture --fastest` |
| チェックボックスの位置合わせ | `--aligned / --no-aligned` |
| エクスポートタイプのチェックボックス | `--processing LEVEL` または `--levels L1,L2,…` (デフォルトは `all`) |
| インデックス動画の記録 | `chloros-cli lattice array-record` |
| 生データバーストの記録 / 動画の生成 | `chloros-cli lattice array-burst` / `array-build-video` |

完全なフラグテーブル、スマートAE安定撮影オプション（`--smart`）、および持続レートモデルについては、[CLI リファレンス § キャプチャモード、レコーダー、およびオフライン再処理](../reference/cli-reference.md#capture-modes-recorders--offline-reprocess)に記載されています。
