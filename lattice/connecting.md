# カメラの接続

<figure><img src="../.gitbook/assets/image (37).png" alt=""><figcaption><p>何も接続されていない状態の「カメラ」タブ</p></figcaption></figure>Chlorosは、リンク上のLATTICE製カメラを自動的に検出します。検出元は、GUIの「カメラ」タブ、`chloros-cli lattice`、 またはPython SDKから検出されます。カメラのモデル文字列が下流のすべての処理を決定します: Chlorosは、カメラの`DeviceUserID`および`DeviceSerialNumber`からセンサープロファイル、バンドレイアウト、および工場出荷時のキャリブレーション情報を取得するため、**カメラごとに設定を行う必要はありません**。

接続する前に、ホストネットワークの設定（リンクローカルアドレス、ジャンボフレーム、およびアレイの場合はNICの受信バッファ設定）が完了していることを確認してください。 これらはハードウェア側の設定であり、LATTICEのマニュアル [**ネットワーク設定**](https://mapir.gitbook.io/lattice-camera/setup/network-setup) に記載されています。

## GUIからの接続

Chlorosのサイドバーで**[Cameras]**タブを開くか（バックエンドの起動が完了するとハードウェアタブが表示されます）、メインメニュー →**[Connect to Camera]**を選択してください。どちらの場合も、**[Connect Camera(s)]**ダイアログが開きます。

### [**カメラへの接続**] ダイアログ

ダイアログが開くとすぐにネットワークのスキャンが開始され（「ネットワークをスキャン中...」）、検出されたすべてのカメラが一覧表示されます。 各行には、カメラの**モデル**（例：`LATT-M3M-L41-F550`）、**シリアル番号**、および**IPアドレス**が表示されます。

* **行をクリックして選択**します（緑色でハイライト表示されます）。**複数のカメラ**を選択して一度に接続できます。Chlorosは、それらを順番に接続します。
* **「接続済み」**バッジが付いている行は、すでに接続済みであり、再選択することはできません。
* **「アレイ内」**バッジが付いている行は、現在接続されているカメラアレイに属しています。そのカメラを単独で使用するには、まずアレイの接続を解除してください。
* **接続** — 選択したカメラを接続します。複数のカメラが選択されている場合、ボタンには「接続 (3)」のように個数が表示されます。
* **再スキャン** — 検出を再度実行します。
* ****閉じる**** — ダイアログを閉じます。
* スキャンが結果なしで終了した場合、ダイアログに ****「ネットワーク上にカメラが見つかりませんでした」**** と表示されます — 以下の [トラブルシューティング](connecting.md#troubleshooting) を参照してください。

<figure><img src="../.gitbook/assets/image (38).png" alt=""><figcaption><p>「カメラの接続」ダイアログ — ここではネットワーク上にカメラが存在しない状態を示しています</p></figcaption></figure>### 初回接続：キャリブレーションパックのダウンロード

特定のカメラをマシンに**初めて**接続すると、ChlorosはGigE経由でカメラ本体からキャリブレーションパック（約3.8 MB）を取得します。 この処理が実行されている間、ダイアログには緑色の**「カメラからキャリブレーションデータをダウンロード中」**というパネルと、シリアル番号ごとの進行状況バーが表示されます。カメラ1台あたり約**70秒**かかります。このパックはホストにキャッシュされるため、同じカメラを再度接続する際にはダウンロードが完全にスキップされます（このパネルも表示されません）。

### システムの分析

ダイアログの**「システムの分析」**ボタンをクリックすると、ホストとネットワークの調査が行われ（実行中は「分析中...」と表示されます）、診断レポートが表示されます：

* **ホスト** — CPUコア数とRAM； GPU名とメモリ、または「GPU: 検出されません」。
* **ネットワークインターフェース** — 各NICの名前、リンク速度、MTU（有効な場合は「ジャンボ」タグ付き）、アップ/ダウン状態、およびUSBバス上に存在するかどうか。
* **カメラ**— シリアル番号、モデル、IPアドレス、および**各カメラが接続されているNIC**。
* **パフォーマンス** — ピクセル形式ごとのカメラごとの現在値と理想値のfps比較。理想値が現在値を上回る場合は、緑色の「潜在的な改善余地：N倍の改善が可能」という行が表示されます。
* **警告と番号付き推奨事項** — 修正すべき点がない場合は、「現在のカメラ数に対してシステムは正常です。」と表示されます。

検出やストリーミングの動作が予期しない場合はいつでも実行してください。ダイアログを閉じることなく、NIC側の問題（MTUの誤り、カメラが誤ったインターフェースに接続されている、USBアダプタの制限など）のほとんどを特定できます。

### アレイの接続

2台以上のカメラを**同期アレイ**として接続するには、代わりにアレイ接続ウィザード（**カメラアレイの接続**）を使用してください： このウィザードでは、マスター／スレーブの選択（GPIO配線プローブによって事前に入力済み）、表示モードの選択（個別タイル表示 vs. 結合タイル表示）、およびアレイ設定画面（確定前に達成可能なfpsと配線帯域幅のリアルタイム予測表示）を順を追って案内します。 ウィザードおよびアレイのワークフローについては、本マニュアルの「マルチカメラアレイ」のセクションで解説しています。 CLI における同等の手順は、[CLI リファレンス](../reference/cli-reference.md)内の「LATTICE カメラ初回接続ワークフロー」です。

## CLI および SDK からの接続

CLI および SDK にアクセスするには、有料の Chloros+ プランへの加入とログインが必要です。 これはサーバー側で強制されます（ログインしていない場合は `401 AUTH_REQUIRED`、無料プランの場合は `403 PLAN_UPGRADE_REQUIRED`）。

```bash
# List cameras on the network (vendor, model, serial, IP, MAC)
chloros-cli lattice info

# Single-camera smoke test: capture one frame (saves every applicable export type)
chloros-cli lattice capture -o output/

# Connect a synchronized array — same smart-prep flow as the GUI
chloros-cli lattice array-connect --serials 213800234,214000533
```

```python
import chloros_sdk

# Persistent live-camera session through the backend
with chloros_sdk.connect_camera("213800234") as cam:
    ...

# Array session (smart-prep: network probe, tier auto-pick, PTP, AE seeding, trigger config)
with chloros_sdk.connect_array(["213800234", "214000533"]) as array:
    ...
```

完全なシグネチャ、オプション、およびキャプチャワークフロー：[CLI リファレンス](../reference/cli-reference.md) § `chloros-cli lattice`、 [SDK リファレンス](../reference/sdk-reference.md) § `connect_camera()` / `connect_array()`。

## 接続時のキャリブレーション処理方法

すべてのLATTICEカメラは、工場出荷時のキャリブレーションパックを**カメラ本体**に搭載しており、Chlorosは、カメラが接続された際にMAPIRのクラウドも確認します：

| 状況   | Chloros が使用するもの                                                                                                                                                                                                          |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **オンライン**|**そのシリアル番号に対して公開された最新のキャリブレーション** — クラウド上のコピーがカメラ内のコピーより優先されます。したがって、MAPIRによって再キャリブレーションまたは更新されたカメラは、自動的に自身を更新します。ユーザーによる操作は不要です。 |
| **オフライン**|**カメラ内のデータ**がそのまま使用されます。完全にオフラインのワークフローは引き続き機能しますが、カメラが一度オンラインになるか（または工場出荷時の状態にリフラッシュされるまで）、新しいキャリブレーションは反映されません。                                                  |

撮影時、実際に適用された係数は**各画像の XMP メタデータに固定**されます。後日のキャリブレーション更新によって、すでに撮影済みの画像が黙って変更されることは決してありません。古い撮影データを再処理する際は、その XMP に記録された係数が使用され、その時点で最新の係数は使用されません。

## トラブルシューティング

* **&quot;ネットワーク上でカメラが見つかりません&quot;**— [ネットワーク設定](https://mapir.gitbook.io/lattice-camera/setup/network-setup) のリンクローカル設定を確認してください：ホストの NIC は静的 IP `169.254.x.x/16`、カメラは同じリンク上にあり、DHCP やゲートウェイは使用しない設定であることを確認してください。 その後、接続ダイアログの**「システムの分析」**を使用して、各カメラがどのNIC上で認識されているか（または認識されていないか）を確認してください。ケーブルの接続変更やNICの変更後は、**「再スキャン」**を行ってください。
* **以前は正常に動作していたシステムが接続できなくなった**（`FRAMES WILL DROP` / `Reduce ROI to enable` のアレイパネルのゲート） — NIC ドライバーの更新により、受信リングの設定が黙ってリセットされてしまいました。 設定を再適用するか、管理者権限のターミナルから `chloros-cli lattice network --fix` を実行してください。[ネットワーク設定](https://mapir.gitbook.io/lattice-camera/setup/network-setup)を参照してください。
* **カメラに「In Array」と表示される** — これは、接続されたアレイセッションに属していることを示しています。カメラをスタンドアロンで使用するには、アレイから切断してください。
