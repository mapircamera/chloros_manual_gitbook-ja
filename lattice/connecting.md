# カメラの接続

<figure><img src="../.gitbook/assets/image (37).png" alt=""><figcaption><p>何も接続されていない状態の「カメラ」タブ</p></figcaption></figure>

Chloros
は、GUIの「カメラ」タブ、`chloros-cli lattice`、またはPython
SDK
から、リンク上のLATTICEカメラを自動的に検出します。 カメラのモデル文字列が下流のすべての処理を制御します。Chloros
は、カメラの`DeviceUserID`および`DeviceSerialNumber`からセンサープロファイル、バンドレイアウト、工場出荷時のキャリブレーションを解決するため、**カメラごとに設定する必要は一切ありません**。

接続する前に、ホストネットワークの設定が完了していることを確認してください。具体的には、リンクローカルアドレス、ジャンボフレーム、およびアレイの場合はNICの受信バッファ設定です。 これらはハードウェア側の設定であり、LATTICEのマニュアル [**ネットワーク設定**](https://mapir.gitbook.io/lattice-camera/setup/network-setup) に記載されています。

## GUI からの接続

Chloros
のサイドバーで **Cameras**タブを開くか（バックエンドの起動が完了するとハードウェアタブが表示されます）、メインメニュー →**Connect to Camera**を選択してください。どちらの場合も**Connect Camera(s)** ダイアログが開きます。

### [**カメラへの接続**]ダイアログ

このダイアログは開いた瞬間にネットワークをスキャンし（「ネットワークをスキャン中...」）、検出されたすべてのカメラを一覧表示します。 各行には、カメラの**モデル**（例：`LATT-M3M-L41-F550`）、**シリアル番号**、および**IPアドレス**が表示されます。

* **行をクリックして選択します**（緑色でハイライト表示されます）。**複数のカメラ**を選択して一度に接続することができます。Chloros
はそれらを順番に接続します。
* **「接続済み」**のバッジが付いている行は、すでに接続済みであり、再選択することはできません。
* **「アレイ内」**のバッジが付いている行は、現在接続されているカメラアレイに属しています。 そのカメラを単独で使用するには、まずアレイから切断してください。
* **接続** — 選択したカメラを接続します。複数選択されている場合、ボタンには「接続 (3)」のように数が表示されます。
* **再スキャン** — 検出を再度実行します。
* ****閉じる**** — ダイアログを閉じます。
* スキャンが結果なしで終了した場合、ダイアログには ****「ネットワーク上でカメラが見つかりませんでした」**** と表示されます — 以下の [トラブルシューティング](connecting.md#troubleshooting) を参照してください。

### 初回接続：キャリブレーションパックのダウンロード

特定のカメラをマシンに**初めて**接続すると、Chloros
はGigE経由でカメラ本体からキャリブレーションパック（約3.8 MB）を取得します。 この処理が実行されている間、ダイアログには緑色の **「カメラからキャリブレーションデータをダウンロード中」**パネルが表示され、シリアル番号ごとの進行状況バーが表示されます。カメラ1台あたり約**70秒** かかります。カメラが6台を超える場合、進行状況の行がパネル内でスクロールします。 このパックはホストにキャッシュされるため、同じカメラを再度接続する際はダウンロードが完全にスキップされ（パネルも表示されません）。

### システムの分析

ダイアログの**「システムの分析」**ボタンをクリックすると、ホストとネットワークの診断が行われ（実行中は「分析中...」と表示されます）、診断レポートが表示されます：

* **ホスト** — CPUコア数とRAM容量；GPU名とメモリ容量、または「GPU：検出されませんでした」。
* **ネットワークインターフェース** — 各NICの名前、リンク速度、MTU（有効な場合は「ジャンボ」タグ付き）、アップ/ダウン状態、およびUSBバス上に存在するかどうか。
* **カメラ**— シリアル番号、モデル、IPアドレス、および**各カメラがどのNICに接続されているか**。
* **パフォーマンス** — ピクセル形式ごとのカメラごとの現在値と理想値のfps比較。理想値が現在値を上回る場合は、緑色の「潜在能力：N倍の改善が可能」という行が表示されます。
* **警告および番号付き推奨事項** — 修正すべき点がない場合は、「現在のカメラ数に対してシステムは正常です。」と表示されます。

検出やストリーミングの動作が予期しない場合はいつでも実行してください。ダイアログを離れることなく、NIC 側の問題（MTU の誤り、カメラが誤ったインターフェースに接続されている、USB アダプタの制限など）のほとんどを特定できます。

### アレイの接続

2台以上のカメラを**同期アレイ**として接続するには、代わりにアレイ接続ウィザード（**カメラアレイの接続**）を使用してください。このウィザードでは、マスター／スレーブの選択（同期ケーブルのプローブによって事前に入力済み — ケーブル接続されたカメラならどれでもマスターに設定可能、 また、RGB
`-FRGB`カメラはケーブル接続時に自動的に選択されます）、表示モードの選択（個別タイル表示 vs. 結合タイル表示）、およびアレイ設定画面（確定前に実現可能なfpsと回線帯域幅のライブプレビューが表示されます）を順を追って案内します。 ウィザードおよびアレイのワークフローについては、本マニュアルの「マルチカメラアレイ」のセクションで解説しています。CLI
での対応操作は、[CLI
リファレンス](../reference/cli-reference.md)に記載されている「LATTICEカメラ初回接続ワークフロー」です。

## CLI
およびSDK
からの接続

CLI
およびSDK
にアクセスするには、有料のChloros
+ティアへの加入とログインが必要です。これはサーバー側で強制されます（ログインしていない場合は`401 AUTH_REQUIRED`、無料ティアの場合は`403 PLAN_UPGRADE_REQUIRED`）。

```bash
# List cameras on the network (vendor, model, serial, IP, MAC)
chloros-cli lattice info

# Single-camera smoke test: capture one frame (saves every applicable export type)
chloros-cli lattice capture -o output/

# Connect a synchronized array — same smart-prep flow as the GUI
chloros-cli lattice array-connect --serials 213800234,214000533
```

```python
import chloros_sdk

# Persistent live-camera session through the backend
with chloros_sdk.connect_camera("213800234") as cam:
    ...

# Array session (smart-prep: network probe, tier auto-pick, PTP, AE seeding, trigger config)
with chloros_sdk.connect_array(["213800234", "214000533"]) as array:
    ...
```

完全なシグネチャ、オプション、およびキャプチャワークフロー：[CLI
リファレンス](../reference/cli-reference.md) § `chloros-cli lattice`、 [SDK
リファレンス](../reference/sdk-reference.md) § `connect_camera()` / `connect_array()`。

## 接続時のキャリブレーション処理について

すべてのLATTICEカメラは、工場出荷時のキャリブレーションパックを**カメラ本体**に搭載しており、Chloros
もカメラが接続された際にMAPIR
のクラウドを確認します：

| 状況   | Chloros
が使用するもの                                                                                                                                                                                                          |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **オンライン**|**そのシリアル番号向けに公開された最新のキャリブレーション** — クラウド上のデータがカメラ内のデータよりも優先されます。したがって、MAPIR
によって再キャリブレーションまたは更新されたカメラは自動的に更新され、ユーザーによる操作は不要です。 |
| **オフライン**|**カメラ内のキャリブレーションデータ**がそのまま使用されます。完全にオフラインのワークフローは引き続き機能しますが、カメラが一度オンラインになる（または工場出荷時の状態にリフラッシュされる）まで、新しいキャリブレーションは反映されません。                                                  |

撮影時には、実際に適用された係数が**各画像のXMPメタデータに固定**されます。後からキャリブレーションが更新されても、すでに撮影済みの画像が黙って変更されることはありません。古い画像を再処理する際は、そのXMPに記録された係数が使用され、その時点で最新の係数は使用されません。

## トラブルシューティング

* **「ネットワーク上にカメラが見つかりません&quot;**— [ネットワーク設定](https://mapir.gitbook.io/lattice-camera/setup/network-setup) のリンクローカル設定を確認してください：ホストの NIC は静的設定（`169.254.x.x/16`）、カメラは同じリンク上にあり、DHCP やゲートウェイは想定されていません。 その後、接続ダイアログの**「システムの分析」**を使用して、各カメラがどのNIC上で認識されているか（または認識されていないか）を確認してください。ケーブルの接続変更やNICの変更後は、**「再スキャン」**を行ってください。
* **以前正常に動作していたシステムが接続できなくなった**（`FRAMES WILL DROP` / `Reduce ROI to enable` のアレイパネルがゲート状態） — NIC ドライバーの更新により、受信リングの設定が黙ってリセットされてしまいました。 設定を再適用するか、管理者権限のターミナルから `chloros-cli lattice network --fix` を実行してください。[ネットワーク設定](https://mapir.gitbook.io/lattice-camera/setup/network-setup) を参照してください。
* **カメラに「In Array」と表示される** — これは、接続済みのアレイセッションに属していることを示しています。カメラをスタンドアロンで使用するには、アレイの接続を解除してください。
