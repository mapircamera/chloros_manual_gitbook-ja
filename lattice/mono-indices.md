# モノクロカメラと植生指数

## 1台のカメラ＝1バンド

**M3M**カメラは、ベイヤー型**M3C**のモノクロ版であり、単一の狭帯域干渉フィルターの背後にIMX265モノクロセンサーを搭載しています。 モデル名にはバンド名が含まれています。例えば、`M3M-<lens>-F<wavelength>`、`M3M-L87-F685` （Chlorosでは、`LATT-M3M-L87-F685`として表示されます）。 このセンサーは、ベイヤーモザイクのない**単一のグレースケールバンド**を出力します。つまり、デモザイク処理を行う必要がなく、チャンネル間のクロストークを分離する必要もなく、ホワイトバランスを設定する必要もありません。

モノクロシステムを計画する前に知っておくべき点：

* **放射輝度と反射率は、バンドごとに完全に定義されています。**これらはバンドごとの放射量マップであるため、1台のM3Mカメラは、M3Cのバンドとまったく同様に、校正済みのfloat32形式の放射量（W/m²/sr/nm）とuint16形式の反射率（`32768` = ρ 1.0）を出力します。 モノクロフレームには**アイデンティティ**センサー応答行列が含まれており、3×3アンミックスは不要であり、適用されることもありません。
* **単一のモノクロカメラでは植生指数を算出できません。** NDVI、NDRE などの指数を算出するには、少なくとも 2 つのバンドが必要です。モノクロハードウェアから指数を算出するには、複数の M3M カメラを組み合わせる必要があります — 詳細は以下を参照してください。
* M3Mカメラは**Mono12**（12ビット、通信上のピクセルあたり2バイト）をストリーミングします。これは[アレイ帯域幅の割り当て](arrays.md#bandwidth-the-rules-of-thumb)において重要です。

## Chlorosがモノクロの場合にスキップする処理 — およびその通知方法

カラーパイプラインの各ステージは、シングルバンドセンサーには単純に適用されません。 Chlorosは、エラーを返すのではなく**1行のメッセージでそれらをスキップ**し、同じセッション内のM3C（ベイヤー）カメラに対しては通常通り処理を実行します：

| ステージ | モノクロ（M3M）時の動作 | M3C時の動作 |
| --- | --- | --- |
| デモザイク／デベイヤー | スキップ — `debayered`のエクスポート結果は1チャンネルのグレースケール画像。 | 3チャンネルのデモザイク。 |
| ホワイトバランス (`lattice white-balance`) | 1行のメッセージが表示され、スキップされる。 | 正常に実行される。 |
| カラープロファイル (`lattice color-profile`) | 1行のメッセージが表示され、スキップされる。 | 正常に実行される。 |
| 彩度/コントラスト (`lattice color`) | 1行のメッセージが表示され、スキップされた。 | 正常に実行される。 |
| スペクトルクロストークの分離 | アイデンティティ（3×3行列なし）。 | カメラごとの3×3行列が適用される。 |
| 放射輝度／反射率 | **実行** — バンドごと、完全にキャリブレーション済み。 | バンドごとに実行される。 |

GUI では同様のゲート処理が適用されます。モノクロカメラの場合、カメラごとの設定ペインでは、RGB 専用の行（ホワイトバランス、ガンマ、カラープロファイル、彩度、 コントラスト、チャンネル分割）を非表示にし、ライブヒストグラムは単一の**MONO**トレースに固定されます。 スタック全体における判別基準は、モデル文字列内の`M3M`トークンであり、GUI/SDK上では`is_mono`として表示されます。

## インデックスには 2 バンド以上が必要です：アライン → スタック → インデックス

モノクロインデックスのワークフローは、常に以下の 3 つのステップで構成されます：

1. **アライン** — 異なる波長で複数のM3Mカメラを向け（例：F650「Red」とF850 「NIR」など）を異なる波長で複数台のM3Mカメラを向け、それらを[マルチカメラアレイ](arrays.md)として接続し、Chlorosにカメラ間の共登録ワープを計算させます。
2. **スタック** — 位置合わせされたフレームは 1 つのマルチバンド画像になります（各カメラが 1 つの名前付きバンドを構成します）。
3. **インデックス** — スタックのバンドに対してインデックス式を評価し、必要に応じて LUT を通じてレンダリングします。

GUI では、この一連の処理全体が **Combined Cameras**アレイ表示モードとなります。ライブ合成画像はすでに対照されており、アレイのインデックス計算機（下図）がレンダリングする式を定義します。キャプチャされたエクスポートデータは、**Aligned** キャプチャオプションを使用することで、同じ位置合わせにワープさせることができます。

## インデックス計算機

インデックス計算機は、ライブビューおよびカメラごとのインデックスエクスポートで使用されるインデックス式を作成します。これは 1 つの共有サーフェスであり、「カメラ」タブのサイドバーにある 2 箇所から開くことができます：

* **カメラごと**— ライブプレビュー →**インデックス** ギア（RGN/OCN/NGB ベイヤーカメラのみ； 単体のモノクロカメラにはインデックス制御がありません。1つのバンドだけではインデックスを作成できないためです）。
* **アレイ単位**— アレイ設定 → ライブプレビュー →**インデックス**の歯車アイコン。これはモノクロカメラ用のパスです。バンドリストは**構成カメラすべて**にまたがっているため、モノクロペアはここで2つのバンドを反映します。

そのコントロールは、上から順に以下の通りです：

* **バンドチップ**（「バンド — クリックして式に追加」） — 利用可能なバンドごとに1つのボタンがあり、色名＋波長（nm）と表示されます（色名が重複する場合は、例えば「Color 850」のように区別されます）。 クリックすると、カーソル位置にバンドトークンが挿入されます。バンドごとの放射輝度を出力できないカメラ（RGB/FRGB）からのバンドは除外されます。
* **演算子および関数ボタン** — `+ - * / ( ) ^ ,` および `abs() sqrt() log() log10() exp() min() max() pow()`。
* **式テキストエリア** — 自由に式を入力可能。プレースホルダーには、従来の NDVI 形式の `(NIR - Red) / (NIR + Red)` が表示される。その上にある読み取り専用のトークン化プレビューでは、バンドチップ、数値、およびフラグが未知のトークンとして表示される。
* **有効性バナー**— 灰色「空 — インデックスは適用されません」； 緑色の「有効な式」；特定の構文エラー（未知のバンド、複数のカメラによって検出された曖昧なバンド、括弧の欠落など）がある場合は赤色；または、式が有効であるが**定数**である場合（例：`X/X`、 または分母が `+` であるべきところを `−` と入力した NDVI など） — 定数の場合、フレーム全体が単一の色にマッピングされます。
* 適用された式に問題がないものの、**ライブフレームが均一**（フラットまたは彩度の高いシーン）である場合、別の琥珀色の警告が表示されます。ヒストグラムの崩壊が自動的に検出されます。
* **LUTを適用**（デフォルトはオン、オフ＝グレースケールストレッチ）、**レベル**2/3/5/7ストップ（デフォルトは7ストップ）、およびグラデーションバーの両側に配置された**最小／最大**入力。 Minのデフォルト値は**

0.2**です。これにより、カラーランプが植生に関連する範囲にズームインされ、それ以下の値はグレースケールとして通過します。インデックスの全範囲を表示するには、Minを−1に設定してください（**リセット**ボタンを押すと−1…+1に戻ります）。Maxのデフォルト値は1です。
* インデックス分布の**ライブヒストグラム** — 平方根スケールで表示されたバー、琥珀色のp2/p98パーセンタイル線、白の中央値線、および範囲外の末端値の表示（「◀ N% &lt; lo」／「hi &lt; N% ▶&quot;) が表示され、1 %を超えるとアンバー色に変わり、Min/Maxの範囲を広げる合図となります。
* **適用**をクリックすると、式がライブストリームに反映されます。LUTの調整は、「適用」をクリックしなくてもリアルタイムで反映されます。式は意図的に**セッション限定** となっており、セッション間で保持されることはありません。

## CLI パス

同じ「アライン → スタック → インデックス」のチェーンで、スクリプトによるエンドツーエンドの制御が可能です：

```bash
chloros-cli lattice array-connect --serials SN_RED,SN_NIR
chloros-cli lattice index --live --profile align.json \
  --preset NDVI --channel red=Red_660 --channel nir=NIR_850 \
  --save-multiband -o output/
```

`--channel`は、プリセットのシンボルをスタックのバンド名にマッピングします。以下の2つのルールに従うことで、実行失敗を防ぐことができます：

* **シンボルは大文字と小文字が区別されます**。プリセットのチャンネル名と完全に一致させる必要があります。プリセットでは小文字が使用されています（NDVIの場合は `red`、`nir`；`--list-presets`を確認してください）。 `--channel red=Red_660`は正常に動作しますが、`--channel RED=660`は「`channel_map missing entries`」というエラーで失敗します。
* バンド側では、アラインされたスタック内のバンド名を指定する必要があります（`lattice align-info --profile align.json` に一覧があります）。オフラインモードでは、0 ベースのバンドインデックス（例：`--channel red=0 --channel nir=1`）も受け入れられます。

`lattice index`は、保存済みのアライン済みマルチバンドTIFFに対しても、完全にオフラインで実行されます：

```bash
chloros-cli lattice index --input aligned.tif --preset NDVI \
  --output ndvi.tif --colorize --gradient RdYlGn
```

### インデックスのプリセット

`lattice index --preset`（および、同じエンジンを使用する「画像」タブの [インデックス/LUT サンドボックス](../image-viewer-gui/index-lut-sandbox.md)）には、以下の **22 種類のプリセット** が含まれています：

`NDVI, GNDVI, BNDVI, NDRE, ENDVI, SAVI, OSAVI, MSAVI, EVI, EVI2, CVI, MSR, TDVI, LAI, GLI, NGRDI, VARI, TGI, EXG, CIRE, CIGREEN, NDWI`

各プリセットの計算式とチャンネル記号については `chloros-cli lattice index --list-presets` を実行し、利用可能なカラーグラデーションについては `--list-gradients` を実行してください。カスタム計算式では、インデックス計算機と同じ構文で `--formula EXPR` を使用します。 このプリセットリストは LATTICE インデックスエンジン固有のものである点に注意してください。インポートされた画像の「プロジェクト設定」にある処理ドロップダウンメニューには、別のリストが表示されます（[マルチスペクトルインデックス式](../project-settings/multispectral-index-formulas.md)を参照）。

完全なフラグセット（`--output-format`、`--vmin/--vmax/--percentile`、`--bg-mode`、`--live` のアライメント・ワープノブ、 その他）については、[CLI リファレンス § インデックス / 植生数学](../reference/cli-reference.md#index--vegetation-maths)に記述されています。 SDKに相当する機能は、[SDK リファレンス](../reference/sdk-reference.md)に記載されています。

## モノ配列からのインデックス製品のキャプチャ

配列が接続され、インデックス式が適用されている状態で、`array-capture`（またはGUIの**すべてキャプチャ**）を実行すると、カメラごとのエクスポートレベル *および* インデックスレンダリングが保存されます — `--index`/`--no-index`はCLI上でこの機能を切り替え、キャプチャ時にはデフォルトで適用可能なすべてのレベルが含まれます。 各キャプチャグループに対するモノカメラの寄与は、RAW/デベイヤー処理済み（グレースケール）/放射輝度/反射率レベルでのその1つのバンドに加え、アレイが結合モードで動作している場合は、共有された結合インデックス合成画像となります。 [マルチカメラアレイ § キャプチャ](arrays.md#capturing-monitoring-vs-analysis)を参照してください。
