# モノクロカメラと植生指数

## 1台のカメラ＝1バンド

**M3M**カメラは、ベイヤー型**M3C**のモノクロ版であり、単一の狭帯域干渉フィルターの背後にIMX265モノクロセンサーを搭載しています。 モデル名にはバンド名が含まれています — `M3M-<lens>-F<wavelength>`、例えば `M3M-L87-F685`（Chloros

では `LATT-M3M-L87-F685` と表示されます）。 このセンサーは、ベイヤーモザイクのない**単一のグレースケールバンド**を出力します。つまり、デモザイク処理を行う必要がなく、チャンネル間のクロストークを分離する必要もなく、ホワイトバランスを設定する必要もありません。

モノクロシステムを計画する前に知っておくべき点：

* **放射輝度と反射率は、バンドごとに完全に定義されています。**これらはバンドごとの放射量マップであるため、1台のM3Mカメラは、M3Cのバンドとまったく同様に、校正済みのfloat32形式の放射量（W/m²/sr/nm）およびuint16形式の反射率（`32768` = ρ 1.0）を出力します。 モノクロフレームには**恒等**センサー応答行列が含まれており、3×3アンミックスは不要であり、適用されることもありません。
* **単一のモノクロカメラでは植生指数を算出できません。** NDVI

、NDRE

などの指数を算出するには、少なくとも2つのバンドが必要です。モノクロハードウェアから指数を算出するには、複数のM3Mカメラを組み合わせる必要があります — 詳細は以下を参照してください。
* M3Mカメラは**Mono12**をストリーミングします （12ビット：通信上のデータは2バイト/ピクセル、またはアレイが[パックされた12ビット転送](arrays.md#packed-12-bit-transport)を使用する場合は1.5バイト/ピクセル）をストリーミングします。これは[アレイの帯域幅の割り当て](arrays.md#bandwidth-how-many-cameras-fit)において重要な要素となります。

## Chloros

がモノクロ処理でスキップする処理 — およびその通知方法

カラーパイプラインの各段階は、シングルバンドセンサーには単純に適用されません。 Chloros

は、エラーを返すのではなく**1行のメッセージでそれらをスキップ**しますが、同じセッション内のM3C（ベイヤー）カメラに対しては通常通り実行します：

| ステージ | モノクロ（M3M）時の動作 | M3C時の動作 |
| --- | --- | --- |
| デモザイク／デベイヤー | スキップ — `debayered`のエクスポート結果は1チャンネルのグレースケール画像です。 | 3チャンネルのデモザイク。 |
| ホワイトバランス (`lattice white-balance`) | 1行のメッセージが表示され、スキップされる。 | 正常に実行される。 |
| カラープロファイル (`lattice color-profile`) | 1行のメッセージが表示され、スキップされる。 | 正常に実行される。 |
| 彩度/コントラスト (`lattice color`) | 1行のメッセージを表示してスキップ。 | 正常に実行。 |
| スペクトルクロストークの分離 | アイデンティティ（3×3行列なし）。 | カメラごとに3×3行列が適用される。 |
| 放射輝度／反射率 | **実行** — バンドごと、完全にキャリブレーション済み。 | バンドごとに実行される。 |

GUIでも同様のゲート処理が適用されます。モノクロカメラの場合、カメラごとの設定ペインではRGB

専用の行（ホワイトバランス、ガンマ、カラープロファイル、彩度、コントラスト、チャンネル分割）が非表示になり、ライブヒストグラムは単一の**MONO**トレースに固定されます。 スタック全体における識別子は、モデル文字列内の `M3M` トークンであり、GUI/SDK

では `is_mono` として表示されます。

## インデックスには 2 バンド以上が必要です：アライン → スタック → インデックス

モノクロインデックスのワークフローは、常に以下の3つのステップで構成されます：

1. **アライン** — 異なる波長に対応する複数のM3Mカメラ（例：F650「Red

」とF850「NIR

」）を向け、それらを[マルチカメラアレイ](arrays.md)として接続し、Chloros

にカメラ間の位置合わせワープを計算させます。
2. **スタック** — アラインされたフレームは1つのマルチバンド画像になります（各カメラが1つの名前付きバンドを構成します）。
3. **インデックス** — スタックの各バンドに対してインデックス式を評価し、必要に応じてLUTを介してレンダリングします。

GUI上では、この一連の処理全体が**Combined Cameras**アレイ表示モードとなります。ライブ合成画像はすでにアライメント済みであり、アレイのインデックス計算機（下図）がレンダリングに用いる式を定義します。**Aligned** キャプチャオプションを使用すると、エクスポートされたキャプチャを同じ位置合わせにワープさせることができます。

## インデックス計算機

インデックス計算機は、ライブビューおよびカメラごとのインデックスエクスポートで使用されるインデックス式を作成します。これは 1 つの共有画面であり、「Cameras」タブのサイドバーにある 2 箇所から開くことができます：

* **カメラごと**— ライブプレビュー →**インデックス** ギア（RGN

/OCN

/NGB

ベイヤーカメラのみ。単一のモノクロカメラにはインデックス制御がありません。1つのバンドではインデックスを作成できないためです）。
* **アレイ単位**— アレイ設定 → ライブプレビュー →**インデックス**の歯車アイコン。これはモノクロカメラ用のパスです。バンドリストは**構成カメラすべて**にまたがっているため、モノクロペアの場合はここで2つのバンドが反映されます。

コントロールは上から順に以下の通りです：

* **バンドチップ**（「Bands — クリックして式に追加」） — 利用可能なバンドごとに1つのボタンがあり、色名＋波長（nm）と表示されます（色名が重複する場合は、例えば「Color 850」のように区別されます）。クリックすると、カーソル位置にバンドトークンが挿入されます。 バンドごとの放射輝度を出力できないカメラ（RGB

/FRGB）のバンドは除外されます。
* **演算子および関数ボタン** — `+ - * / ( ) ^ ,` および `abs() sqrt() log() log10() exp() min() max() pow()`。
* **式入力エリア** — 自由に式を入力可能。プレースホルダーには、従来のNDVI

形式である`(NIR - Red) / (NIR + Red)`が表示されます。その上にある読み取り専用のトークン化されたプレビューでは、バンドチップ、数値、およびフラグが未知のトークンとして表示されます。
* **有効性バナー**— 灰色「空 — インデックスは適用されません」；緑色「有効な式」；赤色で具体的な構文解析エラー（未知のバンド、複数のカメラによって露呈された曖昧なバンド、括弧の欠落など）；または、式は有効だが**定数** （例：`X/X`、または `+` の代わりに `−` と入力された NDVI

の分母） — 定数はフレーム全体を単一の色にマッピングします。
* 適用された式に問題がないものの、**ライブフレームが均一**（フラットまたは飽和したシーン）である場合、別の黄色い警告が表示されます。これは、ヒストグラムの崩壊が自動的に検出されたことを示しています。
* **LUTを適用**（デフォルトはオン、オフ＝グレースケールストレッチ）、**レベル**2/3/5/7ストップ（デフォルトは7ストップ）、およびグラデーションバーの両側に配置された**最小／最大**入力。 Minのデフォルト値は**

0.2**です。これにより、カラーランプが植生に関連する範囲にズームインされ、それ以下の値はグレースケールとして透過されます。インデックスの全範囲を表示するには、Minを−1に設定してください（**リセット**ボタンを押すと−1…+1に復元されます）。Maxのデフォルト値は1です。
* インデックス分布の **ライブヒストグラム** — 平方根スケールで表示されたバー、琥珀色の p2/p98 パーセンタイル線、白の中央値線、および範囲外の尾部表示（「◀ N% &lt; lo」/「hi &lt; N% ▶」）が表示され、1 %を超えるとアンバー色に変わり、Min/Maxの範囲を広げる合図となります。
* **適用**をクリックすると、式がライブストリームに反映されます。LUT の調整は、**適用** をクリックしなくてもリアルタイムで反映されます。プロジェクトが開かれている場合、式と LUT の設定はプロジェクトとともに保存され、プロジェクトを再開すると復元されます。プロジェクトがない場合は、セッション中のみ有効です。

## CLI

パス

「アライン → スタック → インデックス」という同じチェーンを、スクリプトでエンドツーエンドに制御可能：

```bash
chloros-cli lattice align-calibrate --serials SN_RED,SN_NIR --save align.json
chloros-cli lattice index --live --profile align.json \
  --preset NDVI --channel red=Red_660 --channel nir=NIR_850 \
  --save-multiband -o output/
```

`align-calibrate`は、カメラを保持する接続済み配列を使用するか、1回の実行のために自らカメラを開きます。 `index --live`は常に自身でカメラを開き（[一時配列](../reference/cli-reference.md#multi-camera-transient-sessions)）、`--serials`を持たない：ネットワーク上のすべてのカメラを開く。 したがって、Chloros

が保持しているすべてのカメラを、それ以前に解放してください — GUI、`cam-connect`、`array-connect` (`chloros-cli lattice array-disconnect --all`)： 保持中のカメラを2度開くと、その保持者のストリームが停止したり、バックエンドがクラッシュしたりする可能性があります。フレームを送信しないカメラがあると、実行は失敗となり、スタックやインデックスは書き込まれません。

`--channel`は、プリセットのシンボルをスタックのバンド名にマッピングします。 以下の2つのルールに従うことで、実行の失敗を防ぐことができます：

* **シンボルは大文字と小文字が区別されます**。また、プリセットのチャンネル名と完全に一致する必要があります。プリセットでは小文字が使用されます（NDVI

用は `red`、`nir`； `--list-presets`を参照）。`--channel red=Red_660`は正常に動作しますが、`--channel RED=660`は「`channel_map missing entries`」エラーで失敗します。
* バンド側には、アラインメント済みのスタック内のバンド名を指定する必要があります（`lattice align-info --profile align.json`に一覧があります）。オフラインモードでは、0を起点とするバンドインデックス（例：`--channel red=0 --channel nir=1`）も使用可能です。

`lattice index`は、保存済みのアライン済みマルチバンドTIFF

ファイルに対してもオフラインで実行可能です。 すべての形式はバックエンド上で実行されるため、バックエンドが稼働しており、有料のChloros

+ティアにログインしている必要があります。相対パス形式の`--input`や`--output`は、コマンドを実行したフォルダを基準に解決されます：

```bash
chloros-cli lattice index --input aligned.tif --preset NDVI \
  --output ndvi.tif --colorize --gradient RdYlGn
```

### インデックスプリセット

`lattice index --preset`（および、同じエンジンを使用する「画像」タブの [インデックス/LUT サンドボックス](../image-viewer-gui/index-lut-sandbox.md)）には、以下の **22 種類のプリセット** が含まれています：

`NDVI, GNDVI, BNDVI, NDRE, ENDVI, SAVI, OSAVI, MSAVI, EVI, EVI2, CVI, MSR, TDVI, LAI, GLI, NGRDI, VARI, TGI, EXG, CIRE, CIGREEN, NDWI`

各プリセットの計算式やチャンネル記号については `chloros-cli lattice index --list-presets` を実行し、利用可能なカラーグラデーションについては `--list-gradients` を実行してください。カスタム計算式では、インデックス計算機と同じ構文で `--formula EXPR` を使用します。 このプリセットリストは LATTICE インデックスエンジン固有のものであることに注意してください。インポートされた画像の「プロジェクト設定」にある「処理」ドロップダウンメニューには、別のリストが表示されます（[マルチスペクトルインデックス式](../project-settings/multispectral-index-formulas.md)を参照）。

完全なフラグセット（`--output-format`、`--vmin/--vmax/--percentile`、 `--bg-mode`、`--live`用のアライメント・ワープノブなど）については、[CLI

リファレンス § インデックス／植生計算](../reference/cli-reference.md#index--vegetation-maths)に記載されています。 SDK

における対応機能は、[SDK

リファレンス](../reference/sdk-reference.md)に記載されています。

## モノクロ配列からのインデックス製品の取得

配列が接続され、インデックス式が適用されている状態で、`array-capture`（またはGUIの**すべてキャプチャ**）を使用すると、カメラごとのエクスポートレベル *および* インデックスレンダリングが保存されます。`--index`/`--no-index`はCLI

でこれを切り替え、デフォルトでは適用可能なすべてのレベルを含めてキャプチャされます。 各キャプチャグループに対するモノカメラの寄与は、RAW/デベイヤー処理済み（グレースケール）/放射輝度/反射率レベルにおけるその1つのバンドに加え、アレイがコンバインドモードで動作している場合は共有のコンバインドインデックス合成画像となります。 [マルチカメラアレイ § キャプチャ](arrays.md#capturing-monitoring-vs-analysis)を参照してください。
