# プロジェクトへのファイルの追加

Chlorosでプロジェクトを作成または開いたら、次のステップとして、マルチスペクトル画像を追加して処理を開始します。「ファイルブラウザ」<img src="../.gitbook/assets/icon_file-browser.JPG" alt="" data-size="line">タブを使用すると、画像のインポートやデータセットの管理が簡単に行えます。

## ファイルブラウザへのアクセス

1. Chlorosでプロジェクトを開くか、新規作成します
2. 左サイドバーの**「ファイルブラウザ」**<img src="../.gitbook/assets/icon_file-browser.JPG" alt="" data-size="line">アイコンをクリックします
3. ファイルブラウザパネルに、プロジェクトのファイル一覧が表示されます

{% hint style="info" %}
**対応ファイル形式**：

* **Survey3W / Survey3N**：RAW+JPGペアおよびJPG画像 （RAW+JPGを推奨）
* **LATTICE**: `.tif` / `.tiff` キャプチャ — Chlorosのカメラ制御またはLATTICEハブによって記録されたもの
* **光センサーデータ**: `.daq` 記録データ（DAQ-U/M/E）および DAQ-M `.csv` ダウンウェルログ — 反射率校正を行うために画像データと共にインポートされる
{% endhint %}

***

## プロジェクトへの画像の追加

プロジェクトに画像を追加するには、主に 2 つの方法があります。

### 方法 1: ファイルの追加

このオプションを使用して、個別の画像ファイルまたは少数のファイルを選択してインポートします。

1. ファイルブラウザパネルの上部にある **「ファイルを追加」** <img src="../.gitbook/assets/image (3).png" alt="" data-size="line"> ボタンをクリックします
2. 画像が格納されているフォルダに移動します
3. 1つ以上の画像ファイルを選択します（**Ctrl** キーを押しながら選択すると、複数のファイルを選択できます）
4. **「開く」** をクリックして、選択したファイルをインポートします

### 方法 2: フォルダの追加

このオプションを使用すると、フォルダ内のすべての画像を一度にインポートできます。1つのダイアログで**複数のフォルダ**を選択できます。

1. ファイルブラウザパネルの上部にある **「フォルダを追加」** <img src="../.gitbook/assets/image (1) (1).png" alt="" data-size="line"> ボタンをクリックします
2. キャプチャセッションの画像が含まれているフォルダに移動して選択します
3. **「フォルダを選択」** をクリックして、サポートされているすべての画像をインポートします

{% hint style="info" %}
**読み込みに失敗したファイルは報告されます。** フォルダ内に、Chlorosが認識しているものの読み込みできないファイルが含まれている場合、警告が表示されます。画像がグリッドから黙って消えてしまうことはありません。
{% endhint %}

## LATTICE キャプチャフォルダのインポート

LATTICE のキャプチャデータは、**エクスポートレベルごとに 1 つのサブフォルダ**として保存されます。例えば、`raw/`、`debayered/`、 `radiance/`、`reflectance/`、`preview/` — ルートディレクトリには、これに対応するダウンウェルファイル `.daq` が格納されています：

```
output/
├── raw/           capture_<timestamp>_SN<serial>_raw.tif
├── debayered/     capture_<timestamp>_SN<serial>_debayered.tif
├── preview/       capture_<timestamp>_SN<serial>_display.tif
└── *.daq          the downwelling reading matched to the capture
```

**「フォルダを追加」でキャプチャのルートディレクトリを指定**（上記の`output/`）。 選択したフォルダ自体には画像が含まれていないが、サブフォルダがある場合、Chlorosは自動的にそれらのサブフォルダを辿ります。サブフォルダの階層およびルートにある `.daq` が、一度にすべて取り込まれます。

**キャプチャのインポート方法：**

* 各キャプチャは、キャプチャごとにグループ化された**単一の画像**としてインポートされます（レベルごとに1つのエントリになるわけではありません）。同じキャプチャの他のレベルは、その1つの画像の表示モードとして表示されます。
* **処理は常に生データフレームから開始されます。** 他のレベルも表示可能ですが、パイプラインに送られるのは `raw` のみです。すでに処理済みの成果物を再処理すると補正が二重に適用されてしまうため、Chloros はこれを拒否します。 再インポートされたエクスポートデータは、キャプチャの生データスロットを占有することはできません。
* 生データのインポートを**行わずに**保存されたキャプチャフォルダは通常通り表示されますが、処理ではスキップされ、ログにその旨が記録されます。 （CLIフラグ `--input-level` を使用すると、このケースのエントリポイントを強制的に指定できます — [CLIリファレンス](../reference/cli-reference.md#what-a-captures-folder-looks-like)を参照してください。）
* バージョン 1.3.0 以降、キャプチャフォルダには `clamp_masks/` フォルダを含めることもできます（放射輝度および反射率レベル用のピクセル単位のマスク — [出力画像形式](../output-image-formats.md#clamp-masks)を参照）。 マスクはシーンの画像ではなく、Chlorosはインポート時に、その場所にかかわらずマスクをスキップします。

**LATTICEハブセッション**も同様の方法でインポートします： ハブからコピーしたセッションフォルダ（`raw/` および `previews/` が含まれています）を「フォルダの追加」で指定し、DAQ-M の `.csv` ダウンウェルログも併せて指定します。 お使いのマシンにカメラやDAQのキャリブレーションデータがまだキャッシュされていない場合、Chlorosはインポート時にシリアル番号に基づいて自動的に取得します（初回のみインターネット接続が必要です）。***

## ファイルブラウザの表について

画像がインポートされると、以下の列からなるテーブルに表示されます：

### ファイル名

* カメラからの元のファイル名
* カメラの命名規則を維持します（例：IMG\_0001.RAW または capture\_20260816\_101500\_SN213800234\_raw.tif）

### タイムスタンプ

* 画像が撮影された日時
* 画像のEXIFメタデータから抽出
* 光センサーのマッチング、PPK同期、およびキャリブレーションターゲットのスケジューリングに使用

### カメラモデル

* カメラおよびフィルター構成を自動的に検出
* Survey3の例：Survey3W_RGN、Survey3N_OCN、Survey3W_RGB
* LATTICEの例：LATT-M3M-L41-F550、LATT-M3C-L87-FRGN
* 適切な処理プロファイルを適用するために使用されます

### ターゲット列（チェックボックス）

* キャリブレーションターゲットを含む画像には、このチェックボックスをオンにしてください
* 少なくとも1つの画像にチェックが入っている場合、ターゲットの検索は**チェックされた画像のみ**に対して行われます
* 詳細については、[ターゲット画像の選択](choosing-target-images.md)を参照してください

### 画像メタデータの表示

テーブルの上部右隅にあるトグルボタンをクリックすると、画像グリッド領域に選択した画像のメタデータが表示されます。

## プロジェクト内の光センサーファイル

* `.daq` および `.csv` ファイルはファイルブラウザのリストに表示されますが、クリック可能な画像ではありません。これらは、反射率キャリブレーション用の下向き放射照度を提供するものです。
* インポートされたすべての `.daq`/`.csv` ファイルは、**プロジェクト設定 → DAQ 光センサー** に一覧表示され、そこで各ファイルに適用されているディフューザーキャップ補正を確認できます。 [プロジェクト設定の調整](adjusting-project-settings.md)を参照してください。
* **光センサー**タブで作成した記録は、開いているプロジェクトに自動的に追加されます。手動でのインポートは不要です。***

## プロジェクト内のファイルの管理

### ファイルの削除

プロジェクトから不要な画像を削除するには：

1. ファイルブラウザのテーブルで1つ以上の画像を選択します
2. **「選択した項目を削除」**<img src="../.gitbook/assets/image (2) (1).png" alt="" data-size="line">ボタンをクリックします
3. 削除を確認します（ファイルはディスクから削除されず、プロジェクトから削除されるだけです）

### 並べ替えとフィルタリング

* **列ごとの並べ替え**：任意の列ヘッダーをクリックして画像を並べ替えます
* **タイムスタンプによる並べ替え**：撮影順に画像を整理するのに便利です
* **カメラモデルによるフィルタリング**：複数のカメラを使用している場合、カメラの種類ごとに画像をグループ化します***

## 画像のプレビュー

### 画像の全画面表示

ファイルブラウザ内の任意の画像サムネイルをクリックすると、メインのプレビュー領域に表示されます：

1. 画像が中央のプレビューパネルに表示されます
2. ズームコントロールを使用して、画像の詳細を確認します
3. 矢印キーを使用して画像間を移動します

### クイックナビゲーション

* **前の画像**：左矢印をクリックするか、← キーを押します
* **次の画像**：右矢印をクリックするか、→ キーを押します
* **拡大／縮小**：マウスホイールまたはズームボタンを使用します
* **パン**：拡大表示中に画像上でクリックしてドラッグします***

## 重複ファイルの処理

Chlorosは重複ファイルを自動的に検出し、無視します：

* ファイル名が同一のファイルはスキップされます
* 誤って二重に処理されるのを防ぎます
* 重複が検出されると警告メッセージが表示されます

{% hint style="warning" %}
**重要**：インポート前に元の画像ファイルの名前を変更したり、編集したりしないでください。Chlorosは、適切な処理を行うために元のファイル名とメタデータに依存しています。
{% endhint %}

***

## 複数のカメラが混在するデータセット

プロジェクトに複数のMAPIRカメラからの画像が含まれている場合：

1. Chlorosは各カメラモデル（Survey3、LATTICE、またはそれらの組み合わせ）を自動的に検出します
2. 各カメラタイプは、それぞれに適したキャリブレーションプロファイルを使用して処理されます
3. ファイルブラウザの「カメラモデル」列にカメラモデルが表示されます
4. 処理時には、各カメラごとに個別の出力フォルダツリーが作成されます

**使用例**：Survey3W RGN + Survey3N OCNのデュアルカメラ構成、またはRGBマスターと複数の狭帯域モジュールからなるLATTICEアレイ***

## ベストプラクティス

### インポート前の整理

* キャリブレーションターゲット画像は、測量画像と同じフォルダに保存してください
* 各撮影セッションの `.daq` / `.csv` 光センサーファイルを、そのセッションの画像データと一緒に保管してください
* カメラ／SDカード／ハブからの元のフォルダ構造を維持してください
* 異なるセッションのデータセットを1つのプロジェクトに混在させない

### ファイル名の付け方

* カメラの元のファイル名（IMG\_0001.RAW、capture\_...など）を保持する
* インポート前にファイル名を変更しない
* 元のファイル名には重要なメタデータが含まれている

### キャリブレーションターゲット画像

* セッションごとに必ず1～2枚のキャリブレーションターゲット画像を含めること（Survey3の場合。LATTICEの場合はDAQ記録で代用可能 — [ターゲット画像の選択](choosing-target-images.md)を参照）
* 撮影セッションの前後にキャリブレーションターゲット画像を撮影してください
* ターゲット画像は、撮影エリアと同じ照明条件下に配置してください
* 「Target」チェックボックスを使用してターゲット画像にマークを付けてください

## よくある問題と解決策

### インポート後に画像が表示されない

**考えられる原因：**

* ファイル形式がサポートされていない（このページ上部の「サポートされている形式」リストを参照）
* MAPIR製以外のカメラで撮影された画像である（[サポートされているカメラ](../supported-cameras.md)を参照）
* ファイルの破損、またはSDカードからの転送が不完全である

**解決策**：ファイル形式とカメラモデルの互換性を確認し、読み込みに失敗した具体的なファイルについて、ファイル読み込み時の警告メッセージを確認してください

### カメラモデルが検出されない

**考えられる原因：**

* EXIFメタデータが変更されている
* 外部ソフトウェアで画像が編集されている
* ファイルの転送が不完全である

**解決策**：カメラまたはSDカードから、変更されていない元のファイルを再度インポートしてください

### タイムスタンプの欠落

**考えられる原因：**

* カメラの時計が正しく設定されていない
* 外部ソフトウェアによってEXIFデータが削除された

**解決策**：撮影時のカメラの時刻設定が正しかったことを確認してください

### プロジェクトを再開した際にファイルが欠落していると報告される

プロジェクトを最後に開いてからソースファイルが移動または削除された場合、Chlorosは空白のグリッドを表示するのではなく、**どの**ファイルが欠落しているかを通知します。 プロジェクトフォルダ自体が移動された場合、Chlorosはソースパスを`project.json`が現在あるフォルダに再設定し、バックアップ（`project.json.before-relink-<date>-<time>`）を保持します。 それでもファイルが見つからない場合、**「ソースファイルが見つかりません」**ウィンドウが表示され、**「参照」**で新しい場所を指定した後、「新規プロジェクト」または「プロジェクトの削除」を選択できます。CLIからは `chloros-cli project open PATH --relink FOLDER` を、SDKからは `open_project(path, relink=...)` を使用してください。***

## 次の手順

ファイルのインポートが完了したら：

1. **ファイル一覧の確認** - すべての画像が正しく読み込まれていることを確認してください
2. **カメラモデルの確認** - カメラが正しく検出されていることを確認してください
3. **対象画像の指定** - [対象画像の選択](choosing-target-images.md)を参照
4. **設定の調整** - [プロジェクト設定](adjusting-project-settings.md)で処理オプションを構成
5. **処理を開始** - [処理の開始](starting-the-processing.md)を参照してください

プロジェクトの設定に関する詳細については、[プロジェクト設定の調整](adjusting-project-settings.md)を参照してください。
