# プロジェクト設定の調整

画像の処理を行う前に、ワークフローの要件に合わせてプロジェクト設定を構成することが重要です。「プロジェクト設定」<img src="../.gitbook/assets/icon_project-settings.JPG" alt="" data-size="line"> パネルでは、キャリブレーション、処理オプション、マルチスペクトル指数、およびエクスポート形式を包括的に制御できます。

## プロジェクト設定へのアクセス

1. Chlorosでプロジェクトを開きます
2. 左サイドバーの**プロジェクト設定** <img src="../.gitbook/assets/icon_project-settings.JPG" alt="" data-size="line"> アイコンをクリックします
3. プロジェクト設定パネルに、すべての設定オプションが表示されます

**設定はプロジェクトとともに自動的に保存されます**。プロジェクトを再度開くと、すべての設定が復元されます。
{% endhint %}

## 一般的なワークフローのクイックセットアップ

### デフォルト設定（ほとんどのユーザーに推奨）

デフォルト設定は、一般的な Survey3 および LATTICE ワークフローで問題なく機能します：

* ✅ **ヴィネット補正**：有効
* ✅ **反射率キャリブレーション／ホワイトバランス**：有効（MAPIRターゲットおよび／またはDAQ光センサーデータを使用）
* ✅ **デベイヤー方式**：標準（高速、中程度の画質）
* ✅ **エクスポート形式**：TIFF（16ビット）
* ✅ **すべてのエクスポート出力**：有効（LATTICEは、デベイヤー処理済みデータ、プレビュー、放射輝度、反射率へのファンアウトを自動的にキャプチャします）

画像をインポートするだけで、これらのデフォルト設定で処理を開始できます。

***

## プロジェクト設定の概要

「プロジェクト設定」パネルは、以下のセクションで構成されています。プロジェクトに関連するファイルが含まれている場合、**DAQ 光センサー**および**アレイ位置合わせ** という 2 つのセクションが自動的に表示されます。詳細なドキュメントについては、[プロジェクト設定](../project-settings/project-settings.md) を参照してください。

### 表示

* **画像サムネイルの解像度**：画像グリッドのサムネイルの解像度。オプション：**デフォルト (512 px)**、**1024 px**、**2048 px**、**フル解像度**。 表示専用 — 処理には一切影響しません。値が大きいほど、ズームした際に鮮明に見えますが、読み込みに時間がかかります。

### ターゲット検出

Chloros が画像内のキャリブレーションターゲットをどのように識別するかを制御します。

**主な設定：*** **最小キャリブレーションサンプル領域 (px)**：ターゲット検出のサイズ閾値（デフォルト：**25**、範囲 0～10000）
* **最小ターゲットクラスタリング (0～100)**： ターゲット領域をグループ化する際の類似性の閾値（デフォルト：**60**）**調整すべき場合：**

* 誤検出が発生する場合は、サンプル領域を拡大してください
* ターゲットが検出されない場合は、サンプル領域を縮小してください
* ターゲットが複数の検出に分割されている場合は、クラスタリングを調整してください

{% hint style="info" %}
**反射率キャリブレーション／ホワイトバランス**がオフの場合、これらの設定はグレーアウトされます。オフの状態では、ターゲット検出は一切実行されません。
{% endhint %}

### 処理

主な画像処理およびキャリブレーションオプション。

**主な設定：*** **ヴィネット補正**：画像の端でのレンズの暗化を補正します ✅ 推奨
* **反射率キャリブレーション／ホワイトバランス**：検出されたターゲット（Survey3）および／またはDAQ光センサーデータ（LATTICE）を使用して画像をキャリブレーションします ✅ 推奨
* **デベイヤー法**：RAWデータを3チャンネルのマルチスペクトルデータに変換するアルゴリズム
* **再キャリブレーションの最小間隔**：キャリブレーションターゲットを使用する間の最小時間（秒単位）（デフォルト：**0** = すべて使用、範囲 0～3600）**キャリブレーション未実施時の代替製品：**フレームの反射率キャリブレーションができない場合（ターゲットがない、またはキャリブレーションが無効になっている）、2つの代替製品のいずれかとしてエクスポートされます。**1回の実行につき、このペアのうち正確に1つだけが存在**し、Vignette補正スイッチによって選択されます：

* **センサー応答をエクスポート**：`Sensor_Response_Images`を書き込み — ヴィネット補正が**オフ**のときに使用
* **ヴィネット補正済みデータをエクスポート**：`Vignette_Corrected_Images`を書き込み — ヴィネット補正が**オン**のときに使用

選択されていないチェックボックスはグレーアウトされます。アクティブなチェックボックスのチェックを外すと、そのファイルは一切書き込まれなくなります。

**LATTICE エクスポート製品**（すべてのプロジェクトに表示されます。LATTICE キャプチャに適用されます）：

* **デベイヤー処理済みデータをエクスポート**：線形デベイヤー処理済みの画像（`Debayered_Images`）。RGBおよびマルチスペクトルモジュールに適用されます。
* **プレビューをエクスポート**：表示プレビュー（`Preview_Images`）。RGB = ホワイトバランス（利用可能な場合はDAQ光源、そうでない場合はグレイワールド）＋ガンマ；マルチスペクトル = 偽色伸張。
* **放射輝度をエクスポート**：float32 形式のスペクトル放射輝度（`Radiance_Images`、W/m²/sr/nm）。マルチスペクトルモジュールのみ — RGB マスターには適用されません。
* ****反射率のエクスポート**：uint16 反射率（`Reflectance_Calibrated_Images`、DN 32768 = ρ 1.0）。ただし、`.daq` の下向き測定値またはフレーム内のターゲットがフレーム全体を覆っている場合に限る。 マルチスペクトルモジュールのみ。

4つすべてが**デフォルトでオン**になっています。インポートされた1つのLATTICE生フレームは、1回の処理パスで有効かつ該当するすべての製品に展開されます。「**反射率のエクスポート**」チェックボックスは、「反射率キャリブレーション」がオフの場合、グレーアウトされます。 親となるスイッチによって設定が不可能になる項目は常にグレーアウトされ、変更すべきスイッチ名を記載したツールチップが表示されます。**詳細設定：*** **光センサーのタイムゾーンオフセット**：光センサーの時刻同期のためのUTCからの時間差（デフォルト：0、範囲 −12 ～ +12）
* **PPK補正を適用**：`.daq`ファイルからのGPS/露出ピンデータを使用します（デフォルト：オフ）
* **露出ピン1/2**：デュアルカメラ設定において、カメラを露出ピンに割り当てます

{% hint style="info" %}
**LATTICEの入力レベルは自動です。** LATTICEによるキャプチャは、XMPメタデータに処理レベルが記録されており、処理は常にRAWフレームの段階でパイプラインに入ります。GUIで設定する必要はありません。 （CLI フラグ `--input-level` は、メタデータが失われたキャプチャに対する上級ユーザー向けのオーバーライドとして存在します。 [CLI リファレンス](../reference/cli-reference.md)を参照してください。)
{% endhint %}

### デベイヤー方式

現在、Chlorosでは2つのデベイヤー方式を提供しています：

#### 標準（高速、中程度の画質）

標準デベイヤーは処理が高速ですが、デベイヤー処理によるカラーノイズが発生するため、精度は低く、ノイズの多い画像になります。

#### テクスチャ対応（処理に時間がかかる、最高品質）\[Chloros+ のみ\]

テクスチャ対応では、高品質なエッジ認識デベイヤーとAI/MLノイズ除去モデルを組み合わせており、デベイヤー処理によるノイズをほぼすべて除去します。 このモデルの実行にはGPUメモリ（VRAM）が必要です。**7 GB以上のVRAM**があれば複数の画像を同時に処理できますが、7 GB未満の場合は1回に1枚の画像しか処理できず（処理速度が著しく低下します）。 [動的演算適応](../processing-architecture/dynamic-compute-adaptation.md)を参照してください。

{% hint style="info" %}
**LATTICEで取得された画像は、常に標準デモザイクを使用します。** LATTICE用にトレーニングされた「テクスチャ対応」モデルは存在しないため、LATTICE画像ではこのオプションは提供されません。ただし、同じプロジェクト内のSurvey3画像では引き続き使用可能です。
{% endhint %}

### インデックス（マルチスペクトルインデックス）

計算およびエクスポートする植生インデックスを設定します。GUIのドロップダウンメニューには、**27種類の事前定義されたインデックス式**が用意されています。**インデックスの追加方法：**

1.**「インデックスを追加」**ボタンをクリックします
2. ドロップダウンメニューからインデックスを選択します（NDVI、NDRE、GNDVIなど）
3. 視覚化設定（LUTの色、値の範囲）を構成します
4. 必要に応じて複数の指標を追加します

**よく使われる指標：*** **NDVI**：一般的な植生の健全性 （最も一般的）
* **NDRE**：RedEdgeとの組み合わせによる早期ストレス検知
* **GNDVI**：クロロフィル濃度に敏感
* **OSAVI**：可視光域の土壌との相性が良い
* **EVI**：葉面積指数（LAI）の高い領域**カスタム式：**

* すべての画像チャンネルに対するバンド演算を用いて、カスタム多スペクトルインデックス式を作成
* 再利用のためにカスタム式を保存
* カスタム式は Chloros+ の機能です。利用可否はご契約のプランレベルによって異なります

利用可能なすべてのインデックスおよび数式（GUI でのみ使用可能なものと、CLI/SDK でも機能するものも含む）については、[マルチスペクトルインデックス数式](../project-settings/multispectral-index-formulas.md)を参照してください。

### エクスポート

出力ファイル形式を制御します。

**利用可能な形式**（設定：**キャリブレーション済み画像形式**、デフォルト**TIFF (16 ビット)**）：

* **TIFF (16 ビット)**: GIS および科学的な分析に推奨
* **TIFF (32 ビット、パーセント)**: 浮動小数点値
* **PNG (8ビット)**：可視化用のロスレス圧縮
* **JPG (8ビット)**：ファイルサイズが最小、ロスあり圧縮

出力ファイルは、カメラと形式ごとにグループ化され、プロジェクトフォルダの下に「`<project>/<camera>/<format>/<Product>_Images/`」という形式で保存されます。放射輝度は、この設定に関係なく、**常に** float32 として「`tiff32`」フォルダに保存されます。 エクスポートされたファイルはソースのファイル名を保持します。フォルダ名によって生成物が識別されます。完全な出力ツリーについては、[処理の完了](finishing-the-processing.md)を参照してください。

{% hint style="warning" %}
**反射率値の読み取り**: ρ = 1.0 を表す DN はソースカメラによって異なります。LATTICE は 32768（XMP として `Chloros:PixelScale` と刻印）を使用し、Survey3 は 65535 を使用します。 定数であると仮定するのではなく、タグを確認してください。[出力画像フォーマット](../output-image-formats.md)を参照してください。
{% endhint %}

### DAQ 光センサー

このセクションには、プロジェクト内のすべての DAQ ダウンウェルファイル（`.daq` / `.csv`）が、ファイルごとに1行ずつ一覧表示されます。各行には、センサーモデル、ファイル名、およびそのファイルに適用されているディフューザーの**キャップ**補正値が示されています。

* **キャップのオーバーライド（全ファイル）**：プロジェクト全体に適用される単一のドロップダウンメニューです。**自動**（デフォルト）では、各ファイルに記録されたキャップ値が使用されます。何も記録されていない場合は、すべての MAPIR DAQ に日照補正機能が標準搭載されているため、日照状態とみなされます。 キャップを選択すると、すべてのファイルが上書きされます。生データはそれを使って補正され、すでにキャップが記録されているデータについては再参照が行われます（記録された補正が解除され、選択されたキャップが適用されます）。
* 行には、記録されたキャップがオペレーターによる確認ではなくハブの既定値であった場合、および選択したキャップにそのデバイスモデルのプロファイルがない場合（そのファイルに対しては上書きが拒否されます）に警告が表示されます。

[光センサー] タブで作成された DAQ 記録は、開いているプロジェクトに自動的に追加され、インポートされた `.daq` / `.csv` ファイルは、追加されるとすぐにここに表示されます。

<figure><img src="../.gitbook/assets/image (32).png" alt=""><figcaption><p>下部のプロジェクト設定 — インデックス、エクスポート形式、DAQ「光センサー」セクション、およびプロジェクトテンプレート/フォルダの設定</p></figcaption></figure>### アレイ位置合わせ

このセクションは、プロジェクト内の少なくとも 1 枚の画像に、LATTICE アレイが撮影時に付与するモジュール間位置合わせ変換（`Chloros:Alignment*` XMP）が含まれている場合に**のみ**表示されます。 このセクションには、タグが付与されている画像の数と、どのカメラが基準となっているかが表示され、以下の制御項目があります：

* **アレイ位置合わせを適用**（デフォルト：オン）：処理済みのすべての出力（デベイヤー済み／プレビュー／放射輝度／反射率／インデックス）を、アレイの共通基準ジオメトリに合わせてワープします。オフ = センサーのネイティブジオメトリでエクスポートします。
* **共通オーバーラップにトリミング**（デフォルト：オン）：アライメント済みのエクスポートデータを、すべてのモジュールが共有する領域にトリミングし、すべてのバンドのフットプリントを同一にします。オフの場合は、センサーのキャンバス全体が保持されます（ソース領域の外側は黒で塗りつぶされます）。
* **リサンプリング**：**バイリニア（滑らか、デフォルト）**、**最寄り点（正確な値を保持）**— 厳密な放射測定分析用にピクセル間の混合を行わない — または**キュービック（最もシャープ）**。***

## 設定の保存と読み込み

### プロジェクトテンプレートの保存

一貫性のあるワークフローのために、再利用可能なテンプレートを作成します：

1. 「プロジェクト設定」パネルで必要な設定をすべて行います
2. 下部の **「プロジェクトテンプレートを保存」** セクションまでスクロールします
3. わかりやすいテンプレート名を入力します（例：「Survey3N\_RGN\_Agriculture」）
4. 保存アイコンをクリックします

**メリット：**

* 複数のプロジェクトで同一の設定を適用できる
* 設定をチームメンバーと共有できる
* 繰り返し実施する調査において一貫性を維持できる

### 新規プロジェクトでのテンプレートの読み込み

新しいプロジェクトを作成する際：

1. メインメニューから**「新規プロジェクト」**を選択します
2. オプションのテンプレートピッカーからプロジェクトテンプレートを選択します
3. テンプレートのすべての設定が自動的に適用されます

### 作業ディレクトリ

**「作業ディレクトリ」**設定では、新しいプロジェクトがデフォルトで作成される場所を指定します：

* **デフォルトの場所**：`C:\Users\[Username]\Chloros Projects`
* **場所の変更**：編集アイコンをクリックし、新しいフォルダを選択
* **CLIと共有**：`chloros-cli`は同じデフォルトのプロジェクトフォルダ設定を使用します
* **変更するタイミング**：
  * チームでの共同作業のためのネットワークドライブ
  * ストレージ容量の大きい別のドライブ
  * 年別／クライアント別に整理されたフォルダ構造

## PPK（後処理キネマティック）の設定

GPS 搭載の MAPIR DAQ レコーダーを使用して正確な位置情報を取得する場合：

### 前提条件

* GPS（GNSS）モジュールを搭載したMAPIR DAQ
* 露光ピンエントリを含む.daqログファイル
* 撮影セッション中にDAQの露光ピンに接続されたカメラ

### 設定手順

1. .daqログファイルをプロジェクトフォルダに配置します
2. 「プロジェクト設定」で、**「PPK補正を適用」**チェックボックスを有効にします
3. 必要に応じて**「光センサーのタイムゾーンオフセット」**を設定します（デフォルト：UTCの場合は0）
4. カメラを露出ピンに割り当てます：
   * **単一カメラ**：自動的にピン 1 に割り当てられます
   * **デュアルカメラ**：各カメラを正しいピンに手動で割り当てます**露出ピンの割り当て：*** **露出ピン 1**：ドロップダウンからカメラモデルを選択
* **露出ピン 2**：2台目のカメラ、または「使用しない」を選択
* 同じカメラを両方のピンに割り当てることはできません

{% hint style="warning" %}
**重要**：露出ピンは、それぞれのカメラに正しく割り当てる必要があります。割り当てが間違っていると、位置情報が誤ったものになります。
{% endhint %}

## 高度なシナリオ

### マルチカメラプロジェクト

1つのプロジェクトで複数のMAPIRカメラからの画像を処理する場合：

1. Chlorosは各カメラのモデル（Survey3およびLATTICEを含む）を自動的に検出します
2. 各カメラには適切な処理プロファイルが割り当てられ、各カメラごとに独自の出力フォルダツリーが作成されます
3. PPK：各 Survey3 カメラを、正しい露出ピンに手動で割り当てます
4. すべてのカメラで同じエクスポート形式とインデックスが使用されます

**例**：Survey3W、RGN、および Survey3N、OCN によるデュアルカメラリグ、 または、RGBマスターと狭帯域モジュールを組み合わせたLATTICEアレイ

### タイムラプスまたは複数日にわたる観測

同じ地域を長期にわたり繰り返し観測する場合：

1. 標準設定を含むテンプレートを作成する
2. 各セッションで一貫したキャリブレーションターゲットの設定を使用する
3. 各日付のデータを個別のプロジェクトとして処理する
4. 比較可能な結果を得るために同一の設定を使用する
5. 経時分析のために同じ形式でエクスポートする

### 大規模なデータセット

画像数が多数（500枚以上）のプロジェクトの場合：

* 日付やエリアごとに小さなプロジェクトに分割することを検討してください
* 処理を高速化するには、Chloros+の並列処理を使用してください
* バッチ処理の自動化には、CLIまたはAPIの使用を検討してください
* ターゲット検出時間を短縮するため、再キャリブレーションの最小間隔を調整する

## 設定の確認

処理を開始する前に、以下の主要な設定を確認してください：

* [ ] ファイルブラウザでカメラモデルが正しく検出されている
* [ ] ヴィネット補正が有効になっている
