# プロジェクト設定の調整

画像を処理する前に、ワークフローの要件に合わせてプロジェクト設定を構成することが重要です。「プロジェクト設定」<img src="../.gitbook/assets/icon_project-settings.JPG" alt="" data-size="line">パネルでは、キャリブレーション、処理オプション、マルチスペクトルインデックス、およびエクスポート形式を包括的に制御できます。

## プロジェクト設定へのアクセス

1. Chlorosでプロジェクトを開きます
2. 左サイドバーにある**プロジェクト設定** <img src="../.gitbook/assets/icon_project-settings.JPG" alt="" data-size="line">アイコンをクリックします
3. プロジェクト設定パネルに、すべての設定オプションが表示されます

<figure><img src="../.gitbook/assets/image (28).png" alt=""><figcaption><p>「プロジェクト設定」パネル — 表示、ターゲット検出、および処理</p></figcaption></figure>

{% hint style="info" %}
**設定はプロジェクトとともに自動的に保存されます**。プロジェクトを再度開くと、すべての設定が復元されます。
{% endhint %}

## 一般的なワークフローのためのクイックセットアップ

### デフォルト設定（ほとんどのユーザーに推奨）

デフォルト設定は、一般的なSurvey3およびLATTICEのワークフローに最適です：

* ✅ **ヴィネット補正**：有効
* ✅ **ヴィネット補正**：有効（MAPIRターゲットおよび／またはDAQ光センサーデータを使用）
* ✅ **デベイヤー方式**：標準（高速、中品質）
* ✅ **エクスポート形式**： TIFF（16ビット）（すべて8ビットのプロジェクトの場合はTIFF（8ビット））
* ✅ **すべてのエクスポート成果物**：有効（LATTICEは、デベイヤー処理済み、プレビュー、放射輝度、反射率の各データを自動的に出力します）

画像をインポートするだけで、これらのデフォルト設定で処理を開始できます。

***

## プロジェクト設定の概要

「プロジェクト設定」パネルは、以下のセクションで構成されています。プロジェクトに該当するファイルが含まれている場合、**DAQ 光センサー**および**アレイ位置合わせ**という 2 つのセクションが自動的に表示されます。 完全なドキュメントについては、[プロジェクト設定](../project-settings/project-settings.md)を参照してください。

### 表示

* **画像サムネイルの解像度**：画像グリッドのサムネイルの解像度。 オプション：**デフォルト (512 px)**、**1024 px**、**2048 px**、**フル解像度**。表示のみの設定であり、処理には一切影響しません。値が大きいほど、ズームした際の表示は鮮明になりますが、読み込みに時間がかかります。

### ターゲット検出

Chlorosが画像内のキャリブレーションターゲットをどのように識別するかを制御します。

**主な設定：*** **最小キャリブレーションサンプル領域 (px)**：ターゲット検出のサイズ閾値（デフォルト：**25**、範囲 0～10000）
* **最小ターゲットクラスタリング (0–100)**: ターゲット領域をグループ化する際の類似性の閾値（デフォルト:**60**）**調整すべき場合：**

* 誤検出が発生する場合は、サンプル領域を拡大してください
* ターゲットが検出されない場合は、サンプル領域を縮小してください
* ターゲットが複数の検出に分割されてしまう場合は、クラスタリングを調整してください

{% hint style="info" %}
**反射率キャリブレーション／ホワイトバランス**がオフの場合、これらの設定はグレーアウトされます。オフの状態では、ターゲット検出は一切実行されません。
{% endhint %}

### 処理

主な画像処理およびキャリブレーションオプション。

**主な設定：*** **ヴィネット補正**：画像の端でのレンズの暗さを補正します ✅ 推奨
* **反射率キャリブレーション／ホワイトバランス**：検出されたターゲット（Survey3）および／またはDAQの光センサーデータ（LATTICE）を使用して画像をキャリブレーションします ✅ 推奨
* **デベイヤー法**：RAWデータを3チャンネルのマルチスペクトルデータに変換するアルゴリズム
* **再キャリブレーションの最小間隔**：キャリブレーションターゲットを使用する間の最小時間（単位：秒）（デフォルト：**0** = すべて使用、範囲 0～3600）**キャリブレーション未実施時の代替製品：**フレームの反射率キャリブレーションが実行できない場合（ターゲットがない、またはキャリブレーションが無効になっている）、以下の2つの代替製品のいずれかとしてエクスポートされます。**1回の実行につき、このペアのうち正確に1つだけが存在します**。これは「ヴィネット補正」スイッチによって選択されます：

* **センサー応答をエクスポート**：`Sensor_Response_Images`を書き込み — ヴィネット補正が**オフ**のときに使用
* **ヴィネット補正済みデータをエクスポート**：`Vignette_Corrected_Images`を書き込み — ヴィネット補正が**オン**のときに使用

選択されていないチェックボックスはグレー表示になります。アクティブなチェックボックスのチェックを外すと、そのファイルは一切書き込まれなくなります。

**LATTICE エクスポート製品**（すべてのプロジェクトに表示されます。これらは LATTICE キャプチャに適用されます）：

* **デベイヤー処理済み画像をエクスポート**： 線形デベイヤー処理済み画像（`Debayered_Images`）：キャリブレーションパックのダークオフセットを除去した後、デモザイク処理を施したもの。フラットフィールドやアンミックスは行われません。これは、キャプチャがデベイヤー処理済みレベルで保存するファイルと同じもので、センサーのネイティブ向きで出力されます。 RGBおよびマルチスペクトルモジュールに適用されます。
* **プレビューのエクスポート**：画面上のプレビュー（`Preview_Images`）。RGB = ホワイトバランス（利用可能な場合はDAQ光源、それ以外はグレイワールド）＋ガンマ補正；マルチスペクトル = 偽色伸張。
* **放射輝度のエクスポート**：float32 スペクトル放射輝度（`Radiance_Images`、W/m²/sr/nm）。マルチスペクトルモジュールのみ — RGBマスターには適用されません。
* ****反射率のエクスポート**：uint16 反射率（`Reflectance_Calibrated_Images`、DN 32768 = ρ 1.0）。`.daq` の下向き測定値またはフレーム内のターゲットがフレームを覆っている場合。 マルチスペクトルモジュールのみ。

これら4つすべてが**デフォルトでオン**になっています。インポートされた1つのLATTICE生フレームは、1回の処理パスで有効かつ適用可能なすべての製品に分散されます。「**反射率のエクスポート**」チェックボックスは、「反射率キャリブレーション」がオフの場合、グレーアウトされます。 親となるスイッチの設定によって適用不可能となる設定は常にグレーアウトされ、変更すべきスイッチ名を記載したツールチップが表示されます。**詳細設定：*** **光センサーのタイムゾーンオフセット**：光センサーの時刻同期のためのUTCからの時間差（デフォルト：0、範囲 −12 ～ +12）
* **PPK補正を適用**：`.daq`ファイルからのGPS/露出ピンデータを使用します（デフォルト：オフ）
* **露出ピン1/2**：デュアルカメラ構成において、カメラを露出ピンに割り当てます

{% hint style="info" %}
**LATTICEの入力レベルは自動です。** LATTICEによるキャプチャは、XMPメタデータに処理レベルを保持しており、処理は常にRAWフレームの段階でパイプラインに入ります。GUIで設定する必要はありません。 （CLIフラグ `--input-level` は、メタデータが失われたキャプチャに対する上級ユーザー向けのオーバーライドとして存在します。[CLIリファレンス](../reference/cli-reference.md)を参照してください。）
{% endhint %}

### デベイヤー方式

現在、Chlorosでは2つのデベイヤー方式を提供しています：

#### 標準（高速、中程度の品質）

標準デベイヤーは処理が高速ですが、デベイヤー処理によるカラーノイズが発生するため、精度は低く、ノイズの多い画像になります。

#### テクスチャ対応（処理速度：遅い、画質：最高）\[Chloros+ 限定\]

テクスチャ対応では、高品質なエッジ認識デベイヤーとAI/MLノイズ除去モデルを組み合わせており、デベイヤー処理によるノイズをほぼすべて除去します。 このモデルの実行にはGPUメモリ（VRAM）が必要です。**7 GB以上のVRAM**があれば複数の画像を同時に処理できますが、7 GB未満の場合は1枚ずつ処理されます（処理速度が著しく低下します）。 [動的演算適応](../processing-architecture/dynamic-compute-adaptation.md)を参照してください。

{% hint style="info" %}
**LATTICEで取得した画像では、常に「標準デモザイク」が使用されます。** LATTICE用にトレーニングされた「テクスチャ対応」モデルは存在しないため、LATTICE画像ではこのオプションは提供されません。ただし、同じプロジェクト内のSurvey3画像では引き続き使用可能です。
{% endhint %}

### インデックス（マルチスペクトルインデックス）

計算およびエクスポートする植生インデックスを設定します。GUIのドロップダウンメニューには、**27種類の事前定義されたインデックス式**が用意されています。**インデックスの追加方法：**

1.**「インデックスを追加」**ボタンをクリックします
2. ドロップダウンメニューから指標を選択します（NDVI、NDRE、GNDVIなど）
3. 視覚化設定（LUTの色、値の範囲）を構成します
4. 必要に応じて複数の指標を追加します

**よく使われる指標：*** **NDVI**：植生の全般的な健全性（最も一般的）
* **NDRE**： RedEdgeによる早期ストレス検出* **GNDVI**: クロロフィル濃度に敏感
* **OSAVI**: 可視光域の土壌との相性が良い
* **EVI**: 葉面積指数（LAI）の高い地域

**カスタム式:**

* すべての画像チャンネルに対してバンド演算を行い、カスタムマルチスペクトル指標式を作成
* 再利用のためにカスタム式を保存
* カスタム式はChloros+の機能です。利用可否はご契約のプラン階層によって異なります

利用可能なすべてのインデックスおよび式（GUIでのみ利用可能な名称や、CLI/SDKでも機能する名称を含む）については、[マルチスペクトルインデックス式](../project-settings/multispectral-index-formulas.md)を参照してください。

### エクスポート

出力ファイル形式を指定します。

**利用可能な形式**（設定：**キャリブレーション済み画像形式**、デフォルトは**TIFF (16ビット)**）：

* **TIFF (16ビット)**：GIS や科学的な分析に推奨
* **TIFF (8ビット)**: 8ビットTIFF
* **TIFF (32ビット、パーセント)**: 浮動小数点値
* **PNG (8ビット)**: 視覚化用のロスレス圧縮
* **JPG (8ビット)**: ファイルサイズが最も小さく、ロス有りの圧縮

このリストは、プロジェクトの画像が保持できる形式を示しています。Chlorosはビット深度のアップスケールを行いません。すべて8ビットの画像の場合、利用可能な形式はTIFF（8ビット）、PNG（8ビット）、JPG（8ビット）のみであり、デフォルトではTIFF（8ビット）になります。 混合プロジェクトでは、各キャプチャは自身のビット深度、またはそれ以下の深度でエクスポートされます。Radianceは32ビット浮動小数点のままです。

出力ファイルはプロジェクトフォルダ内に、カメラとフォーマットごとにグループ化されて保存されます（例：`<project>/<camera>/<format>/<Product>_Images/`）。Radianceデータは、この設定にかかわらず、**常に**float32形式で`tiff32`フォルダに書き込まれます。 エクスポートされたファイルは元のファイル名を保持します。フォルダ名によって生成物が識別されます。LATTICEマルチスペクトルエクスポートでは、生成物フォルダの隣にある `clamp_masks/` フォルダに、ピクセルごとのクランプマスクを書き込むこともできます。 完全な出力ツリーについては、[処理の完了](finishing-the-processing.md)を参照してください。

{% hint style="warning" %}
**反射率値の読み取り**：ρ = 1.0 に対応する DN は、元のカメラによって異なります。LATTICE では 32768（XMP ファイルに `Chloros:PixelScale` として記録）、Survey3では 65535 を使用します。 定数であると仮定するのではなく、タグを読み取ってください。[出力画像フォーマット](../output-image-formats.md)を参照してください。
{% endhint %}

### DAQ 光センサー

このセクションでは、プロジェクト内のすべてのDAQダウンウェルファイル（`.daq` / `.csv`）を、ファイルごとに1行ずつ一覧表示し、センサーモデル、ファイル名、およびそのファイルに適用されているディフューザーの**キャップ** 補正が適用されているかを表示します。

* **キャップのオーバーライド（全ファイル）**：プロジェクト全体で共通のドロップダウンメニューです。**自動**（デフォルト）は、各ファイルに記録されたキャップを使用します。何も記録されていない場合は日射が想定されますが、DAQ-U、DAQ-M、およびDAQ-Eにはキャップが設定されておらず、Chlorosは適合されたキャップを判別できないため、処理時に想定されたキャップについて警告が表示されます。適合されたキャップを選択してください。 キャップを選択すると、DAQ-E-Sを除くすべてのファイルの設定が上書きされます。DAQ-E-Sのディフューザーは校正の一部であるため、生データはこれに基づいて補正され、すでにキャップが設定されている記録データについては再参照が行われます（記録された補正が解除され、選択されたキャップが適用されます）。
* 記録されたキャップがオペレーターによる確認ではなくハブの想定デフォルトであった場合、および選択したキャップにそのデバイスモデルのプロファイルが存在しない場合、行に警告が表示されます（そのファイルに対しては上書きが拒否されます）。

[光センサー] タブで作成されたDAQ記録は、開いているプロジェクトに自動的に追加され、インポートされた`.daq` / `.csv`ファイルは、追加されるとすぐにここに表示されます。

<figure><img src="../.gitbook/assets/image (32).png" alt=""><figcaption><p>下部のプロジェクト設定 — インデックス、エクスポート形式、DAQ「光センサー」セクション、およびプロジェクトテンプレート/フォルダ制御</p></figcaption></figure>### アレイの位置合わせ

このセクションは、プロジェクト内の少なくとも 1 枚の画像に、LATTICE アレイが撮影時に付与するモジュール間位置合わせ変換（`Chloros:Alignment*` XMP）が含まれている場合に**のみ**表示されます。 ここでは、タグが付与されている画像の数と、どのカメラが基準となっているかが表示され、以下の制御項目があります：

* **アレイ位置合わせを適用**（デフォルト：オン）：処理済みのすべてのプロダクト（デベイヤー処理済み／プレビュー／放射輝度／反射率／インデックス）を、アレイの共通基準ジオメトリにワープします。オフ = センサーのネイティブジオメトリでエクスポートします。
* **共通オーバーラップにトリミング**（デフォルト：オン）：アライメント済みのエクスポートデータを、すべてのモジュールが共有する領域にトリミングし、すべてのバンドのフットプリントを同一にします。オフにすると、センサーのキャンバス全体が保持されます（ソース領域の外側は黒で塗りつぶされます）。
* **リサンプリング**：**バイリニア（滑らか、デフォルト）**、**最寄り点（正確な値を保持）**— 厳密な放射測定分析用にピクセル間の混合を行わない — または**キュービック（最もシャープ）**。***

## 設定の保存と読み込み

### プロジェクトテンプレートの保存

一貫性のあるワークフローのために、再利用可能なテンプレートを作成します：

1. 「プロジェクト設定」パネルで必要な設定をすべて行います
2. 下部の **「プロジェクトテンプレートを保存」** セクションまでスクロールします
3. わかりやすいテンプレート名を入力します（例：「Survey3N_RGN_Agriculture」）
4. 保存アイコンをクリックします

**メリット：**

* 複数のプロジェクトで同一の設定を適用できます
* 設定をチームメンバーと共有できます
* 繰り返し行う調査において一貫性を維持できます

### 新規プロジェクトでのテンプレートの読み込み

新しいプロジェクトを作成する際：

1. メインメニューから**「新規プロジェクト」**を選択します
2. オプションのテンプレートピッカーでプロジェクトテンプレートを選択します
3. テンプレートのすべての設定が自動的に適用されます

### 作業ディレクトリ

**「作業ディレクトリ」**設定では、新しいプロジェクトがデフォルトで作成される場所を指定します：

* **デフォルトの場所**：Windowsの「ドキュメント」フォルダ内の`Documents\MAPIR\Chloros Projects`（通常は`C:\Users\[Username]\Documents\MAPIR\Chloros Projects`。OneDriveやローミングプロファイルによって「ドキュメント」フォルダが移動された場合は、そのフォルダに追従します）
* **場所の変更**：編集アイコンをクリックし、新しいフォルダを選択します
* **CLIと共有**：`chloros-cli` は、同じデフォルトのプロジェクトフォルダ設定を使用します
* **Windowsではパス名を短くする**：Windowsの長いパス機能が有効になっていない限り、約130文字を超える階層を持つプロジェクトフォルダは処理前に拒否されます — [処理の開始](starting-the-processing.md#the-project-folder-is-too-deep-for-this-computer)を参照
* **変更すべき場合**：
  * チームでの共同作業のためのネットワークドライブ
  * より大容量の別のドライブ
  * 年別／クライアント別に整理されたフォルダ構造

## PPK（後処理キネマティック）の設定

GPS 搭載の MAPIR DAQ レコーダーを使用して正確な位置情報を取得する場合：

### 前提条件

* GPS（GNSS）モジュールを搭載したMAPIR DAQ
* 露光ピンエントリを含む .daq ログファイル
* 撮影セッション中に DAQ の露光ピンに接続されたカメラ

### 設定手順

1. .daq ログファイルをプロジェクトフォルダに配置します
2. 「プロジェクト設定」で、**「PPK補正を適用」**チェックボックスを有効にします
3. 必要に応じて **「光センサーのタイムゾーンオフセット」** を設定します（デフォルト：UTC の場合 0）
4. カメラを露出ピンに割り当てます：
   * **シングルカメラ**：自動的にピン 1 に割り当てられます
   * **デュアルカメラ**：各カメラを正しいピンに手動で割り当てます**露出ピンの割り当て：*** **露出ピン 1**：ドロップダウンからカメラモデルを選択
* **露出ピン 2**：2台目のカメラを選択するか、「使用しない」を選択
* 同じカメラを両方のピンに割り当てることはできません

{% hint style="warning" %}
**重要**：露出ピンは、それぞれのカメラに正しく割り当てる必要があります。割り当てが間違っていると、位置情報が誤ったデータとなります。
{% endhint %}

## 高度なシナリオ

### マルチカメラプロジェクト

1つのプロジェクトで複数のMAPIRカメラからの画像を処理する場合：

1. Chlorosは各カメラモデル（Survey3およびLATTICEを含む）を自動的に検出します
2. 各カメラには適切な処理プロファイルが適用され、各カメラごとに独自の出力フォルダツリーが作成されます
3. PPK：各Survey3カメラを正しい露出ピンに手動で割り当ててください
4. すべてのカメラで同じエクスポート形式とインデックスが使用されます

**例**：Survey3W RGN + Survey3N OCNのデュアルカメラリグ、またはRGBマスターと狭帯域モジュールを組み合わせたLATTICEアレイ

### タイムラプスまたは複数日間の調査

同じエリアを長期にわたり繰り返し調査する場合：

1. 標準設定を含むテンプレートを作成します
2. 各セッションで一貫したキャリブレーションターゲットのセットアップを使用する
3. 各日付のデータを個別のプロジェクトとして処理する
4. 比較可能な結果を得るために、同一の設定を使用する
5. 経時分析のために、同じ形式でエクスポートする

### 大規模なデータセット

画像数が非常に多い（500枚以上）プロジェクトの場合：

* 日付やエリアごとに、より小さなプロジェクトに分割することを検討する
* 処理を高速化するには、Chloros+の並列処理を活用する
* バッチ処理の自動化には、CLIまたはAPIの利用を検討する
* ターゲット検出時間を短縮するため、再キャリブレーションの最小間隔を調整する

## 設定の確認

処理を開始する前に、以下の主要な設定を確認してください：

* [ ] ファイルブラウザでカメラモデルが正しく検出されている
* [ ] ヴィネット補正が有効になっている
* [ ] 反射率キャリブレーションが有効になっている
* [ ] Survey3の場合：少なくとも1枚のキャリブレーションターゲット画像がインポートされ、確認されていること。「LATTICE」の場合：ターゲットおよび／または`.daq`のダウンウェル記録が存在すること
* [ ] 必要なマルチスペクトルインデックスが追加されている
* [ ] ワークフローに適したエクスポート形式が設定されている
* [ ] PPK設定が構成されている（露出イベントを含む.daqファイルを使用する場合）
