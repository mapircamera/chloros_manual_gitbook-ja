# 処理の完了

Chloros
による処理が完了したら、結果を確認し、出力品質を検証し、ワークフローで使用するよう処理済みの画像を準備します。このページでは、最後の手順と今後の対応について解説します。

## 処理完了の表示

処理が正常に完了すると、以下の表示が現れます：

* ✅ **進行状況バー**：100% 完了
* ✅ **デバッグログ**：カウント（画像数、カメラグループ数、ターゲット数、キャリブレーション済み画像数、書き込み済みファイル数）を含む `[RUN-SUMMARY]` の最終行が表示されます
* ✅ **開始ボタン**：再び有効になります（次の処理実行の準備が整います）
* ✅ **出力ファイル**：処理済みのすべての画像がプロジェクトの出力ツリー（以下）に保存されます

{% hint style="warning" %}
**画像が書き込まれなかった実行は失敗とみなされます。** 画像プロダクトを要求したにもかかわらず、実行で何も書き込まれなかった場合、Chloros
はこれを失敗として報告します。ログ名に含まれる`[RUN-SUMMARY]`は、考えられる原因（インポートされたデータがない、ターゲットが検出されなかった、または要求されたすべてのプロダクトが適用不可としてスキップされた）を示唆しています。CLI
の対応する処理は、非ゼロの終了コードで終了します。 意図的にメタデータのみを処理する実行（すべてのエクスポート製品をオフにし、インデックスを作成しない）は、依然として成功とみなされます。[CLI
リファレンス](../reference/cli-reference.md#a-run-that-writes-no-images-fails)を参照してください。
{% endhint %}

## 処理済み画像の場所

### 出力フォルダを開く

1. **メインメニュー**の<img src="../.gitbook/assets/image (1) (1) (1) (1).png" alt="" data-size="line">
アイコン（左上）をクリックします
2. **「プロジェクトフォルダを開く」**を選択します
3. ファイルエクスプローラーがプロジェクトディレクトリを開きます
4. 名前からプロジェクトを探します

### 出力ツリー

出力ファイルは、**プロジェクトフォルダーの下に、カメラごとにグループ化され、さらにファイル形式ごとに分類されて**保存されます：

```
<project>/
└── LATT-M3M-L41-F550/                  # one folder per camera
    ├── tiff16/
    │   ├── Reflectance_Calibrated_Images/
    │   ├── Debayered_Images/
    │   ├── Preview_Images/
    │   └── NDVI_Index_Images/           # one folder per selected index
    └── tiff32/
        └── Radiance_Images/             # float32 radiance always lands here
```

* **カメラフォルダ**：LATTICEの場合は`LATT-<sensor>-<lens>-F<filter>`（キャプチャのEXIF情報`Model`と一致）、Survey3
の場合は`<model>_<filter>`（例： `Survey3N_RGN`）。センサーとフィルターを共有するがレンズが異なる2台のカメラは、別々のツリーを保持します（ヴィネット、画角、歪みが異なるため）。
* **フォーマットフォルダ**：エクスポート形式の設定に従います — `tiff16`、 `tiff8`、`png8`、`jpg8`、または `tiff32`（TIFF
（32ビット、パーセント）用）。ラディアンスは常にfloat32型であり、常に`tiff32`の下に配置されます。
* **プロダクトフォルダ**:
  * `Reflectance_Calibrated_Images/` — キャリブレーション済み反射率
  * `Debayered_Images/` — 線形デベイヤー処理済み (LATTICE)
  * `Preview_Images/` — ディスプレイプレビュー (LATTICE)
  * `Radiance_Images/` — float32 スペクトル放射度、W/m²/sr/nm（LATTICE マルチスペクトル）
  * `Vignette_Corrected_Images/` **または** `Sensor_Response_Images/` — 反射率の参照値がないフレームに対する、キャリブレーションされていないフォールバックデータ。1回の実行につき、これら2つのうち正確に1つが存在し、Vignette補正設定によって選択されます
  * `<INDEX>_Index_Images/` — 選択されたインデックスごとに1つのフォルダ（例：`NDVI_Index_Images`）

{% hint style="info" %}
**エクスポートされたすべての製品は、ソースファイルの名前を保持します。**`capture_..._raw.tif` の放射輝度データを出力しても、そのファイル名は依然として `capture_..._raw.tif` となります — 単に `tiff32/Radiance_Images/` フォルダ内に格納されるだけです。**ファイル名ではなくフォルダ名が製品を識別します**。そのため、`*radiance*.tif`で検索しても何も見つかりません。代わりにディレクトリ名で照合してください。
{% endhint %}

### ファイル数はどれくらいあるべきか？

計算式で数えないでください。出力ファイル数は、どの製品が有効化されており、各カメラにどの製品が適用されるかによって異なります（例：RGB
カメラには放射輝度/反射率のデータはありません）。正確なファイル数はログに記載されています： 最後の `[RUN-SUMMARY]` 行には、書き込まれたファイル数が正確に報告されており、ヒント行にはスキップされた項目についての説明が記載されています。

## 反射率のピクセル値の読み取り（GIS / Pix4D / スクリプト）

反射率は整数のDNとして保存されており、**ρ = 1.0 に対応するDNはソースカメラによって異なります**：

| ソース             | ρ = 1.0 に対応する値 | 判別方法                                        |
| --------------- | ---------- | -------------------------------------------------- |
| LATTICE (M3C/M3M) | **32768**（ρ 2.0までの余裕あり） | ファイルに XMP タグ `Chloros:PixelScale=32768` が付加されている |
|Survey3
         | **65535** (ρ 1.0 でクリップされる)     | `Chloros:*` XMP タグがない — その不在が合図となる |

**`Chloros:PixelScale`タグを読み取り、その値で割る**こと。一律に65535と仮定してはならない。LATTICE反射率を65535で割ると、すべての値が黙って半分になってしまう。設計上、スケール情報が含まれないエッジケースが1つある： 8ビットソースでキャプチャされ、8ビット出力として書き出されたデータは、リスケールされずクリップされ、意図的にスケールタグが付与されません — 値を割るのではなく、16ビットまたは32ビットで再エクスポートしてください。 詳細については、[出力画像フォーマット](../output-image-formats.md)を参照してください。***

## エクスポート時に引き継がれるメタデータ

すべての製品は、ソースキャプチャの**GPSブロック**とその**EXIFサブIFD**を保持しているため、
エクスポートには `FocalLength`、 `FNumber`、`ExposureTime`、`ISO`、`DateTimeOriginal`、および
`CameraSerialNumber`に加え、地理参照情報も含まれます。

{% hint style="warning" %}
**オルソモザイクの縮尺が不自然な値になった場合は、まず `FocalLength` を確認してください。**
Pix4D は、焦点距離と高度から地上サンプル距離を算出します。 このタグがないと、
スケールが著しく誤った値になってしまいます。ある49枚の撮影データから構成されるフライトで測定したところ、411 m × 160 mの
オレンジ畑が47.8 km × 13 kmとして再構築され、大部分が
空っぽの空間からなる455メガピクセルのオルソ画像が生成されました。 タイリング処理の遅さや予想外に巨大なファイルサイズは、これによる症状であり、別の
問題ではありません。

```bash
exiftool -FocalLength -GPSLatitude "YourProject/.../some_export.tif"
```
{% endhint %}

*すべての*タグがコピーされるわけではありません。IFD0の構造タグは意図的に除外されており（これらを
コピーするとLATTICEの出力が破損します）、`ExifImageWidth` / `ExifImageHeight`は除外されています
。これらは元のキャプチャを記述しているためです。サイズ変更されたエクスポートをそのまま使用すると、
自身のラスターと矛盾する寸法が指定されてしまうことになります。

## 一般的な出力に関する問題と解決策

### 問題：出力ファイルが見つからない

**考えられる原因：**

* 製品が当該カメラに対応していない（例：RGB
カメラ用の放射輝度／反射率 — ログにその旨が記載されています）
* 必要な参照情報が欠落していた（例：ターゲットおよび`.daq`のダウンウェリングがない状態での反射率）
* プロジェクト設定で、製品のエクスポートチェックボックスが無効になっていた
* エクスポート中にディスク容量が不足した

**解決策：**

1. デバッグログ内の `[RUN-SUMMARY]` のヒントおよび `[EXPORT-CHECK]` の行を確認してください。これらはカメラごとのスキップについて説明しています
2. [プロジェクト設定](adjusting-project-settings.md)
3. ディスク容量が十分であったか確認してください
4. 原因を修正した後、再処理を行ってください

### 問題：エッジが暗い、または明るい（ヴィネットが依然として目立つ）

**考えられる原因：**

* ヴィネット補正が無効になっている
* カメラ／レンズがChloros
のプロファイルデータベースに登録されていない
* 補正能力を超える極端なヴィネット

**解決策：**

1. [プロジェクト設定]でヴィネット補正が有効になっていることを確認してください
2. カメラモデルが正しく検出されているか確認する
3. ヴィネットが残る場合は、MAPIR
のサポートに連絡する

### 問題：色や値が不正確

**考えられる原因：**

* キャリブレーションターゲットが検出されていない
* 誤ったキャリブレーションターゲットモデルが選択されている
* 反射率キャリブレーションが無効になっている
* ターゲット画像の品質が低い

**解決策：**

1. 反射率キャリブレーションが有効になっていることを確認する
2. デバッグログの「ターゲット検出」メッセージを確認する
3. ターゲット画像の品質を確認する
4. 適切なターゲットをマークして再処理する

### 問題：NDVI
の値が不正確に見える

**NDVI
の想定範囲：*** **水、岩石、土壌**：-0.1～0.2
* **まばらな／不健全な植生**：0.2～0.4
* **中程度の植生**：0.4～0.6
* **健全で密生した植生**：0.6 ～ 0.9**値がこれらの範囲外の場合：**

1. 反射率のキャリブレーションが適用されていることを確認する
2. 光センサーのログが含まれていることを確認する
3. キャリブレーションターゲットが検出されたことを確認する
4. 正しいカメラモデルが検出されていることを確認する
5. ターゲット画像の撮影タイミングと条件を見直す
6. 反射率ファイルからインデックスを独自に算出する場合は、ファイルの `Chloros:PixelScale` で除算していることを確認する（上記参照）
