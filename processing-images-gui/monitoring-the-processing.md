# 処理の監視

処理が開始されると、Chloros

では、進捗状況を監視したり、問題を確認したり、データセットの状況を把握したりするためのいくつかの方法が提供されます。このページでは、処理の追跡方法と、Chloros

が提供する情報の解釈方法について説明します。

## 進捗バーの概要

上部ヘッダーにある進捗バーには、リアルタイムの処理状況と完了率が表示されます。進捗状況は、Server-Sent Events（SSE）を介してバックエンドからライブ配信されるため、このバーはパイプラインの実際の動作状況を反映しています。

### 無料モードの進捗バー

Chloros

+ ライセンスをお持ちでないユーザーの場合：

**2段階の進捗表示：**

1.**ターゲット検出** - 画像内のキャリブレーションターゲットの検出
2. **処理** - 補正の適用とエクスポート**進捗バーに表示される内容：**

* 全体の完了率（0～100%）
* 現在のステージ名
* シンプルな水平バーによる可視化

### Chloros

+ プログレスバー

Chloros

+ ライセンスをお持ちのユーザー向け：

**4段階の進行状況表示：**

1.**検出** - キャリブレーションターゲットの検出
2. **分析** - 画像の検証とパイプラインの準備
3. **キャリブレーション** - ヴィネット補正および反射率補正の適用
4. **エクスポート** - 処理済みファイルの保存**インタラクティブ機能：*** **プログレスバーにカーソルを合わせると**、4段階の詳細パネルが表示されます
* **プログレスバーをクリックすると**、詳細パネルが固定されます
* **再度クリック**すると固定が解除され、マウスを離すと自動的に非表示になります
* 各段階ごとに個別の進行状況（0～100%）が表示されます

{% hint style="info" %}
**CLI

との整合性**：`chloros-cli process`の実行中、同じ4つのスレッドが「検出中」、「分析中」、「処理中」、「エクスポート中」と報告され、`chloros-cli export-status`は別のターミナルからのスレッド4のエクスポート進行状況をリアルタイムで表示します。 [CLI

リファレンス](../reference/cli-reference.md)を参照してください。
{% endhint %}

## 各処理ステージの理解

{% hint style="info" %}
**パイプラインアーキテクチャ**：これらの 4 つの GUI 段階は、[4 スレッド処理パイプライン](../processing-architecture/processing-pipeline.md) に対応しています。GPU アクセラレーションが有効なシステムでは、 スレッド3（キャリブレーション）は、お使いのハードウェアに合わせて処理を最適化する[ダイナミック・コンピュート・アダプテーション](../processing-architecture/dynamic-compute-adaptation.md)の恩恵を受けます。
{% endhint %}

### ステージ1：検出（ターゲット検出）

**処理内容：**

* Chloros

は、「ターゲット」チェックボックスで選択した画像をスキャンします（チェックされていない場合はすべての画像をスキャンします）
* コンピュータビジョンアルゴリズムがキャリブレーションパネルを識別します
* 各パネルから反射率値が抽出されます
* 適切なキャリブレーションスケジューリングのために、ターゲットのタイムスタンプが記録されます

**所要時間：**

* ターゲットがマークされている場合：10～60秒
* ターゲットがマークされていない場合：5～30分以上（すべての画像をスキャンするため）

**進行状況インジケーター：**

* 検出中：0% → 100%
* スキャンされた画像数（実際にスキャンされた画像のみをカウント）
* 検出されたターゲットの数

**確認事項：**

* ターゲットが適切にマークされていれば、短時間で完了するはずです
* 処理に時間がかかりすぎる場合は、ターゲットがマークされていない可能性があります
* デバッグログで「Target found」というメッセージを確認してください

### ステージ2：解析

**処理内容：**

* 画像のEXIFメタデータ（タイムスタンプ、露出設定）を読み込み
* ターゲットのタイムスタンプと利用可能なDAQダウンウェルデータに基づいて、キャリブレーション戦略を決定
* 画像処理キューを整理
* 並列処理ワーカーを準備 （Chloros

+ のみ）

**所要時間：** 5～30秒**進行状況インジケーター：**

* 分析中：0% → 100%
* 処理が速く、通常はすぐに完了します

**注意すべき点：**

* 中断することなく着実に進行するはず
* メタデータが欠落している場合の警告がデバッグログに表示される

### ステージ3：キャリブレーション

**処理内容：*** **デベイヤー処理**：RAWベイヤーパターンを3チャンネルに変換（LATTICEモノクロモジュールでは、注記付きでスキップされる）
* **ヴィネット補正**：レンズの周辺部の暗さを除去
* **反射率キャリブレーション**：目標値および／またはDAQダウンウェリングを用いて正規化
* **インデックス計算**：マルチスペクトルインデックスの算出
* 各画像をパイプライン全体で処理

**所要時間：** 処理時間全体の大部分（60～80%）**進行状況インジケーター：**

* キャリブレーション中：0% → 100%
* 現在処理中の画像
* 処理完了した画像数 / 画像総数

**処理の動作：*** **フリーモード**：1枚ずつ順次画像を処理
* **Chloros

+モード**：ハードウェアに適応するワーカープールを稼働 — GPUシステムでは（VRAMに応じて）1～4つのワーカーを並行実行、CPUのみのシステムでは物理コア数（1を差し引いた数）分のワーカーを並行実行。詳細は [動的演算適応](../processing-architecture/dynamic-compute-adaptation.md)
* **GPU アクセラレーション**：この段階の処理を大幅に高速化します**確認事項：**

* 画像数の推移が安定しているか
* デバッグログで、画像ごとの完了メッセージを確認してください
* 画像品質やキャリブレーションの問題に関する警告

### ステージ4：エクスポート

**処理内容：**

* 処理が完了した画像を、選択された形式でディスクに書き込みます
* **LATTICE**：各フレームは、有効になっているすべてのプロダクト（デベイヤー／プレビュー／ラディアンス／反射率）に展開されます
* LUT カラーを使用したマルチスペクトルインデックス画像のエクスポート
* 出力ツリー `<project>/<camera>/<format>/<Product>_Images/` の作成 — エクスポートされたファイルはソースファイル名を保持し、フォルダ名がプロダクトを識別します

**所要時間：** 処理時間全体の 10～20%**進行状況インジケーター：**

* エクスポート中：0% → 100%
* ファイルの書き込み中
* エクスポート形式と保存先

**注意すべき点：**

* ディスク容量不足の警告
* ファイル書き込みエラー
* 設定されたすべての出力の完了

## [デバッグログ] タブ

[デバッグログ] には、処理の進捗状況や発生した問題に関する詳細情報が表示されます。バックエンドの起動メッセージもログコンソールに記録されるため、後からログを開いた場合でも、処理の全容を把握できます。

### デバッグログへのアクセス

1. 左サイドバーの **デバッグログ** <img src="../.gitbook/assets/icon_log.JPG" alt="" data-size="line">

アイコンをクリックします
2. リアルタイムの処理メッセージを表示するログパネルが開きます
3. 最新のメッセージを表示するために自動的にスクロールします

### ログメッセージの理解

Chloros

のログ行には、サブシステム名を表す角括弧で囲まれたタグが先頭に付きます。例えば、`[PROCESSING]`、`[RUN-SUMMARY]`、`[LATTICE-EXPORT]`、 `[EXPORT-CHECK]`、`[IMPORT-LEVEL]`などです。知っておくべき最も重要なものは、すべての実行（停止した実行を含む）の最後に表示される**実行概要**です：

```
[RUN-SUMMARY] 49 image(s) in 2 camera group(s); 4 target(s) detected; 45 image(s) calibrated; 180 file(s) written.
```

説明が必要な場合（例えば、何も生成されなかった実行や、 、または要求されたプロダクトが適用不可としてスキップされたカメラなどです。`[EXPORT-CHECK]`行は、カメラごとのスキップについて説明しています（例：RGB

カメラが放射輝度プロダクトを取得できなかった理由など）。

メッセージの一般的な重大度（以下の例は説明用であり、文字通りの引用ではありません）：

#### 情報メッセージ（白／灰色）

通常の処理状況の更新：処理開始、ターゲットの検出（パネル数を含む）、画像ごとのキャリブレーションの進捗、ファイルのエクスポート、処理完了。

#### 警告メッセージ（黄色）

処理を停止させない非重大な問題 — 例：フレーム内のGPSデータの欠落、ターゲット画像間のタイムスタンプの大きなずれ、またはキャリブレーションパネルのコントラストが低い場合など。

**対応：** 処理後に警告を確認しますが、処理を中断しないでください

#### エラーメッセージ（Red

）

処理の失敗につながる可能性のある重大な問題 — 例：ディスク容量不足、画像ファイルの破損、反射率キャリブレーションが要求された際にターゲットが検出されなかった場合など。

**対応：** 処理を停止し、エラーを解決してから再起動してください

### よくあるログの状況

| 状況                             | 意味                                       | 必要な対応                                         |
| ------------------------------------- | --------------------------------------------- | ----------------------------------------------------- |
| \[ファイル名\]でターゲットを検出しました        | キャリブレーションターゲットが正常に検出されました         | なし - 正常                                         |
| 画像ごとの進行状況バー              | 現在の進行状況の更新                       | なし - 正常                                         |
| ターゲットが見つかりません                      | キャリブレーションターゲットが検出されませんでした               | ターゲット画像にマークを付けるか、反射率キャリブレーションを無効にする |
| ディスク容量不足               | 出力用のストレージ容量が不足しています                 | ディスクの空き容量を確保してください                                    |
| 破損したファイルをスキップ               | 画像ファイルが破損しています                         | SDカードからファイルを再コピーしてください                             |
| `[IMPORT-LEVEL] Skipping ... no raw source` | RAWフレームのないキャプチャは処理できません | RAWを含む状態で再キャプチャするか、 またはCLI

を使用してください `--input-level`  |
| `[RUN-SUMMARY] ... 0 file(s) written` | 実行の結果、画像プロダクトが生成されませんでした — ヒント付きの失敗として報告されました | ヒントの行を読み、何がスキップされたか、その理由を確認してください |
| `[PROCESS] refused: The project folder is too deep for this computer…` | Windows

の長いパス設定がオフになっており、プロジェクトフォルダのパスが260文字の制限を超えて深すぎるため、何も処理されませんでした | より短いプロジェクトフォルダを使用してください （メッセージには収まる最長のパスが表示されています）、またはWindows

の長いパスを有効にしてChloros

を再起動してください — [処理の開始](starting-the-processing.md#the-project-folder-is-too-deep-for-this-computer)を参照 |
| `[unmix-clamp-mask] …` | LATTICE製品のクランプマスクを書き込めませんでした。製品自体に問題はなく、`Chloros:UnmixClampMask=unavailable`と表示されています | ディスク容量とフォルダのアクセス権を確認し、マスクが必要な場合は再処理を行ってください |

### ログデータのコピー

トラブルシューティングやサポートのためにログをコピーするには：

1. [デバッグログ] パネルを開きます
2. **[コピー]**ボタン（ログをクリップボードにコピーします）をクリックするか、**[ダウンロード]** をクリックしてテキストファイルとして保存します
3. テキストファイルに貼り付けるか、メールに添付します
4. 必要に応じてMAPIR

サポートへ送信してください

### ログタブからのバグ報告

バージョン1.3.0の新機能：デバッグログタブ上部のバグアイコン（**バグを報告**）をクリックすると、MAPIR

に直接レポートが送信されます。

1. デバッグログタブ上部のバグアイコンをクリックします
2. 問題の詳細を記述してください：何を行っていたか、どのような動作を期待していたか、そして実際には何が起きたか（必須）
3. 必要に応じて **画像を数枚追加（最大10枚）**にチェックを入れ、開いているプロジェクトから画像を選択するか、**参照...** を使用して他の画像ファイルを選択してください
4. **送信** をクリックしてください

レポートには、説明文、添付した画像、Chloros

のログ、およびシステムの詳細（Chloros

のバージョン、OS、GPU、プロジェクト設定）が含まれます。レポートを送信するには、Chloros

にサインインしている必要があります（「ユーザー」タブ）。送信中はウィンドウを閉じても構いません。 送信が完了すると、`Bug report sent. Reference: BR-…` のような参照番号がログに記録されます。MAPIR

に連絡する際は、この番号を引用してください。レポートをアップロードできない場合 （例：インターネット接続がない場合など）、Chloros

はレポートをお使いのコンピュータに保存し、そのパスを表示しますので、support@mapir.camera宛てにメールで送信してください。

## システムリソースの監視

### CPU使用率

**フリーモード：**

* 1つのCPUコアが約100%で稼働
* 他のコアはアイドル状態または利用可能
* システムは応答性を維持

**「Chloros

+ 並列モード」:**

* 複数のコアが高利用率で稼働 — コア数は[動的演算適応](../processing-architecture/dynamic-compute-adaptation.md)で選択された戦略によって異なります
* システムの応答性が低下しているように感じられる場合があります

**監視方法：**

* Windows

タスク マネージャー (Ctrl+Shift+Esc)
* [パフォーマンス] タブ → [CPU] セクション
* 「Chloros

」または「chloros-backend」というプロセスを探してください

### メモリ (RAM) 使用率

**一般的な使用量：**

* 小規模なプロジェクト（100 画像未満）：2～4 GB
* 中規模なプロジェクト（100～500 画像）：4～8 GB
* 大規模なプロジェクト（500 画像以上）：8～16 GB
* 「Chloros

+」の並列モードでは、より多くの RAM を消費します

**メモリが不足している場合：**

* 処理するバッチのサイズを小さくする
* 他のアプリケーションを閉じる
* 定期的に大規模なデータセットを処理する場合は、RAMを増設する

### GPU使用量（CUDA対応のChloros

+）

GPUアクセラレーションが有効な場合：

* NVIDIA GPUの使用率が上昇する（60～90%）
* VRAMの使用量が増加します（4GB以上のVRAMが必要；Texture Awareデベイヤー処理を同時実行する場合は7GB以上）
* キャリブレーション段階の処理が大幅に高速化されます

**監視方法：**

* NVIDIAのシステムトレイアイコン
* タスクマネージャー → パフォーマンス → GPU
* GPU-Zなどの監視ツール

### ディスク I/O

**予想される動作：**

* 「分析」段階ではディスクの読み取りが活発になります
* 「エクスポート」段階ではディスクへの書き込みが活発になります
* SSD は HDD よりも大幅に高速です

**パフォーマンスのヒント：**

* 可能であれば、プロジェクトフォルダにはSSDを使用してください
* 大容量のデータセットでは、ネットワークドライブの使用を避けてください
* ディスクの空き容量が不足していないことを確認してください（書き込み速度に影響します）

## 処理中の問題の検出

### 警告サイン

**進行状況が停滞する（5分以上変化がない場合）：**

* デバッグログでエラーを確認する
* 空きディスク容量を確認する
* タスクマネージャーでChloros

が実行中であることを確認する

**エラーメッセージが頻繁に表示される場合：**

* 処理を停止し、エラー内容を確認する
* 一般的な原因：ディスク容量不足、ファイルの破損、メモリの問題
* 以下の「トラブルシューティング」セクションを参照

**システムが応答しなくなる場合：**

* Chloros

+の並列モードがリソースを過剰に消費している
* 同時実行タスクの削減またはハードウェアのアップグレードを検討してください
* フリーモードの方がリソース消費が少ない

### 処理を停止すべき場合

以下の現象が見られた場合は、処理を停止してください：

* ❌ 「ディスク容量不足」または「ファイルへの書き込み不可」エラー
* ❌ 画像ファイルの破損エラーが繰り返し発生する
* ❌ システムが完全にフリーズした（応答なし）
* ❌ 誤った設定が行われていたことに気づいた
* ❌ 誤った画像がインポートされた

**停止方法：**

1.**停止ボタン**（「開始」ボタンの代わりに表示されます）をクリックします。1回クリックすれば十分です
2. 処理中のイメージが完了するまで、プログレスバーに「停止中...」と表示され、その後、実行は停止状態で終了します
3. すでにエクスポートされた成果物はディスク上に残ります。ログには、完了した処理内容を示す「`[RUN-SUMMARY]`」という正確なメッセージが出力されます
4. 問題を修正して再起動してください。実行は最初から再開されます

## 処理中のトラブルシューティング

### 処理が非常に遅い

**考えられる原因：**

* ターゲット画像にマークが付いていない（すべての画像をスキャンしている）
* SSDではなくHDDを使用している
* システムリソースが不足している
* 設定されたインデックスが多い
* ネットワークドライブへのアクセス

**解決策：**

1. 処理を開始したばかりで「検出中」の段階の場合：停止し、ターゲットをマークしてから再起動する
2. 今後の対策：SSDを使用する、インデックス数を減らす、ハードウェアをアップグレードする
3. 大規模なデータセットのバッチ処理にはCLI

の利用を検討する

### 「ディスク容量」に関する警告

**解決策：**

1. 直ちにディスク容量を空ける
2. プロジェクトを空き容量の多いドライブに移動する
3. エクスポートするインデックスの数を減らす
4. 不要なLATTICEエクスポート製品を無効にする（プロジェクト設定 → 処理）
5. TIFF

の代わりにJPG形式を使用する（ファイルサイズが小さくなる）

### 「ファイルが破損しています」というメッセージが頻繁に表示される

**解決策：**

1. 画像をSDカードから再度コピーし、整合性を確認する
2. SDカードにエラーがないか確認する
3. プロジェクトから破損したファイルを削除する
4. 残りの画像の処理を続行する

### システムの過熱／スロットリング

**解決策：**

1. 十分な換気を確保する
2. コンピュータの通気口からほこりを除去する
3. 処理負荷を軽減する（Chloros

+ の代わりに Free モードを使用する）
4. 1日のうち比較的涼しい時間帯に処理を行う

## 処理完了の通知

処理が完了すると：

* 進行状況バーが 100% に達する
* デバッグログに、最終カウントを含む「`[RUN-SUMMARY]`」という行が表示される
* 「開始」ボタンが再び有効になる
* すべての出力ファイルが、プロジェクト内のカメラごとの出力ツリー（`<project>/<camera>/<format>/<Product>_Images/`）に保存される

***

## 次の手順

処理が完了したら：

1. **結果の確認** - [処理の完了](finishing-the-processing.md)を参照してください
2. **出力フォルダの確認** - すべてのファイルが正しくエクスポートされていることを確認してください
3. **デバッグログの確認** - 警告やエラーがないか確認してください
4. **処理済み画像のプレビュー** - 画像ビューアまたは外部ソフトウェアを使用してください

処理結果の確認および使用方法については、[処理の完了](finishing-the-processing.md)を参照してください。
