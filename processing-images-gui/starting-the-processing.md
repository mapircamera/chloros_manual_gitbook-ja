# 処理の開始

画像のインポート、キャリブレーションターゲットのマーク付け、プロジェクト設定の完了後、処理を開始する準備が整います。このページでは、Chlorosの処理パイプラインを開始する手順を説明します。

## 処理前の確認事項

「開始」ボタンをクリックする前に、すべての準備が整っていることを確認してください：

* [ ] **ファイルがインポート済み** - すべての画像がファイルブラウザに表示されている
* [ ] **ターゲット画像がマーク済み** - キャリブレーション画像の「ターゲット」列にチェックが入っている（または、LATTICE用に`.daq`の記録がインポートされている）
* [ ] **カメラモデルが検出済み** - 「カメラモデル」列に正しいカメラが表示されている
* [ ] **設定が完了** - プロジェクト設定を確認・調整済み
* [ ] **インデックスが選択済み** - 必要なマルチスペクトルインデックスが追加されている（必要な場合）
* [ ] **エクスポート形式が選択済み** - ワークフローに適した出力形式が設定されています

{% hint style="info" %}
**ヒント**: 処理を開始する前に、ファイルブラウザでいくつかの画像をクリックして、正しく読み込まれていることを確認してください。
{% endhint %}

***

## 処理の開始

### 「開始」ボタンの場所

「開始/再生」ボタンは、Chlorosの上部ヘッダーバーにあります：

* 位置：ウィンドウの上部中央
* アイコン：**再生/開始ボタン** <img src="../.gitbook/assets/image (2) (1) (1).png" alt="" data-size="line">
* 状態：処理の準備が整うと、ボタンが有効（明るく表示）になります

### クリックして開始

1. 上部のヘッダーにある **再生/開始ボタン** をクリックします
2. 処理が直ちに開始されます
3. 処理中は、ボタンが **停止** ボタンに変わります
4. 進行状況バーが更新され、処理状況が表示されます

{% hint style="success" %}
**処理開始**：クリックすると、Chlorosがターゲット検出、デベイヤー処理、キャリブレーション、インデックス計算、エクスポートといったすべての処理ステップを自動的に実行します。プロジェクトがSurvey3、LATTICE、またはその混合であるかを自動検出し、各カメラに適切なパイプラインを適用します。
{% endhint %}

## 処理モードについて

Chlorosは、ライセンスに応じて2つの異なる処理モードで動作します：

### 無料モード（順次処理）

**すべてのユーザーが利用可能**

**動作方法：**

* 画像を1枚ずつ順次処理します
* シングルスレッドでの動作
* メモリ使用量が少ない

**進行状況バーには2つの段階が表示されます：**

1.**ターゲット検出** - キャリブレーションターゲットのスキャン
2. **処理** - キャリブレーションの適用と画像のエクスポート**処理時間：**

* Chloros+の並列モードに比べて大幅に遅い
* 中小規模のデータセット（200枚未満）に適している

### Chloros+モード（並列処理）

**Chloros+ライセンスが必要**

**動作原理：**

* [4スレッド処理パイプライン](../processing-architecture/processing-pipeline.md) を使用して、複数の画像を同時に処理します
* [動的演算適応](../processing-architecture/dynamic-compute-adaptation.md) により、実行開始時にハードウェアに最適な戦略が自動的に選択されます
* NVIDIAグラフィックカードによるGPU（CUDA）アクセラレーション
* **ワーカー数はハードウェアに応じて動的に調整されます**：GPU戦略では**2～4つのワーカーを同時に実行**します（VRAM容量に応じてスケーリングされます — 2～12GBのGPUでは3つ、12GB以上のGPUでは2～4つ）； CPUのみのシステムでは、物理コア数から1を引いた数のワーカーが実行されます**進行状況バーには4つの段階が表示されます**（4つのパイプラインスレッドに対応）：

1. **検出**（スレッド1） - キャリブレーション対象の検出
2. **分析**（スレッド2） - 画像メタデータの検証とキャリブレーションの計算
3. **キャリブレーション**（スレッド3） - デベイヤー処理、ヴィネット補正、キャリブレーション、インデックス計算
4. **エクスポート**（スレッド4） - 処理済み画像とインデックスの保存

**進行状況バーの操作方法：**

* バーに**マウスをホバー**させると、4つの段階の詳細が表示されるドロップダウンパネルが表示されます
* 進行状況バーを**クリック**すると、ドロップダウンパネルが固定されます
* **もう一度クリック**すると、固定が解除され、パネルが非表示になります**処理時間：**

* 無料モードよりも大幅に高速
* GPUアクセラレーションによりさらに処理速度が向上

{% hint style="info" %}
**Chloros+の速度**：大規模なデータセットの場合、並列処理は順次処理モードに比べて5～10倍高速になることがあります。無料モードで2時間かかる500枚の画像プロジェクトも、Chloros+を使用すれば15～20分で完了する可能性があります。
{% endhint %}

## 処理中の流れ

### ステージ1：ターゲット検出

**Chlorosの動作：**

* 「ターゲット」列でチェックした画像をスキャンします（チェックされていない場合は全画像をスキャンします）
* 各ターゲット内のキャリブレーションパネルを識別します
* ターゲットパネルから反射率値を抽出します
* キャリブレーションのスケジュール設定のために、ターゲットのタイムスタンプを記録します

**所要時間：** 1～30秒（ターゲットがマークされている場合）、5～30分以上（マークされていない場合）

### ステージ2：デベイヤー処理（RAW変換）

**Chlorosの処理内容：**

* RAWのベイヤーパターンデータを完全な3チャンネル画像に変換します（LATTICEモノクロモジュールはシングルバンドのままとなります。これらについてはデベイヤー処理がスキップされ、ログに注記が記録されます）
* 選択されたデモザイクアルゴリズムを適用します
* 画像の品質とディテールを最大限に維持します

**所要時間：** 画像数およびCPU/GPUの速度によって異なります

### ステージ3：キャリブレーション

**Chlorosの処理内容：**

* **ヴィネット補正**：画像の端部におけるレンズの暗さを除去します
* **反射率キャリブレーション**：ターゲット反射率値および／またはDAQのダウンウェルデータを使用して正規化します
* すべてのバンド／チャンネルに補正を適用します
* タイムスタンプに基づいて、各画像に適切なキャリブレーション基準を使用します

**所要時間：** 処理時間の大部分を占めます

### ステージ4：インデックス計算

**Chlorosの処理内容：**

* 設定されたマルチスペクトルインデックス（NDVI、NDREなど）を計算
* キャリブレーション済みの画像にバンド演算を適用
* 選択された各インデックスに対応するインデックス画像を生成

**所要時間：** 画像1枚あたり数秒

### ステージ 5：エクスポート

**Chloros の処理内容：**

* 処理済みの画像を選択した形式で保存
* **LATTICE ファンアウト**：各生の LATTICE フレームを、有効化されたすべてのプロダクトとして 1 回の処理でエクスポート — デベイヤー処理済み、プレビュー、放射輝度（常に float32）、反射率
* ファイルをプロジェクト出力ツリー（`<project>/<camera>/<format>/<Product>_Images/`）に書き込みます
* **ソースファイル名を保持** — フォルダ名がプロダクトを識別するため、接尾辞は追加されません**所要時間：** エクスポート形式およびファイルサイズによって異なります***

## 処理の動作

### 自動処理パイプライン

一度開始されると、パイプライン全体が自動的に実行されます：

* ユーザーの操作は不要
* 設定されたすべてのステップが順番に実行される
* 進行状況がリアルタイムで表示される
* エクスポートされたファイルは完了次第ディスクに書き込まれる — 処理が継続中でも、完了した出力ファイルを開くことができる

### 処理中のコンピュータ使用状況

**フリーモード：**

* CPU 使用率は比較的低い（シングルスレッド）
* 他のタスクでもコンピュータはスムーズに動作する
* Chloros を最小化して、他のアプリケーションで作業しても問題ない

**Chloros+ 並列モード：**

* 戦略のワーカープール全体でCPU使用率が高くなります
* GPUアクセラレーション使用時：GPU使用率が高くなります
* 処理中はコンピュータの応答性が低下する可能性があります
* 他のCPU負荷の高いタスクの起動は避けてください

{% hint style="warning" %}
**パフォーマンスのヒント**：Chloros+のパフォーマンスを最大限に引き出すには、他のアプリケーションを閉じて、Chlorosがシステムリソースをフルに活用できるようにしてください。
{% endhint %}

### 処理を一時停止することはできません（ただし、停止は正常に行われます）

* 一度開始した処理は、一時停止して後で再開することはできません
* **停止**をクリックすると、最初のクリックで実行が正常に終了します
* 停止前にすでにエクスポートされた出力データはディスク上に残ります
* 停止された実行は、完了した内容を正確に報告します（ログ内の `[RUN-SUMMARY]` の行を参照）
* 新しい実行を開始すると、パイプラインは最初から再開されます

**計画のヒント：** 非常に大規模なプロジェクトの場合は、バッチ処理を行うか、より詳細な制御のためにCLIを使用することを検討してください。***

## 処理の監視

処理の実行中は、以下の操作が可能です：

* **進行状況バーの確認** - 全体の完了率を確認できます
* **現在のステージの確認** - 検出、分析、キャリブレーション、またはエクスポート
* **ログタブの確認** - 詳細な処理メッセージや警告を確認できます
* **完了した画像のプレビュー** - エクスポートされたファイルは処理中にディスク上に表示されます

モニタリングに関する詳細については、[処理のモニタリング](monitoring-the-processing.md)を参照してください。

## 処理の中止

処理を中止する必要がある場合は、以下の手順に従ってください：

### 中止方法

1. **停止ボタン**を探します （処理中は「開始」ボタンに代わって表示されます）
2. 1回クリックします。処理中の画像の処理が完了するまで、バーに **「停止中...」** と表示されます
3. 処理は完全に停止した状態で終了し、ログには完了した内容に関する正確な `[RUN-SUMMARY]` が出力されます

### 停止すべき場合

**停止が妥当な理由：**

* 誤った設定が使用されていたことに気づいた場合
* 対象画像のマーク付けを忘れた場合
* 間違った画像をインポートしてしまった場合
* システムの動作が遅すぎる、または応答しなくなった場合

**停止後：**

* 停止前にエクスポートされた成果物はディスク上に残ります
* 問題を確認・修正し、必要に応じて設定を調整する
* 処理を再開する — 実行は最初から開始される

## 処理時間の目安

実際の処理時間は、以下の要因によって大きく異なります：

* 画像の数
* 画像の解像度
* 入力形式（RAW または JPG）
* 処理モード （Free または Chloros+）
* CPUの速度とコア数
* GPUの利用可否（Chloros+のみ）
* 計算するインデックスの数
* 有効化されているエクスポート製品の数（LATTICE）

### おおよその目安（Chloros+、12MP画像、最新CPU）

| 画像数 | 無料モード | Chloros+ (CPU) | Chloros+ (GPU) |
| ----------- | --------- | -------------- | -------------- |
| 50 画像   | 15～20 分 | 5～8 分        | 3～5 分        |
| 100 画像  | 30～40 分 | 10～15 分      | 5～8 分        |
| 200 画像  | 1～1.5 時間 | 20～30 分      | 10～15 分      |
| 500 画像  | 2～3 時間   | 45～60 分      | 20～30 分      |
| 1000 画像 | 4～6 時間   | 1.5～2 時間      | 40～60 分      |

{% hint style="info" %}
**初回実行**：Chlorosがキャッシュやプロファイルを構築するため、初期処理には時間がかかる場合があります。同様のデータセットを再度処理する際は、処理速度が向上します。
{% endhint %}

## 起動時の一般的な問題

### 開始ボタンが使用不可（グレー表示）

**考えられる原因：**

* 画像がインポートされていない
* バックエンドが完全に起動していない
* 前回の処理がまだ実行中である
* プロジェクトが完全に読み込まれていない

**解決策：**

1. バックエンドが完全に初期化されるまで待つ（メインメニューのアイコンを確認）
2. ファイルブラウザで画像がインポートされていることを確認する
3. ボタンが依然として無効な場合は、Chlorosを再起動する
4. デバッグログでエラーメッセージを確認する

### 処理が開始された直後に失敗する

**考えられる原因：**

* プロジェクトに有効な画像がない
* 画像ファイルが破損している
* ディスク容量が不足している
* メモリ（RAM）が不足している

**解決策：**

1. デバッグログ<img src="../.gitbook/assets/icon_log.JPG" alt="" data-size="line">でエラーメッセージを確認する
2. 空きディスク容量を確認する
3. 画像のサブセット（少量）を処理してみる
4. 画像が破損していないことを確認する

### 実行は完了したが、画像が書き込まれない

画像プロダクトを要求したにもかかわらず、何も書き込まれなかった実行は、**成功ではなく失敗**として扱われます。Chlorosはこれを明確に報告します：

* GUIログには、`[RUN-SUMMARY]`というヒントが表示され、考えられる原因が示されます。具体的には、画像がインポートされていない、ターゲットが検出されていない、または要求されたすべてのプロダクトが適用不可としてスキップされた場合などです（例：RGB専用カメラから放射輝度/反射率を要求した場合など）
* CLI での同等のエラー (`chloros-cli process`) は、`Processing finished but wrote no image products.` を出力し、**非ゼロで終了**するため、スクリプトでこれを検出できます
* 意図的にメタデータのみを生成する実行（すべてのエクスポートプロダクトを無効化し、インデックスも生成しない）は、依然として成功とみなされます

完全な意味論については、[CLIリファレンス](../reference/cli-reference.md#a-run-that-writes-no-images-fails)を参照してください。

### このコンピュータではプロジェクトフォルダの階層が深すぎる

**Windowsのみ、1.3.0で追加。** Windowsでは、長パスがデフォルトで無効化されており、ファイルパスは260文字を超えてはなりません。Chloros製品はプロジェクトフォルダから最大約130文字下の階層に配置されるため、それより深い階層にあるプロジェクトフォルダには製品が配置されません。実行しても何も書き込まれない状態になるのを防ぐため、Chlorosでは処理開始前に以下のチェックを行うようになりました：

* [Start] をクリックしても実行は開始されません： 進行状況バーに理由が表示され、デバッグログには「`[PROCESS] refused: The project folder is too deep for this computer…`」と記録されます。メッセージには、プロジェクトフォルダの長さと、収まる最長のプロジェクトフォルダ名が示されます。
* プロジェクト自身のファイルでさえ収まらないほど深いフォルダ内でのプロジェクトの作成や開く操作も拒否されます。 メッセージボックスには、その理由と、収まる最長のプロジェクトフォルダ名、および長いパスを有効にする方法が示され、何も作成・開かれません。 デバッグログには `[PROJECT] refused: …` として記録されます。より長い名前でプロジェクトを複製する場合も、制限を超える可能性があります：コピーは作成されますが開くことはできず、同じメッセージで理由が示されます。

**解決策：**

1. プロジェクトを短いフォルダ内に保存する — [プロジェクト設定](../project-settings/project-settings.md) で**作業ディレクトリ** を変更し、プロジェクトを再作成するか、
2. Windowsの長いパスを有効にしてChlorosを再起動する：**「Windowsの長いパスを有効にする」**にチェックを入れた状態でChlorosインストーラーを再実行するか（デフォルトでチェックされています）、グループポリシーを使用します：*コンピューターの構成 > 管理用テンプレート > システム > ファイルシステム > Win32の長いパスを有効にする*。

### 「ターゲットが検出されませんでした」という警告

**考えられる原因：**

* ターゲット画像のマーク付けを忘れた
* ターゲット画像に視認可能なターゲットが含まれていない
* ターゲット検出の設定が厳しすぎる

**解決策：**

1. [ターゲット画像の選択](choosing-target-images.md)
2. [ターゲット] 列で適切な画像にマークを付ける
3. マークした画像内でターゲットが視認できることを確認する
4. 必要に応じてターゲット検出設定を調整する

## 処理を成功させるためのヒント

### 開始前に

1. **まず少量の画像でテストする** - 10～20枚の画像を処理して設定を確認する
2. **利用可能なディスク容量を確認する** - データセットサイズの2～3倍の空き容量を確保する（すべてのLATTICE製品を有効にしている場合はさらに多く必要）
3. **不要なアプリケーションを閉じる** - システムリソースを解放する
4. **ターゲット画像を確認する** - マークされたターゲットをプレビューして品質を確認する
5. **プロジェクトを保存する** - プロジェクトは自動保存されますが、手動で保存することをお勧めします

### 処理中

1. **システムのスリープを回避する** - 省電力モードを無効にする
2. **Chlorosをフォアグラウンドに保つ** - 少なくともタスクバーに表示された状態にする
3. **進行状況を時々確認する** - 警告やエラーがないか確認する
4. **他の負荷の高いアプリケーションを起動しない** - 特にChloros+の並列モード使用時は注意

### Chloros+ の GPU アクセラレーション

NVIDIA の GPU アクセラレーションを使用する場合：

1. NVIDIA ドライバーを最新バージョンに更新する
2. GPU の VRAM が 4GB 以上あることを確認する（Texture Aware デベイヤー処理を同時実行する場合は 7GB 以上）
3. GPU を大量に消費するアプリケーション（ゲーム、動画編集など）を閉じる
4. GPU の温度を監視する （十分な冷却を確保してください）
