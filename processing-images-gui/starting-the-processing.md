# 処理の開始

画像のインポート、キャリブレーションターゲットの指定、プロジェクト設定の完了後、処理を開始する準備が整います。このページでは、Chloros 処理パイプラインの起動手順について説明します。

## 処理前の確認事項

[開始] ボタンをクリックする前に、すべての準備が整っていることを確認してください：

* [ ] **ファイルのインポート完了** - すべての画像がファイルブラウザに表示されている
* [ ] **ターゲット画像のマーク付け完了** - キャリブレーション画像の「ターゲット」列にチェックが入っている （または、LATTICE用にインポートされた`.daq`記録）
* [ ] **カメラモデルが検出済み** - 「カメラモデル」列に正しいカメラが表示されている
* [ ] **設定が完了** - プロジェクト設定を確認・調整済み
* [ ] **インデックスが選択済み** - 必要なマルチスペクトルインデックスが追加されています（必要な場合）
* [ ] **エクスポート形式が選択済み** - ワークフローに適した出力形式が設定されています

{% hint style="info" %}
**ヒント**：処理を開始する前に、ファイルブラウザでいくつかの画像をクリックして、正しく読み込まれていることを確認してください。
{% endhint %}

***

## 処理の開始

### [Start] ボタンの場所

「開始／再生」ボタンは、Chlorosの上部ヘッダーバーにあります：

* 位置：ウィンドウの上部中央
* アイコン：**再生／開始ボタン** <img src="../.gitbook/assets/image (2) (1) (1).png" alt="" data-size="line">
* 状態：処理の準備が整うと、ボタンが有効（明るく表示）になります

### クリックして開始

1. 上部のヘッダーにある**再生/開始ボタン**をクリックします
2. 処理が直ちに開始されます
3. 処理中は、ボタンが**停止**ボタンに変わります
4. 進行状況バーが更新され、処理状況が表示されます

{% hint style="success" %}
**処理開始**：クリックすると、Chlorosが、ターゲット検出、デベイヤー処理、キャリブレーション、インデックス計算、エクスポートといったすべての処理ステップを自動的に実行します。 プロジェクトが Survey3、LATTICE、またはその混合であるかを自動検出し、各カメラに適切なパイプラインを適用します。
{% endhint %}

## 処理モードについて

Chlorosは、ライセンスに応じて2つの異なる処理モードで動作します：

### 無料モード（順次処理）

**すべてのユーザーが利用可能**

**動作原理：**

* 画像を1枚ずつ順次処理します
* シングルスレッドでの動作
* メモリ使用量が少ない

**進行状況バーには2つの段階が表示されます：**

1.**ターゲット検出** - キャリブレーションターゲットをスキャン
2. **処理** - キャリブレーションを適用し、画像をエクスポート**処理時間：**

* Chloros+の並列モードに比べて大幅に遅くなります
* 小規模から中規模のデータセット（200画像未満）に適しています

### Chloros+モード（並列処理）

**Chloros+ ライセンスが必要です**

**動作原理：**

* [4スレッド処理パイプライン](../processing-architecture/processing-pipeline.md) を使用して、複数の画像を同時に処理します
* [動的演算適応機能](../processing-architecture/dynamic-compute-adaptation.md)により、実行開始時にハードウェアに最適な戦略が自動的に選択されます
* NVIDIAグラフィックスカード（デスクトップおよびJetson）によるGPU（CUDA）アクセラレーション
* **ワーカー数はハードウェアに応じて適応**：GPU戦略では**1～4つのワーカーを並行実行**（VRAM容量に応じてスケーリングされます。メモリ容量の少ないJetsonでは1つ、12GB以上のデスクトップGPUでは最大4つを実行）。CPUのみのシステムでは、物理コア数から1を引いた数のワーカーを実行します**進行状況バーには4つの段階が表示されます**（4つのパイプラインスレッドに対応）：

1. **検出**（スレッド1） - キャリブレーション対象の検出
2. **分析**（スレッド2） - 画像メタデータの検証とキャリブレーションの計算
3. **キャリブレーション**（スレッド3） - デベイヤー処理、ヴィネット補正、キャリブレーション、インデックス計算
4. **エクスポート**（スレッド4） - 処理済み画像とインデックスの保存**プログレスバーの操作方法：*** バーに**マウスをホバー**すると、4つの段階の詳細が表示されるドロップダウンパネルが表示されます
* プログレスバーを**クリック**すると、ドロップダウンパネルが固定されます
* **もう一度クリック**すると、固定が解除され、パネルが非表示になります**処理時間：**

* 無料モードよりも大幅に高速
* GPU アクセラレーションによりさらに速度が向上

{% hint style="info" %}
**Chloros+ の速度**：大規模なデータセットの場合、並列処理により逐次モードよりも 5～10 倍高速になります。 無料モードで2時間かかる500枚の画像プロジェクトも、Chloros+を使用すれば15～20分で完了する可能性があります。
{% endhint %}

## 処理中の動作

### ステージ1：ターゲット検出

**Chlorosの動作：**

* 「ターゲット」列でチェックした画像をスキャンします（チェックされていない場合はすべての画像をスキャンします）
* 各ターゲット内のキャリブレーションパネルを識別
* ターゲットパネルから反射率値を抽出
* キャリブレーションのスケジュール設定のためにターゲットのタイムスタンプを記録

**所要時間：** 1～30秒（ターゲットがマークされている場合）、5～30分以上（マークされていない場合）

### ステージ2：デベイヤー処理 （RAW変換）

**Chlorosの機能：**

* RAWのベイヤーパターンデータを完全な3チャンネル画像に変換します（LATTICEモノクロモジュールは単一バンドのままとなります。これらについてはデベイヤー処理がスキップされ、ログに注記されます）
* 選択されたデモザイクアルゴリズムを適用します
* 画像の品質とディテールを最大限に維持します

**所要時間：** 画像数およびCPU/GPUの速度によって異なります

### ステージ3：キャリブレーション

**Chlorosの機能：*** **ヴィネット補正**：画像の周辺部におけるレンズの暗部を補正します
* **反射率キャリブレーション**：ターゲット反射率値および／またはDAQのダウンウェルデータを用いて正規化を行います
* すべてのバンド／チャンネルに補正を適用します
* タイムスタンプに基づいて、各画像に適切なキャリブレーション基準を使用します

**所要時間：** 処理時間の大部分を占める

### ステージ4：インデックス計算

**Chlorosの機能：**

* 設定されたマルチスペクトルインデックス（NDVI、NDREなど）を算出します
* キャリブレーション済みの画像にバンド演算を適用
* 選択された各インデックスに対応するインデックス画像を生成

**所要時間：** 画像1枚あたり数秒

### ステージ5：エクスポート

**Chlorosの機能：**

* 処理済みの画像を選択された形式で保存
* **LATTICE ファンアウト**：各生の LATTICE フレームは、有効化されたすべてのプロダクト（デベイヤー処理済み、プレビュー、放射輝度（常に float32）、反射率）として、1回の処理でエクスポートされます
* プロジェクトの出力ツリーにファイルを書き込みます：`<project>/<camera>/<format>/<Product>_Images/`
* **ソースファイル名を保持** — フォルダ名でプロダクトを識別するため、接尾辞は追加されません**所要時間：** エクスポート形式およびファイルサイズによって異なります***

## 処理の動作

### 自動処理パイプライン

開始されると、パイプライン全体が自動的に実行されます：

* ユーザーの操作は不要
* 設定されたすべてのステップが順番に実行される
* 進行状況がリアルタイムで表示される
* エクスポートされたファイルは完了次第ディスクに書き込まれる — 処理が継続中でも、完了した出力ファイルを開くことができる

### 処理中のコンピュータ使用状況

**フリーモード：**

* CPU 使用率が比較的低い （シングルスレッド）
* 他のタスクに対するコンピュータの応答性は維持されます
* Chlorosを最小化して、他のアプリケーションで作業しても問題ありません

**Chloros+ 並列モード：**

* 戦略のワーカープール全体でCPU使用率が高くなります
* GPUアクセラレーションを使用する場合：GPU使用率が高くなります
* 処理中はコンピュータの応答性が低下する可能性があります
* 他のCPU負荷の高いタスクの起動は避けてください

{% hint style="warning" %}
**パフォーマンスのヒント**：Chloros+のパフォーマンスを最大限に引き出すには、他のアプリケーションを閉じ、Chlorosがシステムリソースをフルに活用できるようにしてください。
{% endhint %}

### 処理を一時停止することはできません（ただし、正常に停止することは可能です）

* 一度開始した処理は一時停止して後で再開することはできません
* **停止**をクリックすると、最初のクリックで実行が正常に停止します
* 停止前にすでにエクスポートされた出力データはディスク上に残ります
* 停止された実行は、完了した内容を正確に報告します（ログ内の `[RUN-SUMMARY]` の行を参照）
* 新しい実行を開始すると、パイプラインは最初から再開されます

**計画上のヒント：** 非常に大規模なプロジェクトの場合は、バッチ処理を行うか、より詳細な制御のために CLI を使用することを検討してください。***

## 処理の監視

処理の実行中は、以下の操作が可能です：

* **進行状況バーの確認** - 全体の完了率を確認できます
* **現在のステージの確認** - 検出、解析、キャリブレーション、またはエクスポート
* **ログタブの確認** - 詳細な処理メッセージや警告を確認できます
* **完了した画像のプレビュー** - 処理中にエクスポートされたファイルがディスク上に表示されます

監視に関する詳細については、[処理の監視](monitoring-the-processing.md)を参照してください。

## 処理の中止

処理を停止する必要がある場合：

### 停止方法

1. **停止ボタン**（処理中は「開始」ボタンに置き換わります）を探します
2. ボタンを1回クリックします。進行状況バーに、処理中の画像の処理が完了するまで **「停止中....&quot;**と表示され、処理中の画像の処理が完了するまで待機します
3. 実行は確実に停止した状態で終了し、ログには完了した処理内容に関する正確な `[RUN-SUMMARY]` が出力されます

### 停止すべき場合

**停止すべき正当な理由：**

* 誤った設定が使用されていたことに気づいた場合
* 対象画像のマーク付けを忘れた場合
* 間違った画像をインポートしてしまった場合
* システムの動作が遅すぎる、または応答しなくなった場合

**停止後：**

* 停止前にエクスポートされた出力データはディスク上に残ります
* 問題を確認・修正し、必要に応じて設定を調整してください
* 処理を再開する — 実行は最初から再開されます

## 処理時間の目安

実際の処理時間は、以下の要因によって大きく異なります：

* 画像の数
* 画像の解像度
* 入力形式（RAW または JPG）
* 処理モード（Free または Chloros+）
* CPU の速度およびコア数
* GPU の利用可否（Chloros+ のみ）
* 計算するインデックスの数
* 有効になっているエクスポート製品の数（LATTICE）

### おおよその目安（Chloros+、12MP画像、最新CPU）

| 画像数 | 無料モード | Chloros+ (CPU) | Chloros+ (GPU) |
| ----------- | --------- | -------------- | -------------- |
| 50画像   | 15～20分 | 5～8分        | 3～5分        |
| 100 画像  | 30～40 分 | 10～15 分      | 5～8 分        |
| 200 画像  | 1～1.5 時間 | 20～30 分      | 10～15 分      |
| 500 画像  | 2～3 時間   | 45～60 分      | 20～30 分      |
| 1000 画像 | 4～6 時間   | 1.5～2 時間      | 40～60 分      |

{% hint style="info" %}
**初回実行**：Chlorosがキャッシュやプロファイルを構築するため、初期処理には時間がかかる場合があります。同様のデータセットを再度処理する際は、処理速度が向上します。
{% endhint %}

## 起動時のよくある問題

### 開始ボタンが使用不可（グレー表示）

**考えられる原因：**

* 画像がインポートされていない
* バックエンドが完全に起動していない
* 前回の処理がまだ実行中である
* プロジェクトが完全に読み込まれていない

**解決策：**

1. バックエンドが完全に初期化されるまで待つ（メインメニューのアイコンを確認）
2. ファイルブラウザで画像がインポートされていることを確認する
3. ボタンが有効にならない場合は、Chlorosを再起動する
4. デバッグログでエラーメッセージを確認する

### 処理が開始された直後に失敗する

**考えられる原因：**

* プロジェクトに有効な画像がない
* 画像ファイルが破損している
* ディスク容量が不足している
* メモリ（RAM）が不足している

**解決策：**

1. デバッグログ（<img src="../.gitbook/assets/icon_log.JPG" alt="" data-size="line">）にエラーメッセージがないか確認する
2. 空きディスク容量を確認する
3. 画像のサブセット（少ない量）で処理を試みる
4. 画像が破損していないことを確認する

### 実行は完了したが、画像が書き込まれない

画像プロダクトを要求したにもかかわらず、何も書き込まれなかった実行は、**成功ではなく失敗**として扱われます。Chloros はこれを明確に報告します：

* GUI ログには、考えられる原因を示すヒントとして `[RUN-SUMMARY]` が表示されます。具体的には、画像がインポートされていない、 ターゲットが検出されない、または要求されたすべてのプロダクトが適用不可としてスキップされた（例：RGB専用カメラから放射輝度/反射率を要求した場合）
* CLIに相当するコマンド（`chloros-cli process`）は、`Processing finished but wrote no image products.`を出力し、**ゼロ以外の値で終了**するため、スクリプトでこれを検出できます
* 意図的にメタデータのみを出力する実行（すべてのエクスポートプロダクトを無効化し、インデックスを生成しない）も、成功としてカウントされます

完全な意味論については、[CLI リファレンス](../reference/cli-reference.md#a-run-that-writes-no-images-fails)を参照してください。

### 「ターゲットが検出されませんでした」という警告

**考えられる原因：**

* ターゲット画像にマークを付けるのを忘れた
* ターゲット画像に視認可能なターゲットが含まれていない
* ターゲット検出の設定が厳しすぎる

**解決策：**

1. [ターゲット画像の選択](choosing-target-images.md) を確認する
2. 「ターゲット」列で適切な画像にマークを付ける
3. マークした画像内でターゲットが視認できることを確認する
4. 必要に応じてターゲット検出設定を調整する

## 処理を成功させるためのヒント

### 開始前に

1. **まず少量の画像でテストする** - 10～20枚の画像を処理して設定を確認する
2. **空きディスク容量を確認する** - データセットの2～3倍の空き容量を確保する （すべてのLATTICE製品を有効にしている場合はさらに多く）
3. **不要なアプリケーションを終了する** - システムリソースを解放する
4. **ターゲット画像を確認する** - マークされたターゲットをプレビューし、品質を確認する
5. **プロジェクトを保存する** - プロジェクトは自動保存されますが、手動で保存することをお勧めします

### 処理中

1. **システムのスリープを避ける** - 省電力モードを無効にする
2. **Chlorosをフォアグラウンドに保つ** - 少なくともタスクバーに表示された状態にする
3. **進行状況を時々確認する** - 警告やエラーがないか確認する
4. **他の負荷の高いアプリケーションを起動しない** - 特に Chloros+ の並列モード使用時は注意

### Chloros+ GPU アクセラレーション

NVIDIA GPU アクセラレーションを使用する場合：

1. NVIDIA ドライバーを最新バージョンに更新する
2. GPUのVRAMが4GB以上あることを確認する（同時実行のテクスチャ対応デベイヤー処理の場合は7GB以上）
3. GPUを多用するアプリケーション（ゲーム、動画編集など）を閉じる
4. GPUの温度を監視する（十分な冷却を確保する）
